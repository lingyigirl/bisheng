# 开放 API 强制鉴权 — 切换清单（执行版）

> 面向：**交付现场 / 运维**（照单执行、逐项记录）
> 配套：操作与排查细节见 [`开放API密钥鉴权迁移指引.md`](开放API密钥鉴权迁移指引.md)；条款验收见 [`开放API条款验收表.md`](开放API条款验收表.md)
> 本清单是现场**唯一执行口径**；早期规划材料里"回退秒级生效""开关关闭期间带密钥仍按密钥身份执行"等表述已作废（见 §2 注、§3）

## 0. 前置条件

| # | 项 | 确认 |
|---|---|---|
| 0.1 | 目标环境版本含本特性（T-27 审计 / T-29 调用面收口在内） | ☐ |
| 0.2 | 数据库为 MySQL 或 DM8；三张表（`service_account` / `api_credential` / `open_api_tenant_setting`）随 `create_all` 自动建，**升级无需手工建表**；DM8 环境按《db-drill 留档》§3 清单预检（重点：`update_time` 触发器已建） | ☐ |
| 0.3 | 管理员账号可用（管理面=超管或当前租户管理员；口令不写入任何脚本） | ☐ |
| 0.4 | 切换窗口：配置变更**需重启后端**（非热生效），按常规停机/滚动窗口申请 | ☐ |
| 0.5 | 已通知全部对接方（见 §1.1 盘点清单），约定切换时点 | ☐ |

## 1. 切换前（三步，逐项打勾）

### 1.1 盘点调用方

- ☐ 列出所有调 `/api/v2` 的系统：调哪些端点、各需哪些权限位、需要访问哪些应用/知识库
- ☐ 特别标注：**目前是否依赖"默认操作员是超管"才能访问资源**（这类系统切换后必然 403/404，是 §5 排查的第一嫌疑）

### 1.2 改造（对接方）

- ☐ 每个系统建一个服务账号（名称即对接系统名）
- ☐ 按"每个要调的端点"签发带对应权限位的密钥（权限位目录：管理端签发页或 `GET /api/v1/open-api/scopes`）
- ☐ 授予资源：服务账号页「资源授权」里逐个授予应用/知识库（**默认可见范围为空**）
- ☐ 对接方调用处改为 `Authorization: Bearer bs-sak-…`；WebSocket 用**握手请求头**携带（禁止放 URL 参数）

### 1.3 预发验证（必须，且**必须在开关打开的状态下**做）

- ☐ 预发改 `open_api.enforce_keys: true` → **重启后端**；**并**打开默认租户开关 `PUT /api/v1/open-api/settings {"enforce_keys": true}`（只开总闸的话，"不带密钥"仍按旧行为放行）
- ☐ 跑通清单：助手调用（含流式）、工作流调用与停止、知识库检索、工具三例（指定已绑定 / 指定未绑定 → 11815 / 不传）、**WebSocket 握手**（有效密钥建连 / 错误密钥被拒）
- ☐ 授权档位提醒：工作流调用要求 `use_app`，**只授 viewer 会被拒（404/11809）**——按"可编辑"及以上授予
- ☐ 逐项对照 [`开放API条款验收表.md`](开放API条款验收表.md) §2，记录结果
- ☐ 用 whoami（`GET /api/v2/auth/whoami`）确认每把密钥的权限位与有效期

> **口径纠正（重要）**：总闸关时 `/api/v2` 是完全旧行为——**连请求里带的密钥也不校验**。所以"开着密钥先验证、开关后开"不成立；预发验证必须在总闸打开后进行。

## 2. 生产切换

| # | 动作 | 验证信号 | 完成 |
|---|---|---|---|
| 2.1 | 改配置文件 `open_api.enforce_keys: true` | — | ☐ |
| 2.2 | **重启后端**（该开关无热加载） | 重启后 `GET /api/v1/open-api/settings` 回显 `deployment_enforced: true` | ☐ |
| 2.3 | 需要拦"无名请求"则打开默认租户开关：`PUT /api/v1/open-api/settings {"enforce_keys": true}` | ≤5 秒生效；回显 `effective: true`；匿名调用 `/api/v2` 开始返回 401/11801 | ☐ |
| 2.4 | 观察并清零异常命中 | **服务端日志**：`11801/11802`（未带/无效密钥——凭据阶段失败**不落审计**，只在日志）；**审计库**（`auditlog.action='open_api.call'`）：`403/11807` 缺权限位、`404/11809` 未授权；对照 §1.1 清单逐项处理 | ☐ |
| 2.5 | 切换完成确认 | 条款验收表 §2 全部"通过"并签署 | ☐ |

> **注**：租户级开关只影响**匿名请求**判定，且只看默认租户那一行；带密钥的调用由总闸说了算（总闸一开就强制，与租户开关无关）。
> **免登录面**：8 个免登录端点（助手对话/详情、会话标题/历史、流程详情、工作流 WS）在"免登录开关"（`default_operator.enable_guest_access`，**默认打开**）打开且租户开关关闭时仍允许匿名调用——要连它们一起拦，需把默认租户开关打开**并**确认免登录开关的业务取舍。

## 3. 回退（切换后**演练一次**并记录）

| # | 动作 | 验证信号 | 完成 |
|---|---|---|---|
| 3.1 | 配置改回 `open_api.enforce_keys: false` + **重启** | 恢复完全旧行为 | ☐ |
| 3.2 | 验证旧行为确实回来（两条特征都要看） | ① 不带密钥的调用恢复正常；② **带任意密钥（含已吊销）的调用也不再被拦**——这是"完全旧行为"的签名 | ☐ |
| 3.3 | 演练后重新打开（如需） | 同 §2.1–2.2 | ☐ |

**回退后仍在的东西（不需要清理）**：三张表与全部数据（服务账号/密钥/租户策略）、已写入的审计记录。**回退期间会停的**：逐调用审计（无鉴权面自然无调用审计）；管理动作审计不受影响。

**完全卸载回退**（撤销本特性时）：`DROP TABLE IF EXISTS service_account / api_credential / open_api_tenant_setting` + 从租户过滤登记表摘除这三张表的模型路径（详见 F076《db-drill 留档》§2.2）。

## 4. 切换后核对（一次）

- ☐ 控制台：系统 → 服务账号 三语文案齐备、非管理员看不到该 Tab；密钥签发的一次性明文弹窗行为正确
- ☐ 审计：随机抽一次调用，库里 `open_api.call` 有对应记录（掩码/账号/权限位/状态/耗时/IP），不含明文
- ☐ 安全抽查：用**已吊销**密钥、**无权限位**密钥各调一次，分别得 401/11804、403/11807
- ☐ WebSocket：有效密钥可建连；错误密钥握手被拒；已建立会话在密钥吊销后不中断（后续新调用按新状态拒）

## 5. 异常速查（详见迁移指引 §4）

| 现象 | 首要怀疑 | 处置 |
|---|---|---|
| 切换后某系统 403/404 | 默认操作员曾配超管，切换后按专用身份判定 | 给该服务账号**授予资源**；**不要**把 owner 换成超管（会被 11810/11816 拒） |
| 我开了租户开关没生效 | 部署总闸没开 | 看回显 `deployment_enforced` |
| 改了配置没反应 | 总闸无热加载 | **重启** |
| 审计里查不到调用 | 总闸关（无鉴权面）/ 查错位置 | 审计页不展示 `open_api.*`，按 SQL 查库 |
