# AI 协作工作方式约定（Codex）

> 2026-10-16 起生效 ｜ 适用：本仓库（毕昇 / F074 相关开发）
> 这份文档记录我与本项目协作时遵循的工作方式，供日后查阅。

## 一、总原则

1. **证据优先**：结论必须落到日志 / 代码 / 数据库 / 实测上，并明确区分"实测事实 / 有依据的推断 / 假设"三档。
2. **主动纠错**：发现你的判断、方案或优先级有问题时当场指出并给证据与替代方案，不顺着说"可以"；我判断错了也接受被直接怼回，重新查证而不是嘴硬。
3. **影响面先行**：动手或提方案前，先答四问——**涉及哪些文件与行为 / 性能影响（并发、请求扇出、写放大）/ 按此实施后结果是什么 / 风险与回退**。没有这四段，不进入实施。

## 二、思考与分析

- **先摸现状再动手**：新增功能前先读同类实现的约定（模型、DAO、迁移、i18n、测试写法），复用既有模式而不是发明第二套。
- **找根因不打补丁**：错误现象先定位到最小根因（例：任务秒失败 → 模型 id 已删除 + 僵尸 worker 抢队列，而不是"重试一下"）。
- **解决一个问题不引入新问题**：改动后必须用回归证明没有伤及别处（见"测试与验证"）；宁可缩小方案边界也不扩大爆炸半径。
- **性能是默认项，不是可选项**：任何新增交互都检查——请求次数是否随数据量线性膨胀（例：每回合各发一次请求 → 改模块级缓存+在途去重）；轮询是否只在需要时运行；服务端查询是否批量（一次查询 vs 每行一次）；写入是否节流；缓存是否必要且收敛。
- **推演优先于直觉**：涉及"默认开启更多工具/更多能力"这类决策时，先算清楚对上下文、成本、弱模型选择难度的实际影响再给建议（例：实测工具 schema 占固定上下文 64%，因此反对"默认全开"）。

## 三、写代码

- **最小侵入**：只动物种需要的文件；不动无关链路（例：常用成员库刻意不碰提交流程与快照结构，恢复/续跑逻辑零影响）。
- **契约单一出处**：同一约束（校验规则、字段上限、事件格式）只在一个地方定义，其它引用它，避免两套实现漂移。
- **注释解释"为什么"**：记录决策理由与陷阱（如"visibility 不是授权，必须执行时再拦一层"），不写重复代码的废话。
- **守门禁**：改前端跑 `lint / typecheck / check-i18n`（新文案三语言齐发）；改后端跑 ruff（只要求不新增非 RUF001 项）与单测；新建路由/接口必带"路由注册"回归测试（新端点 404 是真实踩过的坑）。
- **破坏性操作**：删除/移动前显式列出目标并验证路径；优先移动归档而非删除；被安全策略拦下就不绕过，如实说明。

## 四、测试与验证（由内到外四层）

1. **单测**：新逻辑要有正路径 + 边界 + 回归用例（例：999,949 → "1M" 而非 "1000K"；错误模块路径的导入必须有测试锁住）。
2. **邻域测试**：跑改动周围所有相关测试目录，确认套件级无回归。
3. **全量回归对比基线**：跑全量并对照已知基线（当前 `test/linsight` 基线 = 14 个环境性失败），要求"零新增失败"；flaky 用例单跑复核。
4. **真机 E2E**：API 级（提交任务、轮询状态、查验数据库与产物文件）+ 浏览器级（DOM/AX 文本确认渲染结果）。UI 功能不接受"单测过了就算完"。
5. **证据留档**：关键结论附日志片段 / 接口返回 / DOM 文本；不声称未执行过的核对（例：没在沙箱里跑过 LibreOffice 就不能写"经 LibreOffice 核对"）。

## 五、部署与运行环境

- 重启三件套：**worker**（消费任务）、**API**（新路由必须重启 API，只重启 worker 会 404）、前端（Vite HMR / 重启）。
- 一律用分离启动（WMI），避免终端会话被关时进程树被连坐杀掉；重启脚本先杀干净旧进程（launcher → 子进程 → arena），防止僵尸 worker 抢队列。
- 迁移手动执行 `alembic upgrade head`；新建表遵循"metadata 建整表 + alembic 管存量变更"双契约，迁移链挂当前 head。
- 部署后做健康检查：队列长度、worker 心跳、端口、关键接口冒烟。

## 六、工作区与沟通

- **工作区整理**：探针/E2E 脚本放 `.venv/f074-tools/`；日志归档 `.venv/f074-logs/`；重启入口、pid、凭据、配置留在约定位置；临时浏览器标签即开即关。
- **沟通格式**：结论先行、说人话、少格式；给方案带推荐与代价；发现你错在哪及时指出，附证据而不是态度。
- **变更纪律**：未经明确许可不提交远端；改动保持可回退；交付时列出"改了什么 / 验证结果 / 遗留说明"。
