# 定时任务与事件触发 API（F077）

> 面向：**行内系统对接方 / 平台运维**。对应公告（五）1 的「**定时/事件触发**」与「**手动或自然语言生成定时任务**」。
> 条款验收：[`../定时任务与触发条款验收表.md`](../定时任务与触发条款验收表.md)；任务控制台在平台**应用编辑页**「对外发布 → 定时任务」（入口：智能体 → 点击应用卡片）。

---

## 1. 概念与三种触发方式

**一条定时任务** = 目标应用（助手或工作流） + 触发计划（周期 cron 或一次性绝对时间） + **运行身份**（一个服务账号的专用身份，创建时锁定） + 可选预设输入。

| 触发方式 | 谁发起 | 身份与入口 |
|---|---|---|
| **计划轮次** | 平台调度（默认 20 秒一轮扫描） | 平台内部；以任务锁定的运行身份执行 |
| **事件触发** | 行内系统（本页 §3） | `POST /api/v2/schedule/trigger`，持服务账号密钥 |
| **立即运行** | 人工（控制台按钮） | `POST /api/v1/scheduled-tasks/{id}/run`，登录态 + 应用编辑权限 |

三种方式**共用同一条执行链**：复检（应用在线、运行身份可用、对该应用有运行权限）→ 原子占用（单任务互斥 / 全局并发上限）→ 复用应用的既有运行链路。

## 2. 前置条件（缺一不可）

1. 后端配置 `open_api.enforce_keys: true` 并重启（与（四）3 的强制鉴权同一个总闸；总闸关时本端点仍拒绝匿名，但不会有已校验的密钥身份）；
2. 对接系统有一个**服务账号**，并被授予目标应用 **editor（可编辑）档及以上**——`use_app` 从 editor 档起具备；
3. 该账号签发了包含 **`schedule:trigger`** 权限位的密钥（`bs-sak-` 前缀）；
4. 目标任务已由平台侧创建并处于**启用**状态。

## 3. 事件触发接口

```
POST /api/v2/schedule/trigger
Authorization: Bearer bs-sak-…
Content-Type: application/json
X-Bs-Timestamp: <epoch 秒>
X-Bs-Nonce: <16–64 字符一次性随机串>
```

```json
{"task_id": 123}
```

请求体**只接受** `task_id` 与可选的 `inputs`（入参映射，占位）；出现其它字段一律 400/11916。**任何情况下都不接受执行身份 / 目标应用 / 触发计划参数**——执行身份在任务上锁定（INV-25），请求里带 `user_id` 由开放 API 统一拒绝（400/11817）。

**成功响应**（HTTP 200）：

```json
{"status_code": 200, "status_message": "SUCCESS", "data": {"task_id": 123, "run_trace_id": "3f2c…"}}
```

`run_trace_id` 即本次运行的链路标识，可交给平台侧在监控里核对；**接口本身不提供运行结果查询**（见 §5）。

### 3.1 失败语义（真 HTTP 状态 + 信封业务码）

| HTTP | 业务码 | 含义 |
|---|---|---|
| 401 | 11801 | 未携带密钥或格式非法 |
| 401 | 11802 / 11803 / 11804 / 11805 | 密钥无效 / 已过期 / 已吊销 / 所属账号已停用 |
| 403 | 11807 | 密钥缺少 `schedule:trigger` 权限位（响应 `data.required` 指明） |
| 404 | 11809 | **任务不存在 / 不在该密钥的授权范围 / 已停用**——三者不可区分（防枚举） |
| 400 | 11916 | 请求体含白名单外字段 |
| 400 | 11912 | 防重放拒绝：缺/超窗 `X-Bs-Timestamp`，或 `X-Bs-Nonce` 已被使用 |
| 409 | 11905 | 运行身份不可用（账号停用 / owner 被替换或提权 / 失去该应用运行权限） |
| 409 | 11907 | 目标应用不可用（已下线或已删除） |
| 409 | 11909 | 平台同时运行数已达上限 |
| 409 | 11910 | 该任务已有一轮在运行中（**拒绝**，不会静默去重） |
| 429 | 11911 | 触发频率超限（默认 **10 次/分钟/任务**），可带 `Retry-After` |
| 503 | 11812 | 鉴权/防重放后端（Redis）暂不可用，稍后重试 |
| 500 | 11811 | 端点权限位未登记（内部错误，不应出现） |

### 3.2 防重放与频率

- 时间窗：`|now − X-Bs-Timestamp| ≤ 300 秒`（可配置）；窗口外一律 11912；
- 一次性随机数：`X-Bs-Nonce` 在窗口的 2 倍时间内只接受一次；重复使用 → 11912；
- 任务级频率：默认每分钟 10 次，超限 → 429/11911。这是**调度侧的放大量护栏**，与平台的 API 限流（未实现）不同。

## 4. 管理接口（控制台使用；会话身份 + 应用编辑权限）

| 方法 | 路径 | 说明 |
|---|---|---|
| GET | `/api/v1/scheduled-tasks?app_id=&app_type=` | 任务列表（含人类可读计划、下次执行、上次结果） |
| POST | `/api/v1/scheduled-tasks` | 创建（cron 或一次性；校验应用形状与知识可见性） |
| PUT | `/api/v1/scheduled-tasks/{id}` | 编辑（换运行身份会重走创建期校验） |
| POST | `/api/v1/scheduled-tasks/{id}/enable` \| `/disable` | 启停（重新启用从下一个计划时刻起恢复，停用期间到期的轮次不补跑） |
| POST | `/api/v1/scheduled-tasks/{id}/run` | 立即运行（返回 `run_trace_id`；遇互斥/并发上限 → 11909） |
| DELETE | `/api/v1/scheduled-tasks/{id}` | 删除（运行留痕与审计保留） |
| POST | `/api/v1/scheduled-tasks/preview` | cron 预览（人类可读 + 未来 5 次） |
| POST | `/api/v1/scheduled-tasks/nl-draft` | 自然语言 → 草稿（**不落库**；确认后走创建） |
| GET | `/api/v1/scheduled-tasks/available-identities` | 可用运行身份清单（不含任何密钥信息） |

管理面的 119xx 一律按平台既有信封返回（HTTP 200 + 业务码），只有 `/api/v2` 面回真 HTTP 状态。

## 5. 与既有能力的差异（验收时请注意）

1. **应用下线即不执行**：定时/事件触发在应用未上线时不运行（周期任务记「已跳过」；一次性任务等待上线后补跑一次；事件触发与立即运行直接报 11907）——与既有 `/api/v2` 调用面"不校验上线状态"不同；
2. **不提供外部运行查询接口**：事件触发只返回受理与 `run_trace_id`；运行结果请看平台任务列表 / 监控 / 失败站内信；
3. **新增两个 HTTP 状态码**：409（运行冲突 / 身份或应用不可用）、429（频率超限）。

## 6. 运行结果在哪看

- **任务列表**：触发计划 / 下次执行 / 上次结果（成功/失败/已跳过/等待人工输入）、耗时、失败原因；「立即运行」与事件触发共用同一份结果；
- **监控**：按 `run_trace_id` 检索该次运行的详情（与平台手动调用同一条链路）；
- **失败通知**：连续失败序列的**首败**与**达阈值自动停用**各发一条站内信给任务创建者（同一序列不重复发）。
