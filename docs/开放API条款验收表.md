## 1. 条款原文与我方口径

> **3. 支持外部系统对接：支持行内各系统经 API 调用智能体应用和工具；提供 API Key 与调用方鉴权。**

| 条款要素 | 我方口径 |
|---|---|
| 提供 API Key | 管理端为每个对接系统建**服务账号**并签发 `bs-sak-` 前缀密钥；密钥带权限位与有效期，可轮换、可吊销 |
| 调用方鉴权 | `/api/v2` 每次调用校验密钥；**身份 = 该密钥所属服务账号的专用身份**，用户登录态/cookie/默认操作员一律不可替代 |
| 经 API 调用智能体应用 | 助手与工作流的开放端点均可带密钥调用（含流式与 WebSocket） |
| …和工具 | **按"调用智能体应用时可指定启用哪些平台工具"实现**：调用请求可携带 `tools[]` 白名单（限该应用已绑定且启用的工具），不传则按应用默认配置执行；应用详情接口返回可用工具清单。**不提供"工具作为独立可寻址资源被直接调用"的端点**——若贵方按后一种口径要求，请提出，我方单列补齐项 |

### 1.1 对客可表述的口径（可直接引用）

> 平台已实现开放 API 密钥鉴权（**本机验证通过**：契约测试 134 用例、端到端 11 用例、验收探针 12 项自动断言，含防枚举 404/11809、请求中身份参数收口、密钥明文一次性展示、逐调用审计落库）。
> 公告（四）3 的两个显式要求——「行内各系统经 API 调用智能体应用」与「提供 API Key 与调用方鉴权」——**在按"调用时可指定启用平台工具"的口径理解、并完成环境切换与行内系统改造后可以满足**。
> **需一并说明的两点**：① 强制鉴权**默认关闭**（关闭时保持升级前行为不变），需在行内环境显式打开开关后方生效（见切换清单）；② "工具本身可被独立 API 直调"不在本期范围。

| I | 自检端点（联调便利） | 用密钥调用 `GET /api/v2/auth/whoami` | 回显所属服务账号、权限位、有效期与掩码——对接方可在联调第一步自查密钥是否有效 | ☐ 通过 ☐ 不通过<br>记录： |

| K | 对接资料可得性（交付便利，**需现场人工**） | 管理端打开「系统 → 服务账号 → 接入指南」：改一次「接入地址」→「复制全文」→「导出 Markdown」 | 页面正文即对接说明（含密钥携带方式、9 项权限位、21 条错误码与 curl 示例）；正文中的地址随输入框实时替换（含 ws/wss 示例）；导出件带「来源 / 导出时间 / 接入地址」抬头；复制内容与导出文件**逐字一致** | ☐ 通过 ☐ 不通过<br>记录： |

> 说明：
> - 表中"118xx"为我方统一错误码（响应体 `status_code` 字段），同时返回**真实 HTTP 状态码**（401/403/404）；错误码全表见 [`api/open-api-auth.md`](api/open-api-auth.md) §6。
> - 审计记录**不在**平台「审计日志」页面展示（属取证数据，按上表 H 的 SQL 检索）；对客口径建议保留 ≥ 6 个月。
> - 行 E 的"防枚举"是刻意设计：同一结果使外部无法借错误信息探测行内资源是否存在。
> - **免登录面**：平台免登录页依赖 8 个端点（含助手对话/详情等）属刻意豁免——"免登录开关"打开且租户开关关闭时它们允许匿名调用；因此行 B 用**非免登录端点**（`/filelib/`）验证"无密钥被拒"。要不要连免登录面一起拦，由行内按需决定（把默认租户开关也打开即可）。
> - **授权档位**：工作流/助手的调用要求 `use_app` 权限，它从**编辑者（editor）档**起具备——只授"可查看（viewer）"的密钥调工作流会被拒（404/11809）；验收时请按"可编辑"及以上授予。
> - **行 K 与行 A 的关系**：行 A 验的是"签发流程"，行 K 验的是"给对接方的资料随产品自带、可按环境导出"——**交付时无需另发接口文档**，导出件在文字里自带接入地址与导出时间，避免线下口头交代地址与调用方式。

## 3. 本次不在声明范围内（避免验收时口径错位）

以下均为**明确排除**或**由平台既有能力另行承载**，本条款验收不涉及：

| 项 | 说明 |
|---|---|
| "工具直调"端点 | 工具不可作为独立资源被直接请求；本期口径为"调用应用时可指定启用工具"（见表 D） |
| 代表用户调用 / 外部终端用户标识 | 身份固定为服务账号自身 |
| 限流 / 配额 / IP 白名单 / 幂等 / OpenAPI 规范导出 | 不在本期范围（如需，属变更项） |
| 国密化（SM2/SM3/SM4） | 属公告（十）5 平台级合规条款；传输加密由行内 TLS/网关承载 |
| 存量调用方改造的组织实施 | 我方交付能力与迁移指引；各系统对接改造由贵方组织 |

## 4. 现场验收前置（四步，详见迁移指引）

1. 建服务账号（每对接系统一个）→ 2. 按"要调用的端点"签发带对应权限位的密钥 → 3. 在服务账号页授予其可访问的应用/知识库 → 4. 在测试/预发环境打开强制开关：**部署级**（配置 `open_api.enforce_keys: true` + **重启**）**且**打开默认租户开关（`PUT /api/v1/open-api/settings {"enforce_keys": true}`）——前者管"带密钥必校验"，后者才拦"不带密钥"；跑通后再切生产。
