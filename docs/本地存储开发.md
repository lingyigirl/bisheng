## 一、MinIO 当前的存储与管理方式

| 层面 | MinIO 的做法 |
|------|-------------|
| 逻辑结构 | 两段：`bucket` / `object_name` |
| bucket | `bisheng`（持久文件）、`tmp-dir`（临时文件）、`a-bucket`（Milvus 用，业务无关） |
| object_name | 用 `/` 分层，如 `original/2.pdf`、`knowledge/images/1/2/x.jpg` |
| 上传 / 读取 | SDK：`put_object(bucket, object_name, data)` / `get_object(bucket, object_name)` |
| **物理落盘** | object_name 变成**目录**，内含 `xl.meta` + `<uuid>/part.N` |
| 对外开放 | nginx：`/bisheng/xxx` → `minio:9000` |
| 临时过期 | bucket lifecycle（3 天自动删） |
| 权限 / URL | 预签名 URL、匿名读策略 |

**object_name 常见前缀**（真实代码构造）：

| 前缀 | 用途 |
|------|------|
| `original/{file_id}.{ext}` | 知识库原始文件 |
| `knowledge/images/{kb_id}/{doc_id}/{fname}` | 解析出的图片 |
| `partitions/{file_id}.json` | bbox 分区文件 |
| `preview/{id}.html` | 预览快照 |
| `thumbnails/{uuid}.jpg` | 缩略图 |
| `workflow/report/{key}.docx` | 工作流报告 |
| `tts/{uuid}.mp3` | TTS 音频 |

## 二、本地存储用相同路径结构是否可行

**可行。** 业务代码与前端只认逻辑路径（`bucket` + `object_name`），与底层是 MinIO 还是文件系统无关。

| 层面 | 本地存储（相同路径结构） | 可实现 |
|------|----------------------|-------|
| 逻辑结构 | `{root}/{bucket}/{object_name}` | ✅ 完全一致 |
| bucket | 目录 | ✅ |
| object_name | 文件路径 | ✅ |
| 上传 / 读取 | 写文件 / 读文件 | ✅ |
| 物理落盘 | 普通文件（不用 xl.meta） | ✅ |
| 对外开放 | nginx `alias` 到本地目录 | ✅ |
| 临时过期 | 自建定时清理 | ⚠️ 需补 |
| URL | 直接返回路径 | ⚠️ 需补 |

**例子**：

```
调用：put_object("bisheng", "original/2.pdf", data)

MinIO 落盘： bisheng/original/2.pdf/            ← 目录
             ├── xl.meta
             └── <uuid>/part.1

本地落盘：   {root}/bisheng/original/2.pdf      ← 就是一个文件

访问：GET /bisheng/original/2.pdf
MinIO： nginx → minio:9000 → 按 xl.meta 拼回文件 → 返回
本地：  nginx alias → 直接读文件 → 返回
```

## 三、能否无缝衔接 MinIO 的上下游业务功能

**接口层面基本无缝，但有 5 个断点必须处理**：

| # | 断点 | 位置 | 说明 |
|---|------|------|------|
| 1 | 直接访问原生客户端 `.minio_client_sync` | `approval/...:173`、`brand/...:134`、`evaluation/...:236` | 本地无该对象，**必须改代码** |
| 2 | F017 租户 fallback | `MinioStorage.get_object_sync` 等 3 个方法 | 本地不复刻则多租户读不到共享文件 |
| 3 | tmp 文件 3 天过期 | MinIO bucket lifecycle | 本地需 Celery Beat 自建清理 |
| 4 | `get_share_link` URL 形态 | 30+ 处调用 | 预签名 → 静态路径，须保持 URL 形态一致 |
| 5 | 存量数据 | MinIO 磁盘（xl.meta 格式） | 需一次性导出迁移（`mc mirror` 或逐个 `get_object()`） |

**可无缝的部分**：

- 93 处经 `get_minio_storage()` 的调用——只要函数名与返回接口一致，**无需改动**。
- 前端 URL `/bisheng/...`、`/tmp-dir/...`——nginx 改指向即可。

---

### 5 个断点的性质分类

| 断点 | 性质 | 是否需要讨论 |
|------|------|------------|
| 1. 3 处抽象泄漏 | 必须改，改法有选择（补接口 or 改调用点） | 需定一次方案 |
| 2. F017 租户 fallback | 行为一致性 | **需要决策**（即 Q2） |
| 3. tmp 3 天过期 | 标准补齐动作 | 不需要，直接列为任务 |
| 4. `get_share_link` URL | — | 已定（即 Q1） |
| 5. 存量数据迁移 | 迁移策略（是否迁 / 怎么迁 / 何时迁） | **需要决策** |

> 归类：**需要你拍板的只有第 2、5 项**；第 1 项需定一次实现方案；第 3 项是纯实现任务；第 4 项已解决。

## 四、源码侧改造方案

### 4.1 配置模型（`core/config/settings.py`）

```python
class LocalConf(BaseModel):
    root: str = "/app/data/storage"      # 本地存储根目录
    public_bucket: str = "bisheng"
    tmp_bucket: str = "tmp-dir"

class ObjectStore(BaseModel):
    type: str = "minio"                  # minio | local
    minio: MinioConf | None = Field(default_factory=MinioConf)
    local: LocalConf | None = None
```

`src/backend/bisheng/config.yaml` 切换示例：

```yaml
object_storage:
  type: local
  local:
    root: '/data/bisheng-storage'
```

约束：`type=local` 而 `local` 段缺失时，**启动阶段直接报错**。

### 4.2 工厂化（现有 4 处 + 新增 1 个文件）

| # | 文件 | 改什么 |
|---|------|--------|
| 1 | `core/config/settings.py` | `ObjectStore` 加 `local` 段；新增 `LocalConf` |
| 2 | `core/storage/minio/minio_manager.py` | 按 `object_storage.type` 返回 `MinioStorage` 或 `LocalStorage` |
| 3 | `core/context/manager.py:82` | 注册时传整个 `object_storage`（而非只传 `.minio`） |
| 4 | `core/storage/base.py` | 把业务实际用到的方法补进抽象接口 |
| 5 | `core/storage/local/local_storage.py`（新增） | `LocalStorage` 实现 |

**关键约束**：保留 `get_minio_storage()` / `get_minio_storage_sync()` 函数名，使 93 处调用零改动。

### 4.3 LocalStorage 要实现的接口（三组）

**A 组｜BaseStorage 原语**：bucket/object 增删查拷（同步 + 异步）→ 映射为目录/文件操作。

**B 组｜业务在用、但不在 BaseStorage 的方法**：

| 方法 | 本地实现 |
|------|---------|
| `get_share_link` / `_sync` | 返回相对路径（见 4.4） |
| `put_object_tmp` / `_sync` | 写入 tmp 子目录 |
| `download_object_sync` | 读文件返回 response |
| `.bucket` / `.tmp_bucket` | 直接暴露 |
| `get_minio_share_host` / `clear_minio_share_host` | 本地可退化为空操作 |

**C 组｜3 处抽象泄漏**：见第三节断点 1，必须改调用方。

### 4.4 静态文件服务（已定）

`LocalStorage.get_share_link()` 返回相对路径 `/bisheng/{object_name}`，并在 FastAPI 上挂静态目录（`Starlette StaticFiles`，FastAPI 自带，不引新依赖），把 `/bisheng`、`/tmp-dir` 映射到本地存储目录。

源码侧因此可独立运行（uvicorn + vite），不依赖外部反代；docker 侧由 nginx 承担。

### 4.5 需保留的业务语义与补齐项

| 项 | 处理方式 |
|----|---------|
| F017 租户 fallback | 必须复刻，建议抽公共层（见 Q2） |
| metrics 打点（`@_metered`） | 建议保留 |
| tmp 3 天过期 | 自建 Celery Beat 清理 |
| 路径安全 | **必须防 `../` 穿越**（硬要求） |
| 原子写 | 先写临时文件再 `os.rename` |

### 4.6 需顺手修正的现存问题

- `BaseStorage.object_exists_sync` 漏标 `@abstractmethod`。
- `BaseStorage` 与 `MinioStorage` 方法签名不一致，实现 `LocalStorage` 时以真实调用方为准。
