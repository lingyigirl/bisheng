# Feature: 风险合规知识库（055-risk-compliance-knowledge）

> **本文档定位 — 纯 What（需求口径，不随代码漂移）**
>
> spec 只回答 **做什么 / 验收标准 / 不做什么**。
> **所有 How（决策、数据流、字段、API、Service、前端、文件清单、性能指标）一律不写在这里。**
> How 的唯一真相在 [design.md](./design.md)（接手必读）与 [tasks.md](./tasks.md)（执行流水）。

**关联 PRD**: 用户需求（2026-09-06）：风险合规知识库——行内知识（行内制度、授信政策要求、审查指引、产业分析）与行外知识（行业分析、企业外部评级、市场融资情况、企查查、天眼查、征信资料）通过 RAG 解决大模型在金融专业领域的幻觉问题；知识库需支持四大类内容组织、文档上传、语义切片、标签分类、生效日期设定、知识权重与调用优先级配置，业务人员可动态维护，确保 AI 生成结果符合最新政策与内部标准。
**优先级**: P0
**所属版本**: v2.7.0
**依赖**: 无（基于既有知识库模块与工作流检索能力扩展；错误码复用，不新增）

> **范围边界**
> - **本次纳入**：
>   - **四大类内容组织**：预设「行内制度 / 监管法规 / 行业分析 / 历史案例」分类标签体系，文档打标后可按分类组织与过滤检索
>   - **生效日期设定**：文档级生效/失效日期；检索默认只召回「当前日期处于生效区间内」的文档；未来生效的文档亦不召回
>   - **知识权重与调用优先级**：知识库级权重（多库检索按命中分数 × 库权重综合排序）与优先级（高优先级库优先召回，不足 top_k 再补低优先级库）
>   - **检索参数补全**：工作流检索节点（rag / knowledge_retriever）支持配置 top_k 与相似度阈值
>   - **检索命中测试**：知识库详情页可输入测试问句，查看实际召回结果（命中片段与来源）
>   - **标签中心**：独立标签管理界面（新建/改名/删除标签），取代只能在文档打标弹窗里维护的现状
>   - **动态维护闭环**：标签 / 生效日期 / 权重的修改即时生效，无需重新解析
>   - **外部数据接入口径**：静态资料（外部评级报告、行业分析、市场融资情况等）走既有上传入库管线；实时查询类（企查查、天眼查、征信资料）走 MCP 工具在工作流中调用，**不进知识库**
> - **本次明确排除**：
>   - chunk / 条款级生效日期（文件级起步；单条款修订用既有文档版本管理覆盖）
>   - 工作流节点级动态权重覆盖库级默认值（二期）
>   - 外部数据源定时抓取入库管道（另起 feature；本期仅固定「静态入库 / 实时 MCP」的分流口径）
>   - 过期文档的自动下线 / 物理归档（过期仅影响检索可见性，不影响列表查看与维护）
>   - 语义切片、文档上传、解析等既有能力不做改造（需求已满足，详见 gap 分析）

## 1. 用户故事

作为 **合规审查人员**，
我希望 **回答问题时检索到的是「当前生效」的行内制度与监管法规，且制度类知识优先于历史案例**，
以便 **审查结论符合最新政策与内部标准，不被已废止制度误导**。

作为 **知识管理员（业务人员）**，
我希望 **上传文档后能打分类标签、设定生效日期、调整知识权重，并能随时测试「某问题会召回哪些内容」**，
以便 **独立维护知识内容，不依赖开发人员，确保 AI 生成结果符合最新政策**。

作为 **智能体构建者**，
我希望 **在工作流中按分类、时效、权重、优先级组合多个知识库的检索，并控制召回数量与质量阈值**，
以便 **为风险合规场景搭建可控的 RAG 链路，降低幻觉与低质上下文**。

## 2. 验收标准

### 2.1 分类与标签

- **AC-01** — WHEN 用户创建风险合规知识库, THE SYSTEM SHALL 提供「行内制度 / 监管法规 / 行业分析 / 历史案例」四个预设分类标签可直接选用。
- **AC-02** — WHEN 用户在文档打标弹窗中新建标签并保存, THE SYSTEM SHALL 该标签立即出现在文档列表中（回归：2026-09-06 修复「新建标签后保存不生效」的既有 bug）。
- **AC-03** — WHEN 工作流检索节点配置标签过滤条件, THE SYSTEM SHALL 只召回带有指定标签的文档。
- **AC-04** — WHEN 用户在标签中心修改或删除标签, THE SYSTEM SHALL 文档展示与检索过滤口径同步更新；删除标签后相关文档自动解除该标签关联。

### 2.2 生效日期

- **AC-05** — WHEN 用户为文档设定生效日期与失效日期, THE SYSTEM SHALL 检索时只召回「当前日期处于生效区间内」的文档。
- **AC-06** — IF 文档未设定生效日期, THEN THE SYSTEM SHALL 视为一直生效（历史案例、法规类常无明确期限）。
- **AC-07** — IF 文档已失效或尚未生效, THEN THE SYSTEM SHALL 该文档仍可在知识库列表中查看与维护（带明确的失效/未生效标识），但不参与检索。
- **AC-08** — WHEN 用户修改文档的生效日期, THE SYSTEM SHALL 修改即时生效于检索，无需重新解析文档。

### 2.3 知识权重与调用优先级

- **AC-09** — WHEN 知识库配置了权重, THE SYSTEM SHALL 多知识库检索时按「命中分数 × 知识库权重」综合排序返回。
- **AC-10** — WHEN 用户配置知识库调用优先级, THE SYSTEM SHALL 先召回高优先级库，结果不足 top_k 时再补充低优先级库的结果。
- **AC-11** — IF 知识库未配置权重与优先级, THEN THE SYSTEM SHALL 保持既有行为（各库结果按融合分数排序），既有工作流与问答路径不受影响。

### 2.4 检索参数

- **AC-12** — WHEN 工作流检索节点（rag / knowledge_retriever）配置 top_k 与相似度阈值, THE SYSTEM SHALL 按配置限制召回数量并过滤低分结果。
- **AC-13** — IF 检索节点未配置, THEN THE SYSTEM SHALL 沿用既有默认（top_k=100、无分数阈值），既有工作流行为不变。

### 2.5 检索命中测试

- **AC-14** — WHEN 用户在知识库详情页输入测试问句, THE SYSTEM SHALL 返回实际召回结果（文档名、命中片段、相关度分数）以及生效过滤后的说明（如「N 篇因失效被排除」）。

### 2.6 外部数据分流

- **AC-15** — 实时查询类外部数据（企查查、天眼查、征信资料）THE SYSTEM SHALL 通过工作流 MCP 工具调用获取，不写入知识库检索结果。
- **AC-16** — 静态资料类外部数据（外部评级报告、行业分析、市场融资情况）THE SYSTEM SHALL 走既有上传入库管线，与行内知识统一检索口径（同样受分类/时效/权重约束）。

### 2.7 权限与租户

- **AC-17** — 标签、生效日期、权重的维护 THE SYSTEM SHALL 受既有知识库写权限约束（沿用现有权限模型，不新增权限口径）。
- **AC-18** — WHERE 多租户开启, THE SYSTEM SHALL 新增字段与检索行为按租户隔离，标签/时效/权重不跨租户生效。

## 3. 边界情况

- 生效日期为空 → 一直生效；只填生效日期不填失效日期 → 自生效日起一直有效；只填失效日期 → 至失效日止有效。
- 权重为 0 → 该库不参与多库检索召回。
- 同一文档属于多个分类标签 → 任一标签命中过滤即召回（and/or 语义沿用既有 metadata 过滤口径）。
- 多库检索中某库无任何生效文档 → 跳过该库，不影响其他库召回。
- 阈值过滤后结果为空 → 返回空上下文，不编造内容（rag 节点沿用既有空上下文行为）。
- 命中测试与正式检索 THE SYSTEM SHALL 采用同一套检索逻辑（含时效/标签/权重），保证测试所见即生产所得。
- 实时外部数据不入库——避免把会变化的实时数据缓存进知识库造成陈旧误导；具体数据流指向 design.md。
