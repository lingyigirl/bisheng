## 2. 必须人工验证（自动化无法覆盖）

### 2.1 AC-25 —— 唯一「必须真栈 + 真 LLM 才能证明」的 AC

> 单测（`test_injection_sites.py`）只能断言**模型收到的 prompt 变了**；「答案跟着变」只有真对话能证明。

**步骤**（三条链路各做一遍）：

1. 建一条术语（例如 标准词 `不良贷款率` / 别名 `不良率` / 释义 `<某句可被追问的独特说法>`）
2. 新建一个会话，提问包含 `不良率`
3. **不重开会话**，在管理页把该术语的释义改成另一句独特说法
4. 在**同一个会话**再问一次同样的问题
5. **期望**：第 4 步的回答体现**新**释义

| 链路 | 入口 | 预期可观察点 |
|---|---|---|
| 助手 | 应用对话（`assistant_agent.py`，function call 分支） | 同上 |
| 助手（ReAct 分支） | 同上，模型 `agent_executor_type = ReAct` | 同上 |
| 工作流 Agent 节点 | 编排一个含 Agent 节点的流程 | 同上 |
| 工作台 | `/workspace` 直接对话 | 同上 |

> **两条分支都要测**：`function call` 与 `ReAct` 的注入形状不同（前者异步 callable、后者零参 builder），只测一条会漏掉另一条。这是本次实现期发现的缺口。

### 2.2 AC-20 / AC-21 / AC-22 —— 命中与不命中

- 提问命中**别名** → 回答体现**标准词**的释义，且区块里列出别名（AC-21）
- 提问不命中任何术语 → **prompt 与加本特性前逐字节一致**（AC-22）；实测方式：为同一问题开关术语库各问一次，比较模型行为无差异

### 2.3 管理页交互（AC-12 / AC-13）

需要带 `knowledge` 权限的账号，登录平台 `:3001` → 知识库 → **术语库** Tab：

- [ ] 列表分页正常，新建 / 编辑 / 删除生效
- [ ] 左侧部门树筛选列表；选一个部门含其子部门（AC-13）
- [ ] 导入：上传 xlsx → 看到预览数字 → 选追加 → 列表更新
- [ ] 导入：选**覆盖**且有存量术语时 → **出现破坏性提示**（删除条数）
- [ ] 上传 `.txt` → 报 **11505** 且文案可读

### 2.4 权限呈现（AC-16 / AC-17 / AC-18）

- [ ] 只有 `knowledge` 的账号：**能看列表**，**看不到**新建 / 编辑 / 删除 / 导入入口
- [ ] 后端独立性：用该账号直接 `curl` 写接口 → **被拒**（不依赖前端隐藏）。自动化已覆盖后端侧（`test_term_api.py`），此处只验前端呈现
