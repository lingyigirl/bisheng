# Feature: 对话知识范围默认口径（063-chat-knowledge-scope）

> **本文档定位 — 纯 What（需求口径，不随代码漂移）**
>
> spec 只回答 **做什么 / 验收标准 / 不做什么**。
> **所有 How（决策、数据流、字段、API、Service、前端、文件清单、性能指标）一律不写在这里。**
> How 的唯一真相在 [design.md](./design.md)（接手必读）与 [tasks.md](./tasks.md)（执行流水）。

**关联 PRD**: 用户需求（2026-09-22）：在 `/workspace` 问答页上，用户不应再需要主动逐条选择组织知识库，而应默认使用全部有权限的组织知识库；同时必须保留「只针对知识空间问答」的场景，以及「在全部组织知识库之上再叠加知识空间」的场景。需求澄清共 11 项决策已与需求方逐条对齐（见 §2 各 AC 的分布）。
**优先级**: P0
**所属版本**: v2.7.0
**依赖**: F062-org-dept-knowledge-visibility（机构/部门标记与知识库可见集合的读时求值口径）、F057-knowledge-department-ownership（知识库的部门归属与可见性口径）；工作台配置中的组织知识库功能开关。
**本特性不新增错误码。**

> **范围边界**（写清「明确不做什么」比写「做什么」更能防 scope 膨胀）
> - **本次纳入**：
>   - **默认口径**：用户未选择任何知识空间时，默认使用全部有权限的组织知识库
>   - **作用域关系**：组织知识库档位（全部 / 不使用）与知识空间多选彼此独立；未显式设定时按「有无知识空间」兜底，显式设定后不再回弹
>   - **档位形态**：输入区的组织知识库入口收敛为两个档位，不再逐个勾选、不再展示清单
>   - **附件条汇总**：组织知识库在附件条上以单张汇总卡片呈现，可一键置为「不使用」
>   - **可见性合规**：「全部」所解析的集合与其他知识库读取入口的可见集合一致，且实时求值（INV-21）
>   - **状态记忆与遗留记录处置**：记住用户档位；升级前的遗留记录**不做迁移**（一律视作未显式设定，落入 AC-02 兜底），其中已保存的知识空间选择照常保留
>   - **配置口径**：管理员此前配置的组织知识库清单不再影响对话知识范围的默认值
>   - **覆盖入口**：凡复用该问答输入区的入口（日常问答页、订阅模块的 AI 助手面板、独立对话页、分享页，以及任务模式落地页）适用同一口径
> - **本次明确排除**：
>   - **任务模式执行态（灵思）的知识选择**：任务已创建后的输入区（`TaskModeInput` + `KnowledgeSpaceSelect`）的选择项、选择器与持久化链路均为独立实现，本次保持原状态，另起 feature 处理。**注意**：任务模式*落地页*不在本项排除范围内——它复用日常输入区，跟随本特性口径（见 AC-25 修订）
>   - **「只勾选指定几个组织知识库」能力**：本特性明确移除该能力，组织知识库只保留「全部 / 不使用」两档。理由见本文件 §3 末条
>   - **组织知识库的管理、归属与可见性规则本身**：归 F057 / F062 所有，本特性只读复用其判定，不修改任何可见性口径
>   - **管理员配置入口本身的改动**：平台侧组织知识库配置入口的既有行为与字段本期不变，仅其配置值不再影响对话默认口径（见 AC-22）
>   - **知识空间的清单、搜索与分页展示**：保持既有行为不变
>   - **应用中心问答**：该入口无知识选择能力，不在范围内
>   - **组织知识库「部分可见」或「排除名单」类机制**：不提供，见 AC-12（对应 INV-20 的「只增不减」）
>   - **历史会话的回填**：可见集合变化只影响后续问答，不回溯既有会话

## 1. 用户故事

作为 **日常问答的普通用户**，
我希望 **不选任何东西就能问到组织知识库里的内容**，
以便 **不必每次都在几十个知识库里翻找、勾选，把时间花在提问上而不是配置上**。

作为 **需要把问题限定在某一批资料内的用户**，
我希望 **选择知识空间后就只查这个知识空间，而不会被全公司知识库的召回结果干扰**，
以便 **在验证某份材料时得到干净、可判断的答案**。

作为 **既想用到全量组织知识库、又想额外叠加某个知识空间的用户**，
我希望 **在默认全选的基础上把知识空间加进来，而不是被迫二选一**，
以便 **同时获得兜底召回与专题补充**。

作为 **对信息范围敏感的用户**，
我希望 **能一眼看出当前这轮问答到底用没用组织知识库，并且一键关掉它**，
以便 **在只想随口问一句、不愿触发全公司检索时，有明确且可逆的出口**。

## 2. 验收标准

### 2.1 默认口径与作用域关系

- **AC-01** — THE SYSTEM SHALL 允许组织知识库档位与知识空间选择被独立设定，下列两种组合均合法：**选择了知识空间 + 使用全部组织知识库**、**选择了知识空间 + 不使用任何组织知识库**。
- **AC-02** — WHEN 用户尚未对组织知识库档位做出显式选择, THE SYSTEM SHALL 按下述兜底口径求值：**未选择任何知识空间时为「全部」；选择了至少一个知识空间时为「不使用」**。
- **AC-03** — WHEN 用户未选择任何知识空间, THEN THE SYSTEM SHALL 在该轮问答中检索**当前用户有权限的全部组织知识库**。
- **AC-04** — WHEN 用户选择了至少一个知识空间且未对组织知识库档位做出显式选择, THEN THE SYSTEM SHALL 仅检索所选知识空间，**不使用任何组织知识库**。
- **AC-05** — WHEN 用户显式把组织知识库档位置为「全部」, THEN THE SYSTEM SHALL 检索全部有权限的组织知识库，**无论是否选择了知识空间**。
- **AC-06** — WHEN 用户显式把组织知识库档位置为「不使用」, THEN THE SYSTEM SHALL 不检索任何组织知识库，**无论是否选择了知识空间**。
- **AC-07** — WHILE 用户已对组织知识库档位做出过显式选择, THE SYSTEM SHALL 在该用户其后新增或移除知识空间时保持该档位不变。
- **AC-08** — WHEN 用户清空了全部知识空间选择且此前未对组织知识库档位做出过显式选择, THEN THE SYSTEM SHALL 回到「全部」。
- **AC-09** — WHEN 用户有权限的组织知识库数量超过 50, THEN THE SYSTEM SHALL 照常把全部数量纳入本轮检索，不得因数量超过该值而拒绝请求、返回错误或静默收窄范围。

### 2.2 可见性合规（INV-21）

- **AC-10** — THE SYSTEM SHALL 使「全部」档位所解析出的组织知识库集合，与用户**在其他知识库读取入口**（平台侧知识库列表、组织树节点数量角标）所见的集合**一致**，并满足 INV-21 对全部知识库读取入口的一致口径——不得出现「某入口可见而全选未检索」或「某入口不可见而被全选检索命中」。
- **AC-11** — THE SYSTEM SHALL 在每次问答发起时按**当时**的权限与组织树状态实时求值该集合；知识库的新建、改挂与组织树标记调整 SHALL 在下一次问答即生效，无需用户重新选择。
- **AC-12** — THE SYSTEM SHALL NOT 引入任何用于收窄或排除组织知识库可见性的负向授权或排除名单机制；「不使用组织知识库」仅为本轮问答的**作用域选择**，不产生任何授权语义，也不改变任何其他入口的可见性。**按 AC-10 / AC-11 的可见性规则实时算出的允许集合，是本特性规定的求值方式，不在被禁止之列。**

### 2.3 输入区形态与展示

- **AC-13** — THE SYSTEM SHALL 使输入区的组织知识库入口仅提供「全部 / 不使用」两个档位，SHALL NOT 提供逐个知识库的勾选。
- **AC-14** — THE SYSTEM SHALL NOT 在输入区的组织知识库入口展示组织知识库清单，无论该用户有权限的组织知识库有多少个。
- **AC-15** — WHEN 组织知识库档位求值为「全部」且用户有权限的组织知识库数量大于 0, THE SYSTEM SHALL 在输入区上方的附件条显示**一张**表示「全部组织知识库」的卡片；WHEN 求值为「不使用」或数量为 0, THE SYSTEM SHALL 不显示该卡片。
- **AC-16** — WHEN 用户移除该卡片, THEN THE SYSTEM SHALL 把组织知识库档位显式置为「不使用」。
- **AC-17** — THE SYSTEM SHALL 使附件条上由知识选择产生的卡片数量**不随组织知识库总数增长**。
- **AC-18** — WHERE 组织知识库功能被管理员关闭, THE SYSTEM SHALL 不显示组织知识库档位入口、不检索任何组织知识库，并**保留**用户已选的知识空间。

### 2.4 状态记忆与遗留记录处置

- **AC-19** — THE SYSTEM SHALL 在同一用户的刷新与后续会话之间记住其知识范围选择（含组织知识库档位与知识空间列表）。
- **AC-20** — WHEN 用户**仅在订阅模块的 AI 助手面板**改动知识范围后刷新页面, THE SYSTEM SHALL 恢复为日常问答页所保存的知识范围选择（该面板共用同一份状态，但不单独保存）。
- **AC-21** — THE SYSTEM SHALL NOT 对升级前遗留的知识范围选择记录做任何迁移或语义转换：遗留记录**不参与**档位判定（一律视作 AC-02 的「未显式设定」），其中已保存的**知识空间选择照常保留并生效**，其中残留的**组织知识库逐项选择不再表示任何含义**。（需求方裁决 2026-09-22：按全新口径处理，不引入迁移。）
- **AC-22** — WHEN 用户此前从未保存过任何知识范围选择, THEN THE SYSTEM SHALL 采用 AC-02 的兜底口径。
- **AC-23** — WHERE 管理员在升级前配置过组织知识库清单（含默认勾选与排序）, THE SYSTEM SHALL 使该配置**不再影响**对话知识范围的默认值；平台侧该配置入口自身的既有行为本期不变。

### 2.5 入口范围

- **AC-24** — THE SYSTEM SHALL 使本口径适用于**所有复用该问答输入区的入口**（含日常问答页、订阅模块的 AI 助手面板、独立对话页与分享页），不因入口不同而分叉。
- **AC-25** — THE SYSTEM SHALL NOT 改变**任务模式执行态（灵思）**的知识选择行为——即任务已创建后的输入区（`TaskModeInput` + `KnowledgeSpaceSelect`）的选择项、选择器、持久化口径与后端链路的对外行为，保持本版本之前的状态。

  > **修订（2026-09-22，需求方裁决）**：任务模式**落地页**（`TaskModeChatInput`，复用日常 `AiChatInput`）**不在本条保护范围内**。它与日常问答共用同一输入区组件，无法在不分叉组件的前提下豁免，故**跟随本特性口径**：默认档位为「全部」，提交时按档位判定 `org_knowledge_enabled` / `useKnowledgeBase`（原实现按 `type === 'org'` / 数组长度判定，在「不使用」档会把档位误报成「使用了组织知识库」）。
  >
  > 由此产生一处**对外行为变化，需求方已确认**：落地页首次提问的默认行为由「不检索组织知识库」变为「检索全部组织知识库」——这正是 AC-01/AC-02 的默认口径，落地页只是随之对齐。

## 3. 边界情况

- 当用户有权限的组织知识库数量为 **0** 时，系统应正常作答：不报错、不阻断发送、不出现档位求值异常。
- 当「全部」档位的服务端解析**失败或超时**时，系统应**降级为「本轮不检索组织知识库」继续作答**，不中断本轮问答、不向用户暴露解析失败。
- 当组织树标记或知识库归属发生变化导致可见集合变化时，**下一次问答**按新集合求值；历史会话不被回填、不重算。
- 当用户对已有轮次发起**重新生成或继续追问**时，按**发起该次请求时**的档位与知识空间选择求值。
- 当组织知识库功能被管理员**关闭**时，已保存的「全部」档位不产生任何检索行为，用户既有知识空间选择保留；功能**重新开启**后该档位恢复求值。
- 当用户在**多个标签页或多个窗口**同时打开问答页时，其知识范围改动以最后写入者为准（沿用既有共用状态的行为口径）。
- 遗留记录**不做迁移**（AC-21）：档位判定只认新模型写入的标记，遗留记录因此一律落入 AC-02 兜底，**不存在「判定一次并防重」的迁移时刻**。
- 升级前「既选了组织知识库、又选了知识空间」的用户，升级后落到「不使用组织知识库 + 保留原知识空间」——相对升级前是**收窄**。这是「不做迁移」的已知取舍：判断不出其当初意图时，不替用户扩张可见范围；用户在输入区一键切为「全部」即可恢复。
- 本特性**不新增错误码，也不新增任何错误路径**；原有「组织知识库数量超过固定上限则拒绝」的拒绝口径不再被本特性的任何行为触发（AC-09）。
- **关于移除「指定几个组织知识库」能力**的确认口径：该能力在既有实现中存在，本特性将其明确下线（AC-13）。下线理由是——在「默认全部」的世界里，逐项勾选的价值只剩「缩小到某几个库」，而它与「兜底全选 × 显式档位」的双态模型无法共存（取消单项要么物化全量名单而必然过期，要么引入排除名单而违反 AC-12 与 INV-20）。需要「只查某几个库」的组织，应通过**知识空间**承载（先选定知识空间，即 AC-04 的「只查空间」口径）。
