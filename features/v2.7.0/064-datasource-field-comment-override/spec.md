# Feature: 数据源字段说明人工订正（064-datasource-field-comment-override）

> **本文档定位 — 纯 What（需求口径，不随代码漂移）**
>
> spec 只回答 **做什么 / 验收标准 / 不做什么**。
> **所有 How（决策、数据流、字段、API、Service、前端、文件清单、性能指标）一律不写在这里。**
> How 的唯一真相在 [design.md](./design.md)（接手必读）与 [tasks.md](./tasks.md)（执行流水）。

**关联 PRD**: 用户需求（2026-09-23）：数据源表的**库内注释允许人工订正**，但**不能修改对应的真实的库内注释**；当前界面上字段级说明只是只读展示，管理员无法操作。
**优先级**: P0
**所属版本**: v2.7.0
**依赖**: F061-datasource-qa（`db_datasource_table` 表、表详情视图、重新采集链路、schema 注入与召回、错误码模块 117）。
**本特性不新增错误码**（不新增任何拒绝路径，沿用模块 117）。

> **范围边界**（写清「明确不做什么」比写「做什么」更能防 scope 膨胀）
> - **本次纳入**：
>   - **字段级订正入口**：管理员可对已采集表的**字段**逐个填写 / 修改「字段说明」并保存 —— 这是 F061 **AC-14**「字段描述留空并由人工补充」承诺的那个入口，此前一直缺失
>   - **只落平台侧**：订正内容是本平台的覆盖层，**绝不回写客户数据库**（不执行 `COMMENT` / DDL，不改库内注释）
>   - **重采集不覆盖**：把 F061 **AC-12**「重采集不得覆盖人工内容」的口径从**表级**扩展到**字段级**
>   - **注入优先级**：注入模型的字段说明以「人工订正优先、库内采集兜底」取值
>   - **召回口径**：订正文本与表名 / 业务描述 / 库内注释同口径参与数据源表召回匹配
>   - **界面可辨识**：能看出某字段的说明是人工订正还是库内采集，并保留库内原值的只读可见
> - **本次明确排除**：
>   - **回写客户数据库**：需求方明确要求「不能修改对应的真实的库内注释」，平台对客户库始终是只读的（此点不在任何条件下放宽）
>   - **表级注释的人工订正**：表级已有既有「业务描述」（F061 AC-11），本特性不动其口径、不加表级订正入口
>   - **字段级授权**：不引入按字段授权；数据源仍为授权唯一粒度（沿用 F061 AC-48）
>   - **样例值采集**：仍不读取表内真实数据行（沿用 F061 AC-13）
>   - **批量导入 / 导出订正文本**：无此需求，不做
>   - **字段说明的长度上限**：与既有表级业务描述同口径，不额外设限（超长文本由 F061 既有的 schema 预算 / 检索降级机制兜底）
>   - **修订 F061 的 AC-14 文本**：AC-14 的要求不变，本特性只是交付它承诺的入口（AC-12 的字段级范围限定本次已回写 F061 spec）

## 1. 用户故事

作为 **数据源管理员**，
我希望 **给字段补上库内注释缺失的业务含义（或订正库内那句与业务不符的说明）**，
以便 **模型按我们的口径理解字段，问数结果不再因为一句错误的库内注释而跑偏**。

作为 **对客户库只有只读权限的管理员**，
我希望 **订正只发生在毕昇平台这一侧、绝不碰客户数据库**，
以便 **在不获得（也不想获得）建表 / 改注释权限的前提下，把口径讲清楚**。

作为 **反复重新采集的表结构维护者**，
我希望 **重新采集之后我写的字段说明还在**，
以便 **不必每次采集完都重写一遍（这也是我愿意花时间写它的前提）**。

## 2. 验收标准

### 2.1 订正入口与保存

| ID | 角色 | 操作 | 预期结果 |
|----|------|------|---------|
| AC-01 | 管理员 | 在表详情中对某个**已采集字段**填写「字段说明」并保存 | 保存成功；表详情中该字段显示订正文本，并带「已订正」标记 |
| AC-02 | 管理员 | 保存字段说明 | 内容只落在毕昇平台侧；**对客户数据库不执行任何写操作**（含 `COMMENT` / DDL），库内注释的读取值不发生变化 |
| AC-03 | 管理员 | 只改字段说明 / 只改表级业务描述 | 两者是独立字段，编辑其一不影响另一个 |

### 2.2 与采集的关系

| ID | 角色 | 操作 | 预期结果 |
|----|------|------|---------|
| AC-04 | 管理员 | 保存过字段说明后触发重新采集 | 字段结构以本次采集为准；既有字段说明**不被覆盖**（F061 AC-12 的字段级延伸） |
| AC-05 | 管理员 | 某字段在本次采集中未返回（库中已删除 / 改名） | 该字段的订正内容保留；该字段**不注入模型**；界面标明该字段已不在库中；若该字段日后重新出现，订正恢复生效 |

### 2.3 注入与召回

| ID | 角色 | 操作 | 预期结果 |
|----|------|------|---------|
| AC-06 | 系统 | 构造注入模型的表结构 | 字段说明取「人工订正优先、库内采集注释兜底」；F061 AC-14 承诺的人工补充在此生效 |
| AC-07 | 管理员 / 普通用户 | 用订正文本里的说法提问 | 该文本与表名 / 业务描述 / 库内注释同口径参与召回匹配 |

### 2.4 界面与一致性

| ID | 角色 | 操作 | 预期结果 |
|----|------|------|---------|
| AC-08 | 管理员 | 查看某已订正字段 | 能区分该说明来自人工订正还是库内采集；库内原值**只读可见**（供核对，且不可在此编辑） |
| AC-09 | 管理员 | 清空某字段的说明并保存 | 该字段的订正被撤销；界面与注入均回落到库内采集注释，「已订正」标记消失 |
| AC-10 | 管理员 | 查看某引擎无法采集注释的字段（F061 AC-14） | 已有人工订正的字段不再显示「未采集到注释」告警；但仍**明示库内无注释**，不得让人误以为库里有 |
| AC-11 | 管理员 | 使用字段级订正 | 不因此获得任何字段级授权入口；数据源仍为授权唯一粒度（沿用 F061 AC-48） |

## 3. 边界情况

- 当某字段**从未被订正**时，注入与界面显示均保持既有行为（库内采集注释；采集不到时按 F061 AC-14 明示），本特性不改变这一类字段的任何对外表现。
- 当字段说明被清空（空串）后保存时，视为**撤销订正**，不是「订正为空文本」——否则会把库内注释遮成空白。
- 当**多个字段同时订正**时，一次保存只影响本次提交涉及的字段；未提交的字段保持原值。
- 当**同一字段被先后两位管理员编辑**时，后提交者覆盖先提交者的内容（与既有表级业务描述同口径，不做并发冲突提示）。
- 当字段订正文本**很长**时，不单独截断或拒绝；其占用的注入预算由 F061 既有的 schema 预算 / 检索降级机制处理。
- 当表**未暴露给模型**（`enabled=0`）时，其字段订正照常可编辑与保存，只是不参与注入——订正不因表的暴露状态而丢失。
- 字段订正的可见范围与数据源授权一致：能打开该数据源表详情的角色即可订正，不额外放宽。
