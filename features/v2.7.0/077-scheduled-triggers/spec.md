> **范围边界**
> - **本次纳入**：
>   - **定时任务**：为应用（工作流或助手）建立定时任务，含目标应用、触发计划、运行身份、可选预设输入、名称与描述；支持创建、编辑、启停、删除、立即运行
>   - **触发计划两种形态**：周期（cron，分钟粒度）与一次性（指定绝对时间，执行后自动停用）
>   - **调度与运行**：按计划触发、同一任务互斥（重叠处理）、全局并发上限（超限顺延）、漏跑合并补跑一次、**卡死运行会被自动判失败并释放互斥**
>   - **事件触发**：行内系统凭服务账号密钥触发指定任务（含防重放与放大量护栏）
>   - **触发前复检**：每次触发前校验目标应用与运行身份，不满足时按触发方式显式处置
>   - **任务管理**：列表（触发计划 / 下次执行 / 上次结果 / 启停 / 失败原因），入口在应用编辑器「对外发布」页签的「定时任务」面板
>   - **生成方式**：手动表单；自然语言 → 草稿 → **人工确认** → 落库（一期仅新建）
>   - **运行身份治理**：创建期校验、触发期复检、可用运行身份查询、身份与应用的停用/删除处置
>   - **知识可见性口径**：定时运行作为新的知识读取路径，按应用既有「用户知识库权限校验」开关的两档口径判定
>   - **失败闭环**：首败通知、连续失败达阈值自动停用并通知
>   - **审计与可观测**：管理动作审计（审计页可见）、运行动作留痕（不占审计页）、运行归因（任务列表一跳监控详情、可见本次所用版本标识）
>   - **预设输入**：含单个人工输入节点的应用可配预设输入自动提交；未配置时停留等待并通知，不永久悬挂、不记成功
>   - **界面三语**：zh-Hans / en / ja
> - **本次明确排除**（延后 / 另立变更）：
>   - **渠道侧改动**：一键发布至 API / 免登录页 / 需登录链 / iframe 嵌入 / 分享链均已具备，本期不改；不做"多渠道选择 → 一键分发"改造；不做"Agent Portal"具名渠道；不做企微/钉钉/飞书/公众号等第三方渠道发布

>   - **外部运行查询接口**：本特性不提供供外部系统查询运行结果的接口；事件触发只返回受理与运行标识，"跑得怎么样"由平台侧（任务列表 / 监控）与站内信承载

## 1. 用户故事

**A. 应用编辑者（业务用户）**
作为 **对某应用有编辑权限的业务用户**，
我希望 **用手动表单或一句自然语言就能给这个应用配好"何时自动运行"（且自然语言结果必须先经我确认），并在同一处看到它的下次执行与上次结果**，
以便 **不用记调度语法就让周期性任务自动跑起来，且任何时候都能掌握它是否健康**。

**B. 平台管理员（超管 / 租户管理员）**
作为 **平台管理员**，
我希望 **定时任务的运行身份由专用身份承载、运行期锁定、每次触发前复检，并在应用被引用、身份被停用或任务连续失败时显式处置并通知**，
以便 **人员与资源变动后任务不会静默乱跑、也不会静默停摆，且可管可查**。

**C. 运行身份与安全（平台与行方的安全边界）**
作为 **负责安全边界的角色**，
我希望 **无人值守运行一律非特权、任何触发方式都无法指定或覆盖执行身份，且定时运行读取知识时的可见范围与交互运行遵循同一份判定**，
以便 **定时运行不成为越权与数据越界的旁路**。

**D. 行内系统对接方 / 行方审计**
作为 **行内某系统的对接开发（或行方审计角色）**，
我希望 **在业务事件发生时用一把权限明确的密钥触发平台上已配好的任务并立即拿到受理或拒绝结果，同时每次触发都可追溯、可防重放**，
以便 **系统集成不必自建调度，且接入行为可管、可查、可追责**。

## 2. 验收标准

> **错误码口径**：本特性**沿用** F076 已申领的 118 段码（如 11807 缺权限位 / 403、11811 端点未登记权限位 / 500、11817 调用方指定执行身份 / 400），**不重复申领**；本特性**新增**的拒绝路径统一归入 **119 段**（申领前须按 release-contract 口径完成三来源复核：`common/errcode/`、全部版本 release-contract、`packages/locales/src/api_errors/`；本轮扫描已确认 119 未被占用，正式复核与号位分配在 design 阶段落）。
> 每条 AC 末尾的 `（D#/§#）` 指向 [discovery.md](./discovery.md) 中的决策或结论，供追溯。

### 2.1 定时任务与触发计划

- **AC-01** — WHEN 用户创建定时任务, THE SYSTEM SHALL 以「目标应用（工作流或助手）、触发计划、运行身份」为必要配置，并接受可选的预设输入、名称与描述；IF 任一必要配置缺失或未通过服务端校验, THEN THE SYSTEM SHALL 拒绝创建并返回可读错误（119 段），列表中不得出现该任务。（D2/D3/D12）
- **AC-02** — WHEN 用户停用任务, THE SYSTEM SHALL 停止其后续触发（停用期间到期的轮次不触发、不补跑、不计失败）；WHEN 任务被重新启用, THE SYSTEM SHALL 自下一个计划时刻起恢复触发；启用 / 停用状态在任务列表可见。（§3）
- **AC-03** — WHEN 用户编辑任务的触发计划、预设输入、运行身份、名称或描述, THE SYSTEM SHALL 使变更对后续触发立即生效（已发起的一轮按发起时的配置执行完毕），同步刷新列表中的「下次执行」时间，并对运行身份的变更执行与创建期相同的校验（AC-20）与审计留痕（AC-49）。（§3/D3）
- **AC-04** — WHEN 任务被删除, THE SYSTEM SHALL 停止其全部后续触发并从列表移除；该任务既有的运行留痕与审计记录不因删除而丢失、仍可追溯。（D10/D19）
- **AC-05** — IF 目标应用下启用中的定时任务数已达上限（默认 20，可配置）, THEN THE SYSTEM SHALL 拒绝为该应用新建任务，并返回可读错误与当前数量（119 段）。（§3）
- **AC-06** — WHEN 用户提交 cron 触发计划, THE SYSTEM SHALL 由服务端完成校验（绕过界面直连接口同样受校验）：仅接受 5 段表达式（分 时 日 月 周，分钟粒度），多余空白按归一化处理；**接受**数字、范围（如 `1-5`）、列表（如 `1,15`）、步进（如 `*/5`）与三位英文缩写（如 `mon-fri`）；**IF** 表达式为秒级 / 非 5 段 / 预定义别名（如 `@daily`）/ 星期取值越界（如 `7`）/ 月份或时间字段越界等不合法形态, **THEN** THE SYSTEM SHALL 拒绝并返回可读原因（119 段），不得保存、不得静默改写为其它计划。（§3/§4.4）
- **AC-07** — WHEN 用户提交或修改 cron 触发计划, THE SYSTEM SHALL 返回人类可读的触发解释（如「每天 9:00」）与未来至多 5 次运行时间（按服务器时区展示、取整到分钟）；该预览与列表中的「下次执行」必须同口径、不得互相矛盾。（§3/D7）
- **AC-08** — WHERE 触发计划为一次性, THE SYSTEM SHALL 接受一个含日期的绝对时间（以服务器时区口径解释并明确标注）；WHEN 该次运行结束（成功或失败）, THE SYSTEM SHALL 自动把任务置为停用且不再重试，该状态变化在任务列表可见；因目标应用下线而尚未执行不算「结束」，其处置见 AC-16。（D17）
- **AC-09** — WHERE 涉及时间的一切输入与展示（触发计划、人类可读解释、下次执行、运行与留痕时间）, THE SYSTEM SHALL 统一采用服务器时区 Asia/Shanghai 口径并在界面明确标注；不支持按任务配置时区。（D7）

### 2.2 调度与运行

- **AC-10** — THE SYSTEM SHALL 使计划时刻与实际触发时刻的偏差不超过 30 秒（周期与一次性一致；因全局并发上限顺延导致的偏差除外，见 AC-12）。（§3/D4）
- **AC-11** — WHEN 计划时刻到达而该任务上一轮运行尚未结束, THE SYSTEM SHALL 按重叠处理：**周期任务**跳过本轮并记录「已跳过（上一轮未结束）」；**一次性任务**不跳过、顺延到随后的调度轮次重试直至可执行（只有一次机会，不因重叠丢弃）；被跳过的轮次不计失败、不计入连续失败。（D6/D17）
- **AC-12** — WHEN 计划轮次触发时平台同时运行的定时任务数已达全局上限（默认 10，可配置）, THE SYSTEM SHALL 把该轮顺延到随后的调度轮次重试直至可执行——不并发执行、不丢弃该轮（周期与一次性同样适用）；立即运行遇同一上限的处置见 AC-17。（§3）
- **AC-13** — WHEN 启用中的任务因平台停机或调度停摆跨过一个或多个计划周期, THE SYSTEM SHALL 在恢复后做漏跑合并——无论错过几个周期只补跑一次（不产生补跑风暴），补跑后回到正常节奏；一次性任务错过绝对时间的情形同样只补跑一次。（D6）
- **AC-14** — WHEN 一轮运行被发起, THE SYSTEM SHALL 在该任务上形成「运行中」标记（同一任务同一时刻至多一个、不重叠运行），列表可见运行中状态与开始时间；每轮运行最终收敛为「成功 / 失败 / 已跳过」之一，并作为该任务的「上次结果」与结束时间记录、列表可见；「等待人工输入」为暂停状态（见 AC-46），不构成终态。（§3）
- **AC-15** — WHEN 一轮运行超过运行时长上限（默认 60 分钟，可配置）仍未到达终态, THE SYSTEM SHALL 由平台自动把该轮判定为失败、结束其「运行中」标记，使该任务后续周期可再次触发；该判定不依赖发起运行的进程仍然存活——平台重启或工作进程异常退出后，超时同样判定。**任何任务不得因一次卡死而永久静默停摆**。（§1.1/§3）
- **AC-16** — WHEN 触发前复检发现目标应用处于下线状态, THE SYSTEM SHALL 按触发方式分别处置：**计划轮次（周期任务）**跳过本轮，记为「已跳过（应用已下线）」、不计失败、不计入连续失败、列表可见原因，应用重新上线后按计划继续触发；**一次性任务**不跳过——保持启用并在列表标注「等待应用上线」，应用重新上线后补跑一次（受 AC-13 约束），上线前不消耗其唯一一次机会；**事件触发与立即运行**一律拒绝本次触发并返回可区分错误（119 段），不产生运行。（D13/D17）
- **AC-17** — WHEN 用户对任务执行「立即运行」, THE SYSTEM SHALL 发起一轮与计划轮次同构的运行：共用同一任务的不重叠规则与运行时长上限，结果同样记入「上次结果」，并计入审计（AC-49）；IF 已有运行中的一轮，或平台同时运行数已达全局上限, THEN THE SYSTEM SHALL 拒绝本次立即运行并给出可读提示（119 段）——不排队、不并发、不顺延；立即运行不改变既定触发计划与「下次执行」时间；立即运行的失败**不计入**连续失败（人工试跑不触发 AC-55 的自动停用）。（D9/D6/§3）

### 2.3 运行身份与权限

- **AC-18** — WHEN 用户创建定时任务, THE SYSTEM SHALL 要求为其选定一个服务账号专用身份作为运行身份；该身份一经保存即成为该任务的唯一执行身份（**运行期锁定**：每次运行都以它执行、触发方无法改变；编辑时可更换，更换须走与创建期相同的校验并留痕，见 AC-03）。（D3/★评审裁定）
- **AC-19** — THE SYSTEM SHALL 使任务的每一次运行（计划轮次、事件触发、立即运行）一律以该任务当前的运行身份执行；**任何触发方式均不得在请求或任务配置中指定、附加或覆盖执行身份**——出现此类输入（如携带用户身份参数）一律拒绝（400 / 11817），不得静默忽略、不得按其指定身份执行。（D3/INV-23③）
- **AC-20** — WHEN 用户提交创建定时任务, THE SYSTEM SHALL 在服务端一次性校验全部前置条件：创建者对目标应用持有 `edit_app`；目标应用存在且类型合法；所选运行身份为服务账号专用身份（不得为普通用户、管理员或平台默认操作员）、存在且启用、未被提权；且该运行身份对目标应用持有 `use_app`。任一条件不满足即拒绝创建（119 段），且「创建者无管理权限」与「运行身份不可用」两类原因可区分观测。（D3/D9/§1.2）
- **AC-21** — WHEN 任一次触发到达（计划轮次、事件触发、立即运行）, THE SYSTEM SHALL 在开始执行前**重新复检**：目标应用仍存在且未下线、运行身份仍可用（存在 / 启用 / 未被提权）、运行身份对目标应用的 `use_app` 仍有效；复检在每次触发都执行，不得只在创建时校验一次；复检不通过时的处置见 AC-16（应用下线）、AC-22（身份不可用）、AC-31（应用已删除）。（D13/D14/§1.2）
- **AC-22** — IF 触发前复检发现运行身份已停用、已删除或已被提权，或其对目标应用的运行权限已被撤销, THEN THE SYSTEM SHALL 拒绝该次运行：不执行、**不回退为任何其他身份**（含创建者、默认操作员）执行，按一次失败记录并计入连续失败，并按 AC-54 的通知口径（同一连续失败序列只发首败一条）通知创建者；达阈值后按 AC-55 自动停用。（D3/D14/D15）
- **AC-23** — WHEN 运行身份对目标应用的运行授权被撤销, THE SYSTEM SHALL 使该撤销在最坏 ≤10 秒内对平台判定生效——此后「可用运行身份」查询与任一次触发的前置复检一律按新状态给出拒绝，不得在窗口之后仍按旧授权放行执行。（§1.2）
- **AC-24** — WHEN 对某目标应用持有 `edit_app` 的用户查询「可用运行身份」, THE SYSTEM SHALL 返回该应用当前可用的服务账号专用身份清单（含账号标识、是否启用、是否已具备该应用的运行权限，并区分「可用」与「已列但缺运行权限」），**不返回任何密钥或凭据信息**，也不使调用者获得对专用身份的任何管理能力；不持有 `edit_app` 的调用一律 403。（D18/INV-23①）
- **AC-25** — THE SYSTEM SHALL 按应用级权限位在服务端收口定时任务的全部管理动作：创建 / 编辑 / 启停 / 删除 / 立即运行一律要求调用者对目标应用持有 `edit_app`，每个入口独立校验，不得仅依赖界面门控；不满足一律 403（对外表现为「看不到入口」且「直接调用也改不动、建不了」）。（D9）
- **AC-26** — WHEN 未持有目标应用 `edit_app` 的系统管理员或当前租户管理员操作定时任务, THE SYSTEM SHALL 允许其创建 / 编辑 / 启停 / 删除 / 立即运行（沿用平台既有的管理员准入口径，不另立特权路径）；该允许范围与平台其他管理场景对同角色的判定保持一致。（D9/§1.2）
- **AC-27** — THE SYSTEM SHALL 以「运行身份具备运行权限且身份可用」作为无人值守运行的唯一准入条件——人类（含任务创建者）的权限变化不改变已锁定运行身份的执行口径。（D9）

### 2.4 知识可见性与引用级联

- **AC-28** — WHEN 定时运行触发一次包含知识检索的执行, THE SYSTEM SHALL 按目标应用既有的「用户知识库权限校验」开关判定本次检索的可见集合：开关**关闭**时按**应用配置者**的可见范围检索（安全有界共享，**非**「不过滤」）；开关**开启**时按**本次运行身份**（服务账号专用身份）的可见范围检索。定时运行作为新的知识读取路径，必须接入与应用交互运行**同一份**可见集合判定——不得引入第三种口径、不得按入口分叉、不得越过上述身份各自的可见边界。（§1.7/INV-21）
- **AC-29** — WHEN 创建定时任务且目标应用的知识检索按运行身份判定（开关开启）, IF 所选运行身份对该应用绑定的知识范围没有读取授权, THEN THE SYSTEM SHALL **拒绝创建**，并在错误中指明需要先为该运行身份授予相应知识范围的读取权限（119 段）；运行期若该授权被撤销，相关检索如实表现为空命中 / 降级（本轮运行本身不因此判失败），**一律不得回退**到配置者可见范围检索。（§1.7/INV-21/★评审裁定）
- **AC-30** — IF 目标应用下存在启用中的定时任务, THEN THE SYSTEM SHALL 拒绝删除该应用，返回当前启用任务数量与可读错误（119 段），并指明下一步（由持有该应用编辑权限者先停用或删除这些任务）；仅停用或历史任务不阻断删除。（D14）
- **AC-31** — IF 任务因旁路原因指向已不存在（已删除）的目标应用, THEN THE SYSTEM SHALL 在触发期 fail-closed：拒绝该次运行、自动停用该任务并通知创建者（按 AC-32 的收件人兜底规则）——不静默跳过、不持续累积失败。（D14）
- **AC-32** — WHEN 需向任务创建者发送通知而其账号已停用或删除, THE SYSTEM SHALL 将通知改投当前租户的管理员（租户管理员 / 超管），不得静默丢弃。（D14）

### 2.5 事件触发

- **AC-33** — WHEN 外部系统以服务账号密钥调用任务触发接口, THE SYSTEM SHALL 按既有服务账号密钥校验口径返回真实 HTTP 状态：**未携带与格式非法按既有口径归为同一类（401 / 11801）**；无效 / 已吊销 / 已过期 / 所属账号已停用四类相互可区分（401 / 11802–11805）；密钥缺少该接口所需权限位返回 403 / 11807；鉴权依赖不可用时返回 503，绝不降级放行；IF 目标任务不存在、不在该密钥的授权范围内，或任务已处于停用状态, THEN THE SYSTEM SHALL 一律返回 404（情形不可区分，沿用既有防枚举口径）。**授权范围口径**：密钥所属服务账号对该任务的目标应用持有运行权限，即视为「在授权范围内」（与 AC-24 同源判定）。（D1）
- **AC-34** — WHEN 触发请求通过校验并被受理, THE SYSTEM SHALL 立即返回受理结果（含本次运行标识，供调用方与平台侧对账、支持排查）而不等待运行完成；本次运行一律以该任务当前的运行身份执行，触发方无法改变。（D1/D3）
- **AC-35** — THE SYSTEM SHALL 使触发请求体仅接受「任务标识 +（可选）入参映射」；IF 请求携带执行身份（拒绝口径与码值同 AC-19）、目标应用、触发计划或其余白名单外字段, THEN THE SYSTEM SHALL 拒绝该请求（400），不得静默忽略、不得按其指定执行。（D1/INV-23③）
- **AC-36** — THE SYSTEM SHALL 使任务触发接口纳入 `/api/v2` 的权限位逐条登记；IF 该接口缺少权限位归属, THEN THE SYSTEM SHALL 使其调用一律被拒绝（500 / 11811），不得默认放行。（§4.12）
- **AC-37** — THE SYSTEM SHALL 要求每次触发携带时间戳与一次性随机数，仅受理落在有效时间窗内（默认 ±5 分钟，可配置）、且随机数尚未被使用过的请求；IF 时间戳超出时间窗或随机数被重复使用, THEN THE SYSTEM SHALL 以可区分的 119 段错误码拒绝该请求、不执行，且不产生第二次运行。（D1）
- **AC-38** — WHEN 目标任务已有运行中的一轮, THE SYSTEM SHALL 对新增触发采用**拒绝**语义（而非幂等接受）：不产生第二次并发运行，调用方收到与鉴权失败 / 参数错误可区分的错误响应（119 段），该拒绝不计入连续失败、不改变「上次结果」；THE SYSTEM SHALL 另设**任务级触发频率上限**（默认 10 次/分钟，可配置）作为事件触发面的放大量护栏——超限的触发不产生运行并以可区分结果返回。该护栏是调度侧的安全约束，**不同于**平台级 API 限流 / 配额体系（后者不在本特性范围）。（D1/D6/§3）

### 2.6 生成（手动与自然语言）

- **AC-39** — WHEN 用户在「对外发布」的「定时任务」面板提交创建（目标应用为助手或工作流、触发计划为周期或一次性、运行身份、可选预设输入）, THE SYSTEM SHALL 落库一条启用中的任务，并使其在任务列表立即可见。（D2/D11）
- **AC-40** — THE SYSTEM SHALL 在任务面板内提供完整的任务管理动作：查看列表、创建、编辑、启停、删除、立即运行——各项的准入与拒绝口径见 AC-25、AC-17。（D11）
- **AC-41** — WHEN 用户在任务面板以自然语言描述需求（输入长度不超过上限 2000 字符；为空或超限时拒绝并提示上限）, THE SYSTEM SHALL 返回一份**不落库**的草稿，草稿须含：识别出的目标应用、触发计划的人类可读描述、下次运行时间（一次性为绝对时间）、识别出的预设输入；IF 模型输出非法（周期表达式不合法 / 目标应用不存在或创建者无 `edit_app` / 预设输入超尺寸 / 必要信息缺失）, THEN THE SYSTEM SHALL 拒绝并给出明确、可区分的提示（119 段），不得返回残缺草稿。（D5/§3）
- **AC-42** — THE SYSTEM SHALL 使自然语言草稿在**人工确认前不产生任何持久副作用**（不出现在任务列表、不被触发面执行）；WHEN 用户完成确认, THE SYSTEM SHALL 仅按确认页当前内容（含用户的修改）落库为启用任务；确认页必须完整回显人类可读触发计划与下次运行时间（一次性为绝对时间）——这是用户发现模型误读（如「每天」→「每分钟」）的唯一位置；用户对草稿触发计划的修改在确认前同步重算并更新回显。（D5）
- **AC-43** — THE SYSTEM SHALL 限定自然语言生成一期仅用于**新建**任务；IF 用户以自然语言提出修改、启停或删除既有任务, THEN THE SYSTEM SHALL 不生成任何变更并引导其使用表单操作。（D16）
- **AC-44** — WHEN 目标应用包含单个人工输入节点, THE SYSTEM SHALL 允许创建者为任务逐项配置「预设输入」（默认最多 20 项、单项文本不超过 2000 字符，均可配置）；IF 预设输入超限或格式非法, THEN THE SYSTEM SHALL 拒绝保存并逐项提示（119 段）。（D12）
- **AC-45** — WHEN 已配置预设输入的任务被触发、运行中遇到人工输入节点, THE SYSTEM SHALL 按预设输入自动提交并继续运行；该运行的继续与最终结果可从任务列表与监控观测到。（D12）
- **AC-46** — IF 任务运行中遇到人工输入节点而对应预设输入未配置, THEN THE SYSTEM SHALL 把本次运行置为「等待人工输入」暂停状态（不是终态）并通知创建者（按 AC-54 的去重口径：同一待输入序列只通知一次）；该运行**不晚于运行时长上限被回收为失败终态**，并作为一次失败计入连续失败——不得永久悬挂、不得被记为成功。（D12/§3/★评审裁定）
- **AC-47** — IF 目标应用包含多个人工输入节点或文件类输入项, THEN THE SYSTEM SHALL 在创建任务时**拒绝创建**并明确指出不支持的部分（一期不支持该类应用的定时化）；不得在运行期才暴露。（D12/★评审裁定）
- **AC-48** — WHEN 定时运行结束, THE SYSTEM SHALL 不为该次运行产生任何应用会话与消息（工作流与助手一致，均无会话落点），结果仅可从任务列表与监控查询到；创建任务处须明确提示这一差异。（D2/D8）

### 2.7 审计、可观测与失败闭环

- **AC-49** — WHEN 任一管理动作发生（创建 / 编辑 / 启用 / 停用 / 删除 / 立即运行）, THE SYSTEM SHALL 生成审计记录：在平台审计页可见、可按动作类型筛选，含操作者、动作与关键前后取值。（D19/§3）
- **AC-50** — WHEN 任一运行发生, THE SYSTEM SHALL 留存可归属到任务与本次运行的取证记录（动作者＝该任务的运行身份；系统自动产生的处置动作，如超时判失败与达阈值自动停用，以系统身份留痕），但该动作类型**不进入**审计页白名单：不出现于审计页的列表与筛选项中。（D19/★评审裁定）
- **AC-51** — THE SYSTEM SHALL 使定时任务的全部管理审计与运行留痕不含任何密钥明文或等价凭据材料，也不含对话原文或用户输入正文——留痕只存标识与摘要（任务、运行标识、时间、结果、耗时、失败类别）。（§3/§4.11/INV-11）
- **AC-52** — WHEN 任一运行结束, THE SYSTEM SHALL 在任务列表使该任务最近一次运行的时间、结果、耗时与失败原因可见，并支持**一跳打开该次运行的监控详情**，且可见本次运行所使用应用内容的版本标识；即使同一应用存在多个定时任务，从任务出发仍可唯一定位到该次运行；监控侧既有的字段与筛选维度保持不变。（D19/D8/D13）
- **AC-53** — THE SYSTEM SHALL 使定时任务及其运行记录对所属租户可见、对其他租户不可见（跨租户访问一律 404）。（D8/§1.5）
- **AC-54** — WHEN 某次运行以失败结束且是当前连续失败序列中的**第一次**, THE SYSTEM SHALL 向任务创建者（创建时锁定）发送一条站内信，含任务与失败原因；同一连续失败序列内不逐次重复通知（AC-22、AC-46 的通知同样沿用本口径）；成功运行不发送任何通知，恢复成功不补发。（D15/D8）
- **AC-55** — WHEN 连续失败次数达到阈值（默认 5，可配置）, THE SYSTEM SHALL 自动停用该任务并发送一条通知；失败计数只统计真正失败的轮次（「已跳过」不计入；立即运行不计入，见 AC-17）；运行成功使连续失败计数清零；失败不自动重试（等待触发计划的下一次自然发生）。（D15/§3）
- **AC-56** — THE SYSTEM SHALL 使失败通知默认仅经站内信送达、不外发任何外部渠道；除非该通知类型被显式登记进外发白名单（登记之前外发一律不发生）。（§3）

### 2.8 界面与三语

- **AC-57** — THE SYSTEM SHALL 在应用编辑器（助手与工作流共用同一面板）的「对外发布」中提供「定时任务」入口与面板；该入口对持有目标应用 `edit_app` 的用户可见、并对无该权限者不可见——**入口可见性不继承面板既有门控**（面板其他页签的可见性口径不变）；无论界面如何，服务端一律按 AC-25 强制。（D11/★评审裁定）
- **AC-58** — THE SYSTEM SHALL 在任务列表展示每条任务的：人类可读的触发计划、下次执行时间、上次运行结果（失败时可见失败原因）、启停状态与启停操作；列表在打开面板时自动刷新并提供手动刷新。（D11/§1.4）
- **AC-59** — THE SYSTEM SHALL 使定时任务的全部界面文案具备 zh-Hans / en / ja 三语，并使本特性新增的全部错误码文案以三语同批交付。（D10/§3）

## 3. 边界情况

- **一次性任务遇互斥**：顺延而非跳过（只有一次机会）；周期任务则跳过并记「已跳过」。（AC-11）
- **一次性任务遇应用下线**：不跳过、不消耗机会——保持启用并标注「等待应用上线」，上线后补跑一次。（AC-16）
- **一次性任务遇目标应用已删除**：按不可用处置（自动停用 + 通知），不再等待。（AC-31）
- **漏跑合并**：停机跨多个周期只补跑一次；补跑本身也受互斥与并发上限约束。（AC-13/AC-11/AC-12）
- **`已跳过` 不计失败**：不计入连续失败、不触发通知。（AC-11/AC-55）
- **周期任务遇应用下线**：跳过并标注原因，不算失败、不通知；重新上线后自动恢复。（AC-16）
- **事件触发 / 立即运行遇应用下线或并发已满**：一律拒绝并给出可区分错误——人（或外部系统）触发的动作要即时反馈，不顺延、不排队。（AC-16/AC-17）
- **运行身份被撤权 / 停用 / 提权**：触发期拒绝且**不回退为任何其他身份**；按失败计入连续失败直至自动停用。（AC-22/AC-55）
- **无人值守遇人工输入**：有预设输入则自动提交；无则进入「等待人工输入」暂停态并通知一次，最迟在运行时长上限被回收为失败（计入连续失败）——不得悬挂、不得记成功。（AC-45/AC-46）
- **卡死运行**：超时自动判失败并释放互斥，后续周期恢复；不依赖原进程存活。（AC-15）
- **重复触发 / 并发触发**：拒绝而非幂等接受；防重放窗口外的重复请求同样拒绝。（AC-38/AC-37）
- **手动试跑**：立即运行不计入连续失败，不会因人为反复试跑把任务自动停用。（AC-17/AC-55）
- **多任务同应用**：任务列表按任务归因并可一跳进监控详情，可见本次所用版本标识。（AC-52）
- **租户隔离**：任务、运行记录、可用运行身份清单均限本租户；跨租户 404。（AC-53/AC-33）
- **工作流与助手一致**：定时运行都不产生应用会话与消息，结果只在任务列表与监控。（AC-48）
- **知识检索为空**：开关开启且授权被撤时如实空命中/降级，不得回退到配置者范围。（AC-29）
