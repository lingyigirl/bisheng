# Feature: 任务正文流式展示与报告交付修复

**关联 PRD**：[需求来源与问题证据](./requirements.md)
**优先级**：P1
**所属版本**：v2.7.0
**依赖**：F035 任务模式与导出工具；F074 协作、事件补播与受控恢复。
**状态**：2026-10-19 用户已确认含多格式与性能要求的规格，并直接补充 Linux/Windows 双平台兼容要求；进入设计评审。

## 1. 用户故事

作为工作台任务模式用户，我希望生成中的回答逐步出现，并能区分主智能体与协作成员的发言，以便了解任务进展，无需一直等到最终结果。

作为报告使用者，我希望 Word、PDF 等实际交付文件保留图片、清晰的表格和正确的列表编号，中文与分页正常，预览和下载可用，以便直接使用报告，减少智能体反复修补和等待。

作为长任务和多人协作用户，我希望实时输出、长历史恢复及报告导出期间，页面仍可滚动、输入和操作，其他任务正常响应，避免修复功能后引入明显卡顿或资源持续增长。

**格式范围**：现有报告交付链路中的 Markdown、HTML、DOCX、PDF；已有代码执行或技能链路生成的 XLSX、PPTX、CSV 和图片，纳入文件完整性、可打开性及交付一致性检查。各格式按自身能力验收，不要求 CSV 具备分页，也不将文件完整性等同于研究事实或公式业务逻辑正确。

## 2. 验收标准

### 2.1 正文实时展示

- **AC-01** — WHILE 上游模型正在分段返回面向用户的正文，THE SYSTEM SHALL 在任务结束前逐步展示已收到的正文，不以任务结束或整段生成完毕作为展示前提。
- **AC-02** — WHEN 正文、思考、工具活动或不同成员的输出交错到达，THE SYSTEM SHALL 分别展示并归属到正确的智能体及本次调用；不得将正文伪装为思考，不得串接不同成员的文本。
- **AC-03** — WHEN 主智能体在调用工具前后分别发言，THE SYSTEM SHALL 按实际顺序保留各段发言，并将最终回答与过程发言区分；最终结果到达时不得把同一份最终回答重复展示两次。
- **AC-04** — WHEN 页面刷新、网络重连或同一事件重复到达，THE SYSTEM SHALL 恢复已生成的可用正文且不重复追加；任务完成后的历史展示与实时展示内容一致。
- **AC-05** — WHEN 同一会话继续新一轮、任务经用户澄清继续或受控恢复重新生成，THE SYSTEM SHALL 将正文归入正确轮次与执行尝试，保留已完成历史，不把旧尝试的未完成正文拼接到新尝试。
- **AC-06** — IF 用户终止任务或执行失败，THEN THE SYSTEM SHALL 停止运行态展示，保留当前仍有效的已生成正文并展示真实终止或失败状态；迟到输出不得重新激活已终止任务。
- **AC-07** — IF 上游模型只返回完整回答而未提供正文增量，THEN THE SYSTEM SHALL 正常展示完整回答，不模拟逐字生成，也不因缺少增量造成空白或丢失结果。

### 2.2 文档导出与排版

- **AC-08** — WHEN 报告引用当前任务工作区内的有效图片，THE SYSTEM SHALL 将图片实际嵌入导出的 Word 和 PDF，包括以工作区根目录或相对源报告目录引用的图片；中文文件名应正常处理。
- **AC-09** — IF 被引用的图片不存在、不可读或无法嵌入，THEN THE SYSTEM SHALL 指出具体失败资源，不得静默丢图后声称完整导出成功。
- **AC-10** — WHEN Word 或 PDF 报告包含多个独立的有序列表，THE SYSTEM SHALL 按各列表声明的起始编号展示，避免跨章节意外连续计数及自动编号与手写编号叠加。
- **AC-11** — WHEN Word 或 PDF 报告包含多列表格或跨页表格，THE SYSTEM SHALL 将表格保持在页面可用宽度内，并在跨页后重复表头；长内容能够换行而不覆盖相邻单元格。
- **AC-12** — WHEN 报告导出过程中资源处理、转换或写入失败，THE SYSTEM SHALL 返回可供任务继续处理的具体失败信息，不将失败文件登记为已成功交付。

### 2.3 兼容与隔离

- **AC-13** — THE SYSTEM SHALL 沿用既有任务、工作区和共享查看的授权边界；图片解析与正文恢复不得读取其他任务、其他租户或工作区之外的本机文件，不得因恶意图片引用扩大资源访问权限。
- **AC-14** — WHEN 查看历史任务或导出不含图片的既有报告，THE SYSTEM SHALL 保持正常展示与导出；本次修复不得要求迁移或覆盖既有会话、产物。

### 2.4 PDF 与多格式交付

- **AC-15** — WHEN 导出含中文、英文、数字和标点的 Word 或 PDF，THE SYSTEM SHALL 保留原文字符并使用可显示它们的字体；不得出现因字体缺失导致的方框、乱码或正文消失。无法满足时须说明具体缺失依赖或资源。
- **AC-16** — WHEN 导出多页 PDF，THE SYSTEM SHALL 产生可打开、可逐页渲染的文件，图表和正文保持在可见页面范围内；不得因转换错误产生内容截断、相互覆盖或意外空白页。文件生成成功与排版核验通过应如实区分。
- **AC-17** — WHEN 同一报告同时交付 Markdown、HTML、Word 或 PDF，THE SYSTEM SHALL 保留共同正文、图表和引用的对应关系；Markdown 与 HTML 在当前预览或交付页面中可解析任务资源，下载后的文档不得依赖用户机器上不存在的生成环境绝对路径。
- **AC-18** — WHEN 用户通过智能体导出或产物区“另存为”获得 Word/PDF，THE SYSTEM SHALL 在两种入口一致处理图片、中文、列表、表格与转换失败，不得出现一个入口正常而另一个静默丢图或生成损坏文件。
- **AC-19** — WHEN 交付现有链路生成的 XLSX、PPTX、CSV 或图片，THE SYSTEM SHALL 保留原始文件类型和内容，并验证文件可被相应格式读取器打开；扩展名与实际格式不符、内容截断或无法读取时，须明确标记失败，不能把错误文本包装成成功文件下载。

### 2.5 性能与资源使用

- **AC-20** — WHILE 长正文或多个协作成员持续输出，THE SYSTEM SHALL 保持输入、滚动、终止和切换会话可用；正常运行时不得持续积压已经收到但尚未展示的正文，任务结束时不得丢失待展示尾部文本。
- **AC-21** — WHEN 打开或重连具有长执行历史的会话，THE SYSTEM SHALL 展示完整可用历史及最新状态，并保持页面可操作；切换或关闭会话后不得继续累积该页面的订阅、计时器或待处理输出。
- **AC-22** — WHILE Word/PDF 导出、图片处理或排版核验正在执行，THE SYSTEM SHALL 保持现有聊天请求、任务事件传输及其他会话响应，不得让一次耗时转换阻塞所有任务。
- **AC-23** — WHEN 用户重复预览或下载内容未变化的同一产物，THE SYSTEM SHALL 复用已经完成且仍有效的生成及核验结果，不额外调用模型，不反复执行完整格式转换或完整文件校验；内容、目标格式或相关生成条件变化后不得错误复用旧产物。
- **AC-24** — IF 文档、图片数量或并发导出超出可处理范围，THEN THE SYSTEM SHALL 给出明确的等待、限制或失败结果，保持其他任务可用；超时、取消或失败后不得遗留持续占用的转换进程、临时文件或后台核验任务。
- **AC-25** — THE SYSTEM SHALL 在固定的短会话、长正文、多成员并发、长历史及多页图文报告样例上记录修复前后的首段展示等待、增量展示延迟、页面交互、导出耗时和资源占用，并按设计阶段明确的性能预算验收；不得仅凭功能通过或主观感觉宣称性能达标。

### 2.6 Linux 与 Windows

- **AC-26** — WHERE 后端运行于 Linux 或 Windows，THE SYSTEM SHALL 以相同业务语义提供正文实时展示、任务恢复和已纳入范围的产物处理；不得把另一平台视为仅尽力兼容。
- **AC-27** — WHEN 任一平台处理含中文、空格或不同路径分隔符的工作区文件，THE SYSTEM SHALL 正确定位授权资源并保持文件名、内容和格式；不得依赖另一平台的绝对路径或通过路径转换绕过工作区隔离。
- **AC-28** — IF 当前平台缺少 PDF 转换程序或必要字体，THEN THE SYSTEM SHALL 在执行相关导出时明确报告依赖及配置方式，保持其他可用格式和任务正常工作；依赖就绪后同一组图文样例须能正常导出，不得把“提示缺依赖”算作该平台完整导出通过。
- **AC-29** — WHEN 任一平台的导出被取消、超时或失败，THE SYSTEM SHALL 终止本次导出拥有的子进程并清理其临时资源，不影响其他任务、用户已打开的 Office 程序或其他服务进程。

## 3. 边界情况

- 正文只含空格、换行，或一个模型响应同时携带正文与工具调用：保留文本原有顺序与格式，不丢失换行。
- 同一成员并行多次调用、内置研究成员、自定义成员和后台协作：各自输出不混合；未暴露正文的工具不伪造模型发言。
- 恢复记录已过期或缺失：沿用既有明确重置与可用历史恢复行为，不声称找回不存在的文本。
- 图片重复引用、文件名含空格、相对路径规范化、越界路径和不受支持的图片：成功与失败均可观察，不允许借图片访问任意文件。
- 沿用既有对远端图片的安全限制，不为兼容工作区图片而放宽 URL 清理规则。
- PDF 是正式修复和验收对象，不仅是 Word 变更的附带回归项；渲染依赖不可用、字体缺失、超时和写入失败均须有明确结果，不能交付伪 PDF。
- Word 与 PDF 分别检查实际文件和代表页面，不能只用转换函数返回成功推断图片、中文与分页正确；HTML 与 Markdown 分别核对资源引用。
- XLSX、PPTX、CSV 与图片沿用已有生成能力，分别核对格式、可读性和下载完整性；不因本次修复新增这些格式的通用转换器。
- 文件完整性和排版核验应随产物版本保留结果，不把每次预览、下载变成新的完整生成或核验；不能以性能优化为由跳过首次必要检查。
- 性能验证覆盖无 GPU 加速的浏览器环境；慢模型的上游等待与本系统收到文本后的转发、渲染延迟分别记录，避免把供应商等待误当作本地性能问题。
- 大图、多图、超长正文、多会话并发和慢消费者须有资源边界；具体预算、限额及测量方法在设计阶段确认。
- Linux/Windows 分别运行同一组功能与性能样例，记录系统和依赖版本、字体及路径；只能在单个平台运行的测试不能宣称证明双平台通过。
- 仅修改本机代码并验证；远端共享环境不执行破坏性验证，不覆盖用户给出的原会话及原报告。

## 4. 本期不包含

- 模型供应商首字延迟优化、模拟打字效果、任务调度与模型选择改造。
- Markdown 编辑器、Office 在线编辑、文档模板管理和任意文件格式转换。
- 长期记忆、扩大成员权限、未知外部副作用重放或恢复策略变更。
- 修复业务报告中的研究口径、事实或模型任意生成代码的正确性。

## 5. 实现文档

正文协议、展示方式、兼容策略、各格式的生成及核验链路、资源解析、具体排版方案，以及延迟、交互、内存、并发和转换耗时预算在 design.md 中评审；Linux/Windows 的依赖发现、文件路径和子进程生命周期采用明确的平台适配。
