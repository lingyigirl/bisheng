## 设计自评中已修正的遗漏

- 补充 assistant_text_v1 客户端能力与任务 text_protocol 门控，避免新 Worker 给旧页面发送无法识别的正文步骤。
- 补充共同文档结构/资源与目标成品两级缓存，Word/PDF 共用源时不重复解析资源，PDF 不无谓生成中间 DOCX。
- 补充模块责任表、旧另存为参数的可信任务定位和授权、Windows 缺 LibreOffice 的实际环境限制。
- 将结构核验与视觉核验分开，不将可打开、转换成功或文档存在当作完整排版验收。
- 核查当前 LibreOffice 配置时发现 conversation_export_service.py 明确记录 Word→LibreOffice 的表格、列表排版回归；设计尚未确认，已修正为统一资源/校验服务、Markdown/HTML PDF 使用 Chromium、原生 Office 转换使用 LibreOffice。两个后端分别探测依赖，不能把缺 LO 等同所有 PDF 不可用。

## 待执行而非已通过

Windows LibreOffice 依赖准备、Linux 运行环境核对、锁定 LangGraph 版本下后台正文传播、两平台实际转换/取消/性能预算均为实施阶段必做项。设计列出明确适配、降级和验收行为，不将它们写成现成能力。
