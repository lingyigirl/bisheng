# 工具、连接器可用性与成员侧栏性能验证

## 结论

可选目录代表当前用户获得使用权限，不代表所有服务已经配置完成或实时在线。真实目录共 124 个动作，102 个能初始化，22 个缺初始化参数。MCP 的构造是惰性的，因此另行执行了五组真实握手：四组成功，企业融资数据组返回上游 HTTP 403。不能将 102 个初始化成功解释成 102 个业务调用全部通过。

本轮修复自定义 API 的参数 JSON Schema 及异步 HTTP 错误处理，并针对侧栏压力测试结果优化搜索及列表复用。未填写或替换任何业务密钥、未放宽权限、未发送邮件或业务消息、未修改成员模板。

## 发现的问题与修复

1. `OpenApiTools.parse_args_schema()` 把字段写在 JSON Schema 根节点，`properties` 为空；模型可能看不到天气的经纬度或汇率基准等参数。改为写入 `properties` 并复制完整字段定义，保留数组、嵌套对象、枚举、默认值和 required 信息，避免修改原配置。
2. 异步自定义 API 使用文本请求包装器，HTTP 404 等错误页会直接返回为普通字符串。现在请求启用 HTTP 状态检查，返回不含 URL、认证参数和响应正文的 `ToolException`，交给已有任务工具错误处理。初轮探针只得到响应文本，不能据此判断业务成功；最终采用合法参数，并分别核对天气温度字段和 USD 基准汇率。
3. 侧栏搜索每次重新转换所有资源的搜索文本，并通过 key 重建全部当前复选框。现在目录更新时预计算搜索文本、缓存筛选结果，使用 ref 重置滚动位置，复用仍在列表中的复选框。

## 性能方法

在 Windows 当前 Chromium 浏览器中，用实际 React 18 客户端组件和样式运行独立 Vite 开发夹具；资源数据由 react-query 缓存预置，不写数据库。使用提交前的 `SubagentEditor` 作为旧版对照。目录总量包含技能、工具、连接器三类，分别测试 100、1,000、10,000 项。

每个搜索/切换场景执行 8 轮，共 40 次操作；同类勾选对照各执行 20 次。React Profiler 记录渲染提交，PerformanceObserver 记录事件及 50ms 以上长任务。表中 P95 为本轮组件渲染提交样本的分位数，**不是生产端到端延迟或服务容量 P95**。一次操作可能产生多个 React 提交。

| 场景 | 渲染 P95 | 最长渲染 | 资源区域 DOM 元素 | 复选框数 | 长任务 |
| --- | ---: | ---: | ---: | ---: | ---: |
| 新版 100 项，搜索/切换初测 | 3.3ms | 5.8ms | 158 | 35 | 0 |
| 新版 1,000 项，搜索/切换初测 | 3.6ms | 10.9ms | 186 | 41 | 0 |
| 新版 10,000 项，搜索/切换初测 | 3.9ms | 6.3ms | 186 | 41 | 0 |

| 最终新版 1,000 项，勾选复测 | 2.6ms | 4.0ms | 186 | 41 | 0 |

复选框数包含“只看已选”控件，资源行始终最多 40 项。千项目录同类勾选渲染 P95 下降约 92%，DOM 元素下降约 91%。各组搜索、分类切换未新增资源 API 请求。

慢 CPU 复测最长长任务从 114ms 降到 83ms，最长事件耗时从 120ms 降到 96ms；仍有长任务，不能宣称在所有低配终端上均无卡顿。4 倍减速是当前开发版浏览器的压力场景，未替代信创浏览器或 Linux/Windows 生产包硬件矩阵。CPU 减速已恢复为 1 倍，临时服务和夹具已清理。

## 回归与审查

- 后端：26 项通过，覆盖 API schema、HTTP 错误、授权校验、模型/工具独立绑定、子 Agent 配置。
- 前端：16 项通过，覆盖真实组件的搜索、分页、选择保留、只读查看及成员保存相关行为。
- 最终代码的客户端 lint、工作区类型检查、i18n 检查、Ruff、架构守卫及 diff 空白检查通过；API 健康检查 200。
- 工作区整体 lint 的平台侧 54 项既有错误不属于本轮改动；临时性能夹具已删除，不扩大抑制清单。
- 审查确认：没有新增全局状态或库、没有取消资源授权检查、搜索与分页不调用 HTTP、HTTP 失败信息不携带认证 URL。
- 正常应用中再次验证真实 87 个连接器目录及按“天气”搜索；最终截图 `final-app-smoke.png`。浏览器 CPU 已恢复，测试页关闭，没有保存成员草稿。

后端真实调用复测由加载最终源代码的独立进程执行，使用现有远端配置。没有为加载此修复再次中断用户正在访问的常驻 API；常驻进程需按正常重启流程加载修改，不能把测试通过表述为所有已启动进程均已热更新。
