# 需求来源与问题证据

日期：2026-10-19。

## 用户需求

用户反馈工作台任务模式的模型输出等待一段时间后集中显示，并指出协作会话中的主 Agent 在导出 Word 时反复调整。完成定位后，用户明确要求“修复”，随后补充“不只是word，pdf什么的也要做好处理”。修复范围为模型正文实时展示，以及报告的多格式生成、资源、排版和交付问题。

用户进一步要求“同时需要考虑性能问题”。性能作为独立验收范围，覆盖实时展示、长会话恢复、并发协作、图文转换与核验；不得通过每次下载重新生成或全量解析文件造成额外开销。设计阶段明确预算并记录修复前后对比，不把模型供应商的等待混入本地转发和渲染延迟。

用户已确认上述规格，并进一步明确“系统需要同时兼容linux和windows”。本次新增或调整的流式、文件与导出能力均须同时覆盖两个后端运行平台，包含中文及空格路径、工具和字体发现、转换取消与进程树清理；必须分别记录实测结果，不以模拟另一平台代替真实运行。

PDF 与 Word 同为正式修复对象；Markdown、HTML 纳入内容和资源引用一致性；已有代码执行或技能链路生成的 XLSX、PPTX、CSV、图片纳入格式、可读取性和下载完整性验证。各格式不适用的排版属性不强行套用。

## 需求边界

正文展示与思考展示分离；多个成员并发、重连、多轮继续、终止和受控恢复沿用既有安全约束。修复 Word/PDF 的工作区图片、中文字体、列表、表格、分页和失败反馈，并覆盖工具及“另存为”入口；其他现有产物格式按实际能力检查内容、资源与文件完整性。性能覆盖无 GPU 浏览器交互、长历史及多成员输出资源使用、转换对聊天的影响、重复使用已验证产物与超限清理。不承诺修正模型任意自编脚本，也不扩展为全套 Office 编辑器或任意格式转换器。
