> spec 只承载需求口径，才能长期稳定、可被反复引用。

**优先级**: P1
**所属版本**: v2.7.0
**依赖**: 无新增依赖（复用既有流程版本机制：`flow_version` 表、`/api/v1/workflow/versions*` 系列接口均已上线）

> **范围边界**（文章经验：写清「明确不做什么」比写「做什么」更能防 scope 膨胀）
> - **本次纳入**：
>   - 工作流编辑器（`/flow/:id`）「保存版本」下拉新增「版本对比」入口
>   - 对比弹窗：选择任意两个版本（旧版本 / 新版本），展示结构化差异
>   - 字段级变更列表：节点级（新增/删除/修改）+ 节点内部参数级差异（旧值→新值）
>   - 画布联动：点击变更条目 → 画布居中并高亮对应节点
>   - 后端只读版本对比查询接口（返回结构化差异）
> - **本次明确排除**：
>   - **assistant 编辑器**——该编辑器当前没有版本功能，无从比较（延后到 assistant 有版本管理后再议）
>   - **版本合并 / 基于差异的自动回滚**——切换版本已有，比较只读，不产生任何写操作
>   - **版本间运行指标对比**（访问量/成功率等）——属于 F046-agent-monitoring 监控领域，不在本特性
>   - **差异结果导出**（导出对比报告文件）——本期不做，如有需求另起 feature
>   - **客户端（H5/workspace）**——本特性只做 platform 管理端（:3001）

## 1. 用户故事

> 只保留**业务价值视角**的故事。
> 「为什么这么实现」（如：统一某状态管理、共用某 Service）属于**设计意图**，写进 design.md §3 / §4.3，不在 spec 重复。

作为 **流程开发者**，
我希望 **对比同一流程任意两个历史版本的具体差异**，
以便 **升级前后快速确认改了什么、出问题时定位是哪个改动引入的**。

作为 **流程开发者**，
我希望 **点击差异条目就能在画布上定位到对应节点**，
以便 **在节点拓扑相同、只有参数变化的场景下（如多版本迭代的智能体流程）快速看清变更发生在哪个节点的哪个字段**。

## 2. 验收标准

> **spec 的核心资产。** AC-ID 在本特性内唯一，格式 `AC-NN`。
> tasks.md 中的测试任务必须通过 `覆盖 AC: AC-NN` 追溯到此表。
> 错误码号在此表中**仅作为「可观测的对外行为」引用**（如「返错误码 12061」）；
> 错误码的定义、归属、编码规则是实现细节，写在 design.md §6 / 代码 `common/errcode/`，不在 spec 维护错误码详表。

本特性跨前后端并新增只读契约，验收标准采用 EARS 句型。

### 2.1 入口与版本选择

- **AC-01** — THE SYSTEM SHALL 在工作流编辑器（`/flow/:id`）的「保存版本」下拉中提供「版本对比」入口。
- **AC-02** — WHEN 用户点击「版本对比」, THE SYSTEM SHALL 打开对比弹窗，默认「旧版本」为按创建顺序早于当前选中版本的最近一个版本、「新版本」为当前选中版本（两者均可在全部非删除版本中重选）。
- **AC-03** — IF 用户选择的两个版本相同, THEN THE SYSTEM SHALL 禁用「开始对比」并提示选择两个不同的版本。

### 2.2 差异内容

- **AC-04** — WHEN 对比开始, THE SYSTEM SHALL 展示节点级差异清单：新增节点 / 删除节点 / 修改节点（节点业务数据任一字段变化即视为修改）。
- **AC-05** — 对修改节点, THE SYSTEM SHALL 展开到字段级：列出每个变化字段（含参数列表内按参数 key 对齐的单个参数差异），并展示旧值 → 新值。
- **AC-06** — THE SYSTEM SHALL 在差异展示中忽略节点画布坐标 / 视口（viewport）等纯布局字段的变化——布局字段不算业务差异（与既有「未保存修改」判定口径一致）。
- **AC-07** — IF 两个版本内容完全一致, THEN THE SYSTEM SHALL 提示「两个版本内容相同」。
- **AC-08** — 对长文本字段（代码、提示词等）的差异, THE SYSTEM SHALL 默认折叠展示（显示开头部分），用户可展开查看完整旧值/新值。

### 2.3 画布联动

- **AC-09** — WHEN 用户点击变更清单中的某条节点差异, THE SYSTEM SHALL 在画布上居中该节点并高亮标记。
- **AC-10** — WHILE 对比弹窗处于打开状态, THE SYSTEM SHALL 保持当前编辑器中的流程数据不被修改（对比是纯查看行为：只高亮定位，不加载任何版本的节点数据到编辑器，不产生未保存修改）。
- **AC-11** — WHEN 用户关闭对比弹窗, THE SYSTEM SHALL 清除画布高亮并恢复正常编辑状态。

### 2.4 后端对比接口（对外可观测行为）

- **AC-12** — THE SYSTEM SHALL 提供只读查询接口，支持按流程与任意两个版本查询结构化差异（节点增/删/改 + 字段级新旧值）。
- **AC-13** — IF 任一 version_id 不存在、已删除或不属于该 flow, THEN THE SYSTEM SHALL 返回错误码 10500（版本信息不存在）。
- **AC-14** — IF 请求用户对该流程无访问权限, THEN THE SYSTEM SHALL 拦截并返回无权限错误（与既有流程读取接口的权限口径一致，走统一权限入口，不新增权限分支）。

## 3. 边界情况

- 当对比过程中用户再次点击「版本对比」时，系统应重开弹窗并回到默认选择状态（无未完成的对比状态残留）。
- 当版本列表只剩一个版本时，「版本对比」入口不可用（无可比对象）。
- 当流程数据中包含历史版本遗留的空字段 / 缺失字段时，对比应将「缺失」与「空值」区分为删除/新增差异（具体兜底策略指向 design.md §5）。
- 当参数列表内参数顺序在两个版本间变化但内容未变时，系统不应产生虚假差异（按参数 key 对齐）。
- 对比接口是纯只读操作：不修改 `flow` / `flow_version` 任何数据，不做并发锁。
