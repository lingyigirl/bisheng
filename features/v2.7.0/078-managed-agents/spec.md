# Feature: 智能体纳管（078-managed-agents）

> **本文档定位 — 纯 What（需求口径，不随代码漂移）**
>
> spec 只回答 **做什么 / 验收标准 / 不做什么**。
> **所有 How（决策、数据流、字段、API、Service、前端、文件清单、性能指标）一律不写在这里。**
> How 的唯一真相在 [design.md](./design.md)（接手必读）与 [tasks.md](./tasks.md)（执行流水）。
>
> **前置步骤**：已完成 Spec Discovery（[discovery.md](./discovery.md)），15 个决策点已确认。

**关联 PRD**: 北京农商银行《智能体平台建设项目供应商征集公告》**（五）3**「智能体纳管：统一纳管本平台、其他低代码平台或高码开发的第三方智能体，实现统一接入、调度与运营；支持按场景/行业/标签分类展示。」
**优先级**: P0
**所属版本**: v2.7.0
**依赖**: F076-openapi-auth（服务账号/密钥/授权代管）、F077-scheduled-triggers（调度基座）、F047-agent-plaza（目录/筛选范式）、v2.5.0 F004-rebac-core（AuthorizationModel 与 PermissionService）

> **范围边界**
> - **本次纳入**：
>   - 纳管注册表：本平台应用投影 + 第三方智能体（低代码 / 高代码）登记、编辑、启停、删除、测试/健康检查。
>   - 第三方接入协议：OpenAI-compatible + 自定义 HTTP（非流式）。
>   - 统一调用：新增纳管智能体调用接口与调用权限位，复用 F076 密钥与身份；频控、防枚举、审计。
>   - 调度：复用 F077，支持 cron / 一次性 / 事件触发 / 立即运行；服务账号运行身份与失败闭环。
>   - 运营：健康检查、调用留痕、基础统计、失败通知。
>   - 分类：场景/行业结构化分类 + 标签；平台纳管控制台；客户端“第三方智能体”页签与筛选。
>   - 权限：新增纳管智能体资源类型；F076 授权代管支持该类型。
>   - 三语、审计、开关、错误码 121 段。
> - **本次明确排除**：
>   - A2A Agent Card 自动发现、A2A 任务生命周期、流式/SSE（Phase 2）。
>   - 具名低代码平台连接器（Coze/豆包/钉钉等）；MVP 只做通用 HTTP / OpenAI-compatible。
>   - 应用市场/交易/计费、评测集成、故障转移、自动扩缩容。
>   - 把第三方智能体写入 `flow` / `assistant` 表，或扩展 `FlowType`。
>   - 复用 `dsh_market`、MCP 工具注册表作为纳管入口。
>   - 代表用户调用、OAuth2 授权服务器。

## 1. 用户故事

**A. 平台管理员 / 应用负责人**
作为平台管理员或应用负责人，
我希望把本平台应用和第三方智能体登记到同一纳管目录，配置来源、协议、凭据、场景/行业/标签，
以便统一管理它们的上下线、权限、调用与调度，而不是在多个平台之间切换。

**B. 外部系统对接方**
作为行内外部系统的开发者，
我希望用平台的 API Key 和纳管智能体调用权限位调用已纳管的智能体，
以便在不了解其底层协议的情况下复用统一的鉴权、频控与审计。

**C. 运维 / 安全管理员**
作为运维或安全管理员，
我希望看到纳管智能体的健康状态、调用量、成功率、延迟和失败通知，并能在异常时停用，
以便在无人值守场景下快速发现和止损。

**D. 业务用户**
作为业务用户，
我希望在客户端按场景、行业、标签浏览已上线的智能体，
以便快速找到适合当前业务场景的智能体。

## 2. 验收标准

### 2.1 注册与纳管

- **AC-01** — WHEN 管理员选择本平台已存在的助手或工作流并执行“纳管本平台应用”, THE SYSTEM SHALL 创建一条来源为本平台的纳管记录，关联该应用的标识与类型，且**不复制**应用数据、不改动原应用。
- **AC-02** — WHEN 管理员登记第三方智能体, THE SYSTEM SHALL 接受来源为低代码或高代码、协议为 OpenAI-compatible 或自定义 HTTP，并记录接入地址、Agent Card/能力清单、版本、负责人，创建为草稿状态。
- **AC-03** — IF 注册缺少名称、来源、协议、外部接入地址或原生应用标识, THEN THE SYSTEM SHALL 拒绝并返回错误码 12102。
- **AC-04** — IF 来源与协议组合不合法（如本平台来源未关联本平台应用、外部来源未提供接入地址）, THEN THE SYSTEM SHALL 拒绝并返回错误码 12104。
- **AC-05** — IF 同一租户内名称或外部接入地址与既有纳管记录重复, THEN THE SYSTEM SHALL 拒绝并返回错误码 12103。
- **AC-06** — WHEN 管理员编辑纳管记录, THE SYSTEM SHALL 保存变更并重新校验来源、协议、接入地址、分类与凭据；响应不得回显凭据明文。
- **AC-07** — WHEN 管理员执行上线、下线或停用, THE SYSTEM SHALL 按“草稿 → 上线 → 下线 → 停用”的状态机流转；仅已上线状态可被调用或调度。
- **AC-08** — IF 纳管智能体仍被至少一个启用中的定时任务引用, THEN THE SYSTEM SHALL 拒绝删除并返回错误码 12110。
- **AC-09** — WHEN 管理员执行测试/健康检查, THE SYSTEM SHALL 返回本次检查结果与耗时；失败返回错误码 12108，且不把失败静默当作成功。
- **AC-10** — WHEN 原生应用被删除或下线, THE SYSTEM SHALL 在后续查看、调用或触发复检时将该纳管记录按不可用处理（fail-closed），不得回退到其他应用。
- **AC-11** — WHEN 管理员查询纳管列表, THE SYSTEM SHALL 支持按关键词、来源、协议、状态、场景、行业、标签筛选，且结果限定在当前租户。
- **AC-12** — IF 租户纳管数量超过配置上限, THEN THE SYSTEM SHALL 拒绝新增并返回错误码 12102。

### 2.2 第三方接入与适配

- **AC-13** — WHEN 调用 OpenAI-compatible 智能体, THE SYSTEM SHALL 按该协议的对话请求/响应形态映射输入输出；MVP 只要求非流式。
- **AC-14** — WHEN 调用自定义 HTTP 智能体, THE SYSTEM SHALL 按平台定义的 JSON 契约传递输入、会话标识与调用方信息，并解析输出与可选用量；允许配置固定请求头。
- **AC-15** — IF 接入地址不是 http/https、包含内嵌凭据，或其 DNS 解析结果包含私网/链路本地/元数据地址, THEN THE SYSTEM SHALL 拒绝注册或调用并返回错误码 12111。
- **AC-16** — IF 接入地址不在租户/部署的出站 allowlist 内, THEN THE SYSTEM SHALL 拒绝调用并返回错误码 12111。
- **AC-17** — WHEN 外部调用超过配置的超时, THE SYSTEM SHALL 终止调用并返回错误码 12106；WHEN 响应体超过配置上限, THE SYSTEM SHALL 终止读取并返回错误码 12113。
- **AC-18** — IF 上游返回 4xx/5xx, THEN THE SYSTEM SHALL 返回错误码 12106；IF 上游返回非法响应, THEN THE SYSTEM SHALL 返回错误码 12113；两种情况均只记录上游状态码与摘要，不向调用方透传上游正文。
- **AC-19** — WHEN 保存外部智能体凭据, THE SYSTEM SHALL 加密存储；任何列表、详情、日志、审计与异常均不得出现明文，详情只返回掩码。
- **AC-20** — WHEN 对第三方智能体执行健康检查, THE SYSTEM SHALL 使用配置的健康检查方式（健康 URL 或试调用）并记录结果、耗时与时间。

### 2.3 统一调用与权限

- **AC-21** — WHEN 外部调用方请求纳管智能体调用接口, THE SYSTEM SHALL 要求 F076 密钥鉴权并校验纳管智能体调用权限位；缺权限位返回 11807。
- **AC-22** — WHEN 调用已纳管智能体, THE SYSTEM SHALL 要求该智能体对调用方可见，且密钥所属服务账号的专用身份对其持有运行权限；不满足时按防枚举口径返回 404/11809。该智能体处于下线、停用或草稿状态时按 AC-29 处理。
- **AC-23** — WHEN 提交调用请求, THE SYSTEM SHALL 只接受调用目标、输入与可选会话标识三个白名单字段；出现白名单外字段返回 12114。
- **AC-24** — WHEN 调用成功, THE SYSTEM SHALL 返回运行标识、输出与可选用量信息；不得返回内部异常堆栈或上游原始错误正文。
- **AC-25** — WHEN 调用方传入会话标识, THE SYSTEM SHALL 将其透传给对应协议的接入通道；平台不因此建立或持久化对话历史。
- **AC-26** — IF 同一租户/智能体的调用频率超过配置上限, THEN THE SYSTEM SHALL 返回 HTTP 429 与错误码 12112。
- **AC-27** — WHEN 调用完成（成功或失败）, THE SYSTEM SHALL 写入一条纳管智能体调用留痕（调用方、智能体、状态、耗时、错误码），**不记录输入正文与凭据**。
- **AC-28** — IF 调用方传入其他租户的智能体标识, THEN THE SYSTEM SHALL 按不存在处理并返回 404/11809，不泄露该智能体是否存在。
- **AC-29** — IF 智能体处于下线、停用或草稿状态, THEN THE SYSTEM SHALL 拒绝调用并返回 12105。
- **AC-30** — WHEN 多个调用并发到达, THE SYSTEM SHALL 在频控允许范围内并发处理，不施加定时任务式的单任务互斥。

### 2.4 调度与运行

- **AC-31** — WHEN 管理员为纳管智能体创建定时任务, THE SYSTEM SHALL 接受纳管智能体作为目标类型，并在任务表单中只展示已上线的纳管智能体。
- **AC-32** — WHEN 创建指向纳管智能体的定时任务, THE SYSTEM SHALL 校验智能体存在且上线、服务账号所有者对其持有运行权限、预设输入符合 Agent Card 声明的输入要求；含文件类输入项时拒绝并返回 11914。
- **AC-33** — WHEN 计划轮次、事件触发或立即运行触发纳管智能体, THE SYSTEM SHALL 执行与 F077 相同的触发前复检（智能体状态、服务账号、所有者与运行权限），失败一律拒绝且不得回退身份。
- **AC-34** — WHEN 计划轮次触发纳管智能体, THE SYSTEM SHALL 通过对应协议的接入通道执行并回写终态；失败计数、连续失败自动停用、首次失败通知与 F077 口径一致。
- **AC-35** — WHEN 事件触发指向纳管智能体任务, THE SYSTEM SHALL 复用 F077 的防重放、频控、互斥与错误码语义。
- **AC-36** — WHEN 管理员对纳管智能体任务执行“立即运行”, THE SYSTEM SHALL 复用 F077 的同步触发语义与 11909/11910 分工。
- **AC-37** — WHEN 定时任务指向原生应用投影, THE SYSTEM SHALL 委派到该原生应用的既有运行链路，运行身份与知识可见性口径不变。
- **AC-38** — IF 纳管智能体在任务创建后下线/停用/删除, THEN THE SYSTEM SHALL 按 F077 对客口径处理：周期轮次跳过、一次性等待、事件与立即运行拒绝。
- **AC-39** — WHEN 删除纳管智能体, THE SYSTEM SHALL 与 2.1 AC-08 一致地检查启用中的定时任务；删除定时任务不影响智能体本身。
- **AC-40** — WHEN 管理员使用自然语言生成定时任务草稿, THE SYSTEM SHALL 在可用目标中包含已纳管智能体，并按 AC-32 的校验口径生成草稿；草稿不落库，须经人工确认。

### 2.5 运营与健康

- **AC-41** — WHEN 健康检查周期到达, THE SYSTEM SHALL 在租户上下文中检查已上线/已登记智能体，更新健康状态与最近检查时间；跨租户枚举不得漏租户或串租户。
- **AC-42** — WHEN 连续健康检查失败达到配置阈值, THE SYSTEM SHALL 标记为不健康并按配置决定是否自动下线；同时发送失败通知。
- **AC-43** — WHEN 调用或定时运行完成, THE SYSTEM SHALL 写入调用留痕（智能体、调用方、服务账号、状态、耗时、错误码、运行标识）；不记录输入正文与凭据。
- **AC-44** — WHEN 管理员查询运营统计, THE SYSTEM SHALL 返回指定时间窗内的调用量、成功率、平均延迟；结果按权限与租户收窄。
- **AC-45** — WHEN 纳管智能体的定时运行首次失败或达到连续失败阈值, THE SYSTEM SHALL 复用 F077 的通知/自动停用闭环，不重复造通知通道。
- **AC-46** — WHEN 管理员执行健康检查或启停, THE SYSTEM SHALL 写入可见审计动作。
- **AC-47** — WHEN 调用留痕或统计被读取, THE SYSTEM SHALL 不返回输入正文、凭据或上游原始错误正文。

### 2.6 分类与展示

- **AC-48** — WHEN 管理员维护分类法, THE SYSTEM SHALL 支持场景/行业两类、租户内唯一分类标识、三语名称、排序与启用位。
- **AC-49** — WHEN 创建或编辑纳管智能体并指定场景/行业, THE SYSTEM SHALL 校验分类项存在且启用；非法返回 12109。
- **AC-50** — WHEN 管理员为纳管智能体关联标签, THE SYSTEM SHALL 复用既有标签体系；列表与客户端可按标签筛选。
- **AC-51** — WHEN 管理员查看纳管控制台, THE SYSTEM SHALL 展示来源、协议、状态、健康、场景、行业、标签、最近调用摘要。
- **AC-52** — WHEN 业务用户打开客户端“第三方智能体”页签, THE SYSTEM SHALL 只展示已上线且当前用户有查看权限的纳管智能体，并支持按场景/行业/标签筛选。
- **AC-53** — WHEN 本平台应用被投影纳管, THE SYSTEM SHALL 在客户端同一页签中以“本平台”来源标识展示，与第三方智能体使用同一套分类筛选。
- **AC-54** — IF 纳管智能体下线、停用或用户失去查看权限, THEN THE SYSTEM SHALL 从客户端目录隐藏，不泄露其存在。
- **AC-55** — WHEN 展示场景/行业名称, THE SYSTEM SHALL 按当前语言返回三语名称；分类标识保持稳定，不随语言变化。

### 2.7 审计、安全与租户

- **AC-56** — WHEN 管理员执行注册、编辑、删除、启停、健康检查, THE SYSTEM SHALL 写入纳管管理审计动作，含操作者、时间、对象与结果。
- **AC-57** — WHEN 新增或修改审计动作, THE SYSTEM SHALL 保持后端白名单、命名空间映射与前端日志页白名单一致（锁步测试通过）。
- **AC-58** — WHEN 存储或读取凭据, THE SYSTEM SHALL 加密存储、掩码返回、禁止写入日志/审计/异常；不得在 API 响应中出现明文。
- **AC-59** — WHEN 配置或调用外部接入地址, THE SYSTEM SHALL 执行 2.2 的 SSRF 与 allowlist 校验，默认拒绝私网与元数据地址。
- **AC-60** — WHEN 读取/调用/统计纳管对象, THE SYSTEM SHALL 限定当前租户；跨租户不可见、不可调用、不可统计。
- **AC-61** — WHEN 创建、查看、编辑、删除或调用纳管智能体, THE SYSTEM SHALL 通过平台统一权限判定入口完成授权与校验（创建时授权，查看/编辑/删除/调用前校验），不得直读角色表或绕过权限单入口。
- **AC-62** — WHEN 管理员在服务账号授权代管中授权, THE SYSTEM SHALL 支持纳管智能体资源类型与 viewer/editor/manager 档位；调用要求 editor 档对应的运行权限。

### 2.8 开关与兼容

- **AC-63** — WHERE 纳管功能开关关闭, THE SYSTEM SHALL 隐藏纳管入口、拒绝纳管相关 API（404），且既有应用管理、`/api/v2` 与 F077 调度行为不变。
- **AC-64** — WHEN 开启纳管, THE SYSTEM SHALL 不修改既有原生应用数据、不改变既有 `/api/v2` 端点行为。
- **AC-65** — WHEN 部署新版本, THE SYSTEM SHALL 不要求对既有表做数据迁移；回滚只需移除新增对象，不得影响既有数据。
- **AC-66** — WHEN 增加纳管智能体调用权限位, THE SYSTEM SHALL 保持权限位注册表、三语文案、接入指南与验收表口径一致（总数由 9 增至 10），锁步测试通过。

### 2.9 界面与三语

- **AC-67** — WHEN 有权限的管理员进入平台, THE SYSTEM SHALL 在构建区提供“智能体纳管”入口；无权限或开关关闭时不显示。
- **AC-68** — WHEN 业务用户进入客户端应用中心/广场, THE SYSTEM SHALL 提供“第三方智能体”页签，且不影响既有原生应用页签。
- **AC-69** — WHEN 新增界面文案, THE SYSTEM SHALL 同时提供 zh-Hans / en-US / ja 三语，不得硬编码中文。
- **AC-70** — WHEN 前端质量门禁执行, THE SYSTEM SHALL 通过 lint、typecheck 与 i18n parity；不新增 UI/状态库，不使用 `backdrop-filter`。

## 3. 边界情况

- 外部智能体在调用过程中超时、断连或返回非 JSON：按 12106/12113 处理，不重试不可重试的请求；是否重试由适配器配置决定，MVP 默认不自动重试。
- 外部智能体返回超大响应：超过配置上限即终止，不把内容读入内存无界增长。
- 原生应用被删除/下线：纳管记录保留但不可用；客户端隐藏；定时任务按 F077 口径跳过/拒绝。
- 纳管智能体被删除但仍有历史调用留痕：留痕保留，不级联删除。
- 分类项被停用：既有记录保留原分类标识，展示回退为标识或“未分类”，筛选不再返回；不静默改绑。
- 同一接入地址在同一租户内不得被多条纳管记录重复登记（与 AC-05 一致）；如需同地址的不同版本，使用同一条记录的版本字段，健康/统计按记录隔离。
- 租户被停用：其纳管智能体不可调用；沿用 F076 租户停用口径。
- 服务账号被停用/提权/失去运行权限：调用与调度按 F076/F077 既有 fail-closed 口径拒绝。
- 分类法三语名称缺失：回退到分类标识，不阻断保存（由管理员补齐）。
- 外部智能体返回的 `usage` 字段缺失：调用成功，用量字段留空。

## 5. 待澄清
