# Feature: 评测支持表单型工作流（form_input 智能体的版本对比评测）

> **本文档定位 — 纯 What（需求口径，不随代码漂移）**
>
> spec 只回答 **做什么 / 验收标准 / 不做什么**。
> **所有 How（决策、数据流、字段、API、Service、前端、文件清单、性能指标）一律不写在这里。**
> How 的唯一真相在 [design.md](./design.md)（接手必读）与 [tasks.md](./tasks.md)（执行流水）。

**关联 PRD**: 用户需求（2026-09-05）：流水/征信/财务等表单型智能体也要支持评测与版本对比——当前评测执行链仅支持问答型（dialog_input）工作流（"Only Q&A type workflows are currently supported"）。追加需求（2026-09-06）：下载的结果文件要能展示具体测试案例（表单输入值）及测试值（见 §3 边界情况）。
**优先级**: P0
**所属版本**: v2.7.0
**依赖**: F053-agent-version-eval-compare（对比组机制已上线；本 Feature 让表单型智能体可评测，使对比评测对其可用）

> **范围边界**
> - **本次纳入**：
>   - 评测执行链支持**表单型（form_input）工作流**：执行进入输入节点后，按评测数据集的表单值提交并继续执行，采集输出作为答案
>   - 评测数据集格式扩展：新增可选 `form_values` 列（JSON，按**表单项 label** 引用；文件值 = MinIO 对象路径，执行时生成预签名 URL）
>   - 文本项与文件项（多文件数组）均支持；缺省可选文本项填空串
>   - 单题执行失败不中断整份评测（该题标记失败原因，其余继续）
> - **本次明确排除**：
>   - 助手 / 灵思智能体的表单型评测（其执行链与工作流不同，另起 feature）
>   - 评测数据集的文件上传管理界面（文件仍走既有上传方式，数据集中写对象路径）
>   - 表单项 label 重复的自动消歧（创建校验报错，要求数据集作者修正）
>   - 图片/音频特殊输入类型（文件项按既有 file 类型统一处理，不新增专属交互）

---

## 1. 用户故事

作为 **应用负责人**，
我希望 **用同一份评测数据集对流水/征信/财务等表单型智能体的不同版本进行评测**，
以便 **像问答型智能体一样量化比较版本准确性的变化**。

作为 **评测数据集作者**，
我希望 **在 CSV 里用表单项的 label 填写表单值（文件写对象路径）**，
以便 **不必关心运行时随机生成的字段 key，数据集长期有效**。

作为 **应用负责人**，
我希望 **个别题目因数据问题（如文件缺失、label 不匹配）失败时不中断整份评测**，
以便 **快速定位坏题目而不浪费整轮评测**。

## 2. 验收标准

### 2.1 数据集格式与校验

- **AC-01** — WHEN 评测数据集包含 `form_values` 列, THE SYSTEM SHALL 按 JSON 解析该列；IF 某行 JSON 无效, THEN 创建评测时返回参数错误并指明行号。
- **AC-02** — `form_values` THE SYSTEM SHALL 按表单项 label 引用（如 `"银行流水文件（PDF/Excel/图片，可多份）": ["tmp-dir/bankflow_2026.csv"]`）；文件值接受字符串（自动按单文件数组处理）或数组。
- **AC-03** — WHEN 评测执行, THE SYSTEM SHALL 将表单值中的文件路径转换为预签名 URL 后提交；IF 对象不存在, THEN 该题执行失败并记录失败原因。
- **AC-04** — IF `form_values` 引用的 label 在运行时表单中不存在或重复, THEN 该题执行失败并记录原因（label 不匹配/重复）。

### 2.2 执行

- **AC-05** — WHEN 工作流执行进入表单输入状态, THE SYSTEM SHALL 按 `form_values` 提交全部表单项（文本项填对应值或空串；文件项填预签名 URL 列表），继续执行并采集输出作为答案。
- **AC-06** — WHEN 工作流为问答型（dialog_input）, THE SYSTEM SHALL 执行路径与现在完全一致（无 `form_values` 时行为零变化）。
- **AC-07** — IF 某题执行失败, THEN 该题在评测结果中标记失败原因，其余题目继续执行。
- **AC-08** — IF 整份评测所有题目都失败, THEN 评测任务状态为失败并记录原因摘要。

### 2.3 结果与评分

- **AC-09** — 执行失败的题目 THE SYSTEM SHALL 不参与评分聚合（按 N/A 口径，与既有评测一致）。
- **AC-10** — `ground_truth` 列 THE SYSTEM SHALL 保持必填（评分基准）；`question` 列对表单型评测可选（缺省为空字符串，不参与逐题匹配）。

### 2.4 版本对比联动

- **AC-11** — WHEN 对表单型智能体创建双版本对比评测（F053 流程）, THE SYSTEM SHALL 与单版本评测一致可用：同一数据集跑两个版本，对比视图正常展示。

### 2.5 权限与租户隔离

- **AC-12** — 评测与对比接口权限口径与既有评测一致（仅登录用户自己的评测）。
- **AC-13** — WHERE 多租户开启, THE SYSTEM SHALL 仅返回当前租户的评测与对比数据。

## 3. 边界情况

- 文件值同时支持完整 URL（含 http 前缀）与对象路径（无协议前缀按对象路径处理，生成预签名 URL）；既有对象路径不含 bucket 时按默认 bucket 处理。
- 表单型行在结果 CSV 的 `question` 列填**可读摘要**（`label: 值; label: 值`，列表值逗号连接，空值跳过）——仅用于展示，让下载的结果文件能看出每行对应哪个测试案例；**评分输入仍为原始空 question**（不改评分行为）。既有列结构不变，问答型行不受影响。（2026-09-06 用户确认，取代原先「表单值不写入结果 CSV」的锁定）
- 表单型评测的答案采集口径与问答型一致：取执行输出事件文本为 answer。
- 多文件项顺序保持数据集给定顺序。
- 数据集行中 `form_values` 为空（空串/空对象）且工作流为表单型 → 该题失败（必填项缺值），原因标注。
