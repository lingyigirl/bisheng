## 原因与实现

旧日志同一任务 `4cc2ca2157e84aa0869cda76e69ccf30` 显示工作区先逐文件上传 54 个文件，随后 Skills 物化路径再次上传同一批文件；parse_results 又独立遍历并下载输入，之后 copy-out 再扫描和收集。84 秒不能全部归因于沙箱冷启动，重复的小文件网络请求是明确的本地实现瓶颈。

- workspace sync 和 Skills copy-in 复用批量上传 helper，每批至多 32 个文件、8 MiB；已显式声明的大文件仍可单独上传，不改变 required_files 门槛。
- 成功上传后记录 **路径＋内容摘要**，相同内容的不同路径都必须存在，工作区与 Skills 不再重复传。所有批次成功后才确认缓存，部分失败不误记成功；Skills 批次失败恢复待暂存状态，下次重试。
- 标准 run 的结果解析不再额外同步整个文件树，copy-out 一次读取变更文件，同时写入持久工作区和本地文件，不下载未变输入。回传的本地文件记录同步指纹，下一次无需反向重传。
- 每次创建新沙箱都清空上传摘要，防止关闭/重建后沿用旧确认而漏传。legacy run_code_with_one_sandbox 保留结果解析内的本地同步。沙箱失效仅在执行前允许重建；执行或结果收集失败仍禁止自动重跑用户代码。
- 新增 prepare / execute / collect 分段耗时日志，不记录代码、文件内容或凭据。
