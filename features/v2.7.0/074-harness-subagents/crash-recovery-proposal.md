# 执行中崩溃自动接管：规格与设计补充草案

日期：2026-10-14。状态：用户已在本会话明确回复“确认”，规格与设计获准实施。关联 spec.md、design.md、crash-resume-validation.md。
本草案扩展此前明确未实现的执行中崩溃接管；不改变长期记忆归属。只在当前本地分支开发，不推送远端。

## 1. 可交付范围

支持 API/Worker 重启、Worker 被强杀后，在 Redis、数据库及持久工作区可用的条件下，自动接管符合安全条件的 Harness 任务。保持原 session_version_id/thread_id、成员配置、任务文件和历史，不创建替代任务。

“任意崩溃”不能无条件保证：任意外部工具若已发出写入、却来不及保存结果，平台无法凭 checkpoint 判断远端是否已执行。未知结果不得自动重放，必须记录明确阻断原因。模型推理可重算；工具必须依据平台维护的恢复策略判定，不能相信模型自报“只读”。

首期仅对启用新恢复协议的新任务保证恢复；旧任务缺少租约与工具日志，沿用显式失败，不能推测历史副作用。现有人工等待点恢复和用户终止保持原语义。

## 2. 验收标准

| 编号 | 验收行为 |
|---|---|
| CR-01 | 主模型或子模型生成期间强杀 Worker，待租约过期后由新 Worker 自动接续原 checkpoint 并完成，不需要提交新问题或人工回答 |
| CR-02 | 两个 Worker 同时发现孤儿任务，只有一个取得执行租约；重复队列消息不能启动第二个执行实例 |
| CR-03 | 原 Worker 暂停超过租约期限后恢复，其过期代次不能追加 checkpoint、事件、工具结果或覆盖任务终态；不能启动新的工具调用 |
| CR-04 | 对平台批准可重复执行的只读调用，未完成时允许重试；对已持久化结果的调用使用原结果，不重复执行 |
| CR-05 | 任意未知副作用调用，包括任意 Python/E2B 代码和未声明策略的 API/MCP，在执行中或结果落盘前崩溃时阻断自动重放，给出可诊断原因 |
| CR-06 | 工作区从持久存储重建；不能恢复的沙箱进程、未同步文件或失效资源必须明确阻断，不能静默丢失状态继续 |
| CR-07 | 已终止/完成/失败任务不复活；人工等待任务不被自动提交答案，恢复途中用户终止仍生效 |
| CR-08 | 主子调用继承可信租户、用户及配置快照，接管前再次校验资源权限；另一租户不能读取或接管任务 |
| CR-09 | 页面显示恢复进度与阻断原因；原历史可回放，不能把重新计算的流式片段直接重复追加成原答案 |
| CR-10 | 恢复次数有上限（默认 3 次）和退避；缺 checkpoint、恢复元数据丢失、依赖不可用时不无限循环，不回退成全新任务 |
| CR-11 | 启动检查与运行期定时检查都可发现孤儿任务，包括新 Worker 在旧心跳过期前启动的场景；无其他 Worker 时应明确等待服务恢复 |
| CR-12 | 实际故障注入覆盖主模型、子 Agent、可重试工具、未知副作用工具、双 Worker 抢占、旧进程复活、用户终止及多租户；Mock 结果与真实服务结果分列 |

## 3. 实现方案

### 3.1 租约与接管

新增领域 RecoveryService/Repository，复用现有队列和 Redis checkpoint，不引入新调度系统。任务记录保存协议版本、执行代次、恢复次数和最近原因；新增字段通过 JsonType/可移植列实现，DDL 验证 MySQL 与 DM8。

Redis Lua 原子领取/续期/释放带随机 token 的租约，释放必须比较 token；恢复时增加单调执行代次。Worker 启动及运行期定时扫描仅将符合条件的任务列为候选，成功领取租约后再次核对 DB 终态和代次再执行。队列中的任务携带恢复类型和代次；消费时再次核验，避免扫描、入队、消费之间的状态竞争。数据库状态更新通过 Repository 条件更新，不能用整行旧对象回写覆盖新状态。

不能仅依赖心跳判死：执行前检查租约，checkpoint/pending-writes/事件/工具日志的写入必须原子验证 token；所有完成/失败写入同样受代次约束。续期失败取消当前图并拒绝后续写入。已送往外部服务的请求无法撤回，因此未知副作用日志必须阻止新一代重放。

Redis 中恢复租约、工具日志、checkpoint 的缺失不解释为“从未执行”。元数据保留期至少覆盖 checkpoint；Redis 丢失不在本期自动恢复保证内。

### 3.2 恢复执行与工具结果

新增独立 crash-recover 入口，不调用 Command(resume=虚构答案)，也不复用新任务 async_run。重建原图、恢复可信租户和原 thread_id，确认 checkpoint 有后续节点且无人工 interrupt 后，以空输入接续图。

新增主子图共用的工具恢复 middleware，按 task/thread + checkpoint namespace + tool_call_id 记录 started/result/unknown。执行外部调用前先持久化 started，失败则不调用；调用完成后先持久化结果再返回图。日志包含参数摘要和策略版本，拒绝 ID 相同但参数不同的结果复用。

只读策略采用代码维护的明确允许列表和测试，不根据工具名字包含 search/read 或用户描述猜测。内置读文件、列目录等在工作区隔离条件下可重复；edit_file、任意代码执行、未知 API/MCP 默认不可重放。主 task 委派作为子图控制操作处理，必须检查对应子图的未决调用日志，不能将 task 本身标成安全就绕过子工具。

新 E2B 沙箱不等于旧沙箱进程恢复。本期只在确认无未决沙箱调用、工作区状态已持久化时重新装配工具；遇到未知执行结果或依赖原内存状态的任务明确阻断。

### 3.3 事件和页面

事件追加携带恢复代次，补充恢复开始/完成/阻断状态。新代次接管前将旧的未完成调用投影视为被中断，保留已完成步骤；同一节点重新计算的输出按调用身份及代次替换未完成投影，不能简单拼接两次文本。复用现有快照/游标、成员卡片和三语文案，不新增状态管理库。

## 4. 修改范围及执行顺序

1. Recovery 配置/状态/Repository、单链迁移、MySQL/DM8 测试。
2. 租约 Lua、代次隔离及多 Worker 竞争测试，接入现有 Worker 启动与周期扫描。
3. 主子工具恢复日志及策略，覆盖完成结果复用与未知副作用阻断。
4. task_exec 独立恢复入口、checkpoint 写入隔离、文件重建及权限重验。
5. 事件协议与 Client 恢复展示、历史投影去重，三语同步。
6. 实际故障注入、回归、更新规格/设计/任务和验收报告。只在证据覆盖的条件下标支持。

主要触及 worker.py、domain/task_exec.py、checkpointer.py、state_message_manager/event_replay、agent_factory/configured_subagents，以及 Client Websocket/执行卡片；新增 RecoveryService、Repository、middleware 与专用测试。不得在 Endpoint 中新增 ORM 查询或在 legacy DAO 中增加入口。

## 5. 自查及风险

依据 constitution C1–C7 和 sdd-review 的规格/设计检查框架进行了初步自查，未运行独立评审 Agent。

- 已明确新旧任务兼容、最大重试、终态优先、权限及租户恢复、Redis 元数据丢失边界。
- 已明确 checkpoint 有记录并不代表工具安全重放；不能宣称全局 exactly-once。
- 实现前需锁定本项目 LangGraph 子图恢复语义，通过真实图测试验证中间 checkpoint 的 namespace、pending writes 和调用身份；不能按假定实现。
- 跨 Redis 与 DB 的状态不具有统一事务，需要代次检查和定期对账；所有终态写入路径都必须覆盖，漏一条就可能复活旧任务。
- 这不是单文件修复，会改变此前“孤儿任务直接失败”的已确认契约。规格与设计确认后才进入业务实现。
