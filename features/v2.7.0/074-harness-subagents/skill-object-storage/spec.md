# Feature: Skill 共享持久存储与可重建缓存

**关联 PRD**：[已确认的需求发现](../skill-object-storage-discovery.md)；用户要求参照官方新版 Skill 存储方案改进当前实现，2026-10-18 确认继续。
**优先级**：P1
**所属版本**：v2.7.0
**依赖**：F035 Skill 管理与任务加载；F074 成员 Skill 选择、校验与恢复；已有共享存储和权限能力。
**归属**：F035 既有 Skill 存储契约的延续改进；F074 仅适配消费方，不取得 Skill 对象所有权。见[版本契约](../../release-contract.md)。
**状态**：2026-10-18 用户确认规格；不代表已实现。

## 1. 用户故事

作为管理员，我希望一次导入的 Skill 可以被不同后端节点读取和维护，避免数据库有记录但换台机器就无法执行。

作为任务用户，我希望主 Agent 和配置了 Skill 的成员都能读取完整文件包，并在节点切换或缓存丢失后继续按既有任务恢复规则工作。

作为运维人员，我希望可预览、可核验地迁移旧文件，并明确知道哪些文件缺失、哪些操作失败，而不是升级后悄悄丢失内容。

## 2. 验收标准

### 2.1 管理与跨节点使用

- **AC-01** — WHEN 管理员成功创建或导入 Skill，THE SYSTEM SHALL 使文件包独立于接收请求的机器持久可用；仅连接相同数据库而未取得原机器文件的另一授权节点，也能读取该 Skill。
- **AC-02** — WHEN 管理员查看详情、查看文件、导出或更新已有 Skill，THE SYSTEM SHALL 对完整的同一已发布版本操作，并保留正文、中文路径文件及二进制附件的正确内容。
- **AC-03** — WHEN 节点没有对应本地缓存或缓存被删除，THE SYSTEM SHALL 能够重新取得已发布文件包并完成查看和任务加载，不要求手工同步机器目录。
- **AC-04** — WHEN 主 Agent 或成员加载本轮已选且启用的 Skill，THE SYSTEM SHALL 向对应执行上下文提供完整文件包；未选、停用或无权访问的 Skill 不得因存储改造变得可见。
- **AC-05** — WHEN 用户刷新已有 Skill 管理页面或使用既有创建、导入、编辑、导出、删除和启停入口，THE SYSTEM SHALL 保持这些入口可用及原有授权边界。

### 2.2 一致性、异常与恢复

- **AC-06** — WHEN 两个节点并发发布同一 Skill 的不同内容，THE SYSTEM SHALL 使最终可读的内容与其已发布版本一致，不得出现元数据指向另一份内容或半个文件包。
- **AC-07** — IF 发布文件包失败，THEN THE SYSTEM SHALL 返回失败且保留此前可用版本，不得将不完整内容报告为发布成功。
- **AC-08** — IF 所需文件包不存在或内容校验不通过且无法重新取得正确内容，THEN THE SYSTEM SHALL 明确报告所选 Skill 不可用，不得把空正文或未装载该 Skill 的执行冒充成功；其他未选择该 Skill 的任务不因此被阻断。
- **AC-09** — WHEN 存储访问暂时失败后重新发起读取或导入，THE SYSTEM SHALL 允许在服务恢复后成功完成，不得因一次失败留下永久不可用的本地状态。
- **AC-10** — WHEN 相同节点并发首次读取相同版本，THE SYSTEM SHALL 提供完整且一致的文件内容；不得向任一请求暴露写入中的缓存或错误版本。
- **AC-11** — WHEN 同一任务在新节点恢复且所选 Skill 内容未变，THE SYSTEM SHALL 保持既有恢复能力，不得仅因持久存放位置或缓存变化将其判断为内容变化。
- **AC-12** — IF 所选 Skill 在恢复前发生内容变化、停用、删除或权限撤销，THEN THE SYSTEM SHALL 沿用既有恢复校验明确阻断不安全续跑，不得默默替换为新内容或旧缓存绕过撤销。
- **AC-13** — WHEN 授权管理员删除 Skill，THE SYSTEM SHALL 使后续管理读取和新任务选择不可用；另一节点已有缓存不得使被删除 Skill 继续通过授权与可用性校验。

### 2.3 迁移与运行维护

- **AC-14** — WHEN 运维预览旧文件迁移，THE SYSTEM SHALL 列出待迁移、已完成、缺失和失败的记录及原因，不修改既有文件或发布状态。
- **AC-15** — WHEN 运维显式执行旧文件迁移，THE SYSTEM SHALL 仅在目标文件包可读取且内容核验一致后完成该记录的迁移，并保留旧文件及迁移前记录以供核对和恢复。
- **AC-16** — WHEN 运维重新执行中断或已完成的迁移，THE SYSTEM SHALL 不重复改变已正确完成的记录，不覆盖迁移期间管理员发布的新版本，并报告仍未完成的项目。
- **AC-17** — IF 旧记录对应的源文件缺失，THEN THE SYSTEM SHALL 保留记录并报告缺失，不创建占位 Skill；获得原文件并显式迁移或重新导入后应可恢复使用。
- **AC-18** — WHEN 发布本次升级，THE SYSTEM SHALL 提供可操作的升级、迁移和回退说明，区分结构更新与文件数据搬迁，并说明混用不兼容节点版本的限制；不得以直接回退代码代替必要的文件恢复。

### 2.4 隔离与资源边界

- **AC-19** — WHERE 多租户启用，THE SYSTEM SHALL 使不同租户的同名 Skill 文件、缓存和迁移互相隔离，禁止通过伪造文件路径、对象引用或缓存命中读取其他租户的内容。
- **AC-20** — IF 上传或存储中的文件包含越界路径、损坏压缩数据或超过允许资源上限，THEN THE SYSTEM SHALL 明确拒绝，不写出 Skill 管理目录边界，不发布不完整文件包。
- **AC-21** — THE SYSTEM SHALL 提供本地缓存和未引用历史版本的运行维护说明，使清理可识别范围且不删除仍在使用的唯一持久副本；本地缓存不承担唯一持久存储职责。
- **AC-22** — THE SYSTEM SHALL 在日志及迁移报告中提供足以定位失败记录的信息，同时不输出存储凭据、登录凭据或完整 Skill 正文。

## 3. 边界情况

- “本机只缓存”仍允许内容为读取和执行临时落盘，不承诺后端绝不接触或保存任何内容。
- 重新打包但文件内容完全相同，应保持内容未变化的判断；更改正文或附件应视为内容变化。
- 正文存在而附件损坏、并发更新与迁移交错、只上传成功但发布失败，均需给出一致且可重试的结果，不能提前销毁此前版本。
- 存量文件只能从实际文件来源恢复，不能由名称、描述或数据库路径推导出正文。
- 删除期间已在执行的任务，沿用现有终止和恢复规则；本期不承诺撤回已经读入模型上下文的内容。

## 4. 范围边界

本期覆盖自定义 Skill 的共享持久存储、缓存、管理、任务加载、成员恢复校验及旧数据迁移。沿用既有模型、工具、权限、租户和 Skill 文件格式。

本期不包含长期记忆、Skill 市场、跨租户分享、新增内置 Skill 包、替换 Agent 框架、任意历史任务协议升级或整合官方其他功能。缓存淘汰和历史对象清理由运维流程管理，本期不引入后台调度服务。
