# Design: Skill 对象存储与可重建缓存

关联：[规格](spec.md) · [执行记录](tasks.md) · [需求发现](../skill-object-storage-discovery.md)
版本：v2.7.0；更新：2026-10-18。
状态：2026-10-18 用户已确认设计；已实施并完成本机 API/Worker 对云端中间件的验证。§4 的旧状态仅作为对照，§4.2/§4.3 为当前实现；实测与限制见 e2e-report.md。

## 1. 目标与非目标

参照官方新版将 Skill 文件包持久化到现有 MinIO，节点仅保存可重建缓存，同时适配管理、任务加载和成员恢复校验。提供旧磁盘文件的独立迁移与恢复程序。

范围沿用 spec §4；不替换 Agent 框架，不引入自动 Skill 学习、市场、共享权限或新的后台清理服务，不同步官方其他功能。

## 2. 关键约束

遵循 [constitution C1–C7](../../../../docs/constitution.md)、[版本契约](../../release-contract.md)及 backend / migrations / scripts 的 AGENTS.md。保持 F035 对 Skill 对象的归属，数据库访问集中到 repository；保留现有 PermissionService 调用和严格租户上下文。

- 当前 API/Worker 连接共享远端中间件，只有任务队列独立。因此上线期间需要协调节点版本，不能将私有任务队列误认为数据隔离。
- 沿用上传 10 MiB、解压后 100 MiB 限制，不随官方主分支扩大容量；应用于上传、GitHub 导入、迁移和缓存解压。内部重新打包所得 ZIP 另设 110 MiB 传输上限、最多 4096 个文件、单个相对路径 UTF-8 最长 512 字节，以覆盖原有可压缩大包并约束 ZIP 元数据开销。超过新增文件数或路径上限的旧包报告需人工处理。
- 路径必须在包内且规范唯一；拒绝绝对路径、盘符、空字节、`.`/`..`、符号链接、重复或规范化后冲突路径，拒绝与 Windows 目录规则冲突的文件名。不把数据库 object_path 当任意可访问对象地址。
- 节点不向前端生成 Skill 包的公开下载链接；导出仍通过已有授权接口。缓存只对运行服务账户开放，不提交本地路径、正文或凭据到日志。

## 3. 方案与关键决策

### D1：权威存储与版本

备选：共享磁盘延续旧方案，需要部署额外挂载；固定对象名覆盖上传，存在对象更新与数据库发布竞争；按内容版本不可变对象，发布只切换引用。

选定第三种，复用 `get_minio_storage_sync()`、配置桶及已有凭据，对象键 `linsight/skills/{tenant_id}/{name}/{content_hash}.zip`。以排序路径和逐文件内容 SHA-256 计算整体 SHA-256，与官方方式对齐；ZIP 时间戳固定，重新打包相同文件不产生内容变化。

原因：已有远端实测证明仅切数据库不能提供文件；不可变对象避免两个并发写入把一个版本引用与另一份文件拼在一起。若未来需要历史版本产品化，再增加显式版本管理，不在本次引入。

### D2：缓存完整性与并发

备选：仅检查 SKILL.md 存在，成本低但附件损坏不可见；每次读取对 MinIO 发 HEAD，增加请求仍不能证明本地内容正确；本地内容校验后复用。

选定本地校验：根目录 `skills_cache_dir`，默认 `Path(CACHE_DIR)/"linsight_skills"`；目录 `{tenant_id}/{name}/{content_hash}`。每个批次读取完整文件映射并校验整体哈希；一次任务装载/详情/导出只校验一次，随后从该内存映射读取，避免每个文件重复扫描。预热缓存零 MinIO 调用，存在损坏时隔离当前缓存并重新下载一次，仍不匹配则失败。

同进程对相同版本采用有引用计数、空闲即释放的锁注册表，合并下载；不同进程可能各自下载一次，使用唯一临时目录、校验后原子发布，竞争失败者核验获胜目录，不返回临时目录。不同版本互不加锁。清理正在读取的缓存须在停机维护执行，避免清理与读写相互竞争。

原因：官方“目录存在即可信”无法覆盖本规格已确认的缓存损坏场景；本地 SHA-256 的成本换取内容完整性。若大包热点导致磁盘校验成为瓶颈，先依据压测讨论受保护缓存的校验复用，不直接关闭校验。

### D3：旧文件迁移与恢复摘要

备选：启动时扫描并迁移，可能阻塞启动且无法明确预览；运行读取自动上传并改数据库，会使普通读取具有发布副作用；独立显式迁移。

选定独立脚本。模型新增可空 `content_hash: String(64)`；空值表示未迁移，旧 `object_path` 保留，运行时仅允许从旧 `skills_root` 的推导目录只读加载。新发布必须对象存储，不能因 MinIO 错误退回磁盘发布。旧文件缺失时明确失败；兼容读取不冒充跨节点已可用。

迁移时只更改存储引用和版本字段，不改变文件字节。F074 `skill_digests` 继续使用当前 `路径 + NUL + 原始文件内容` 的旧摘要算法；新内容哈希用于对象版本，不能拿它替换旧任务快照摘要。同内容迁移不会阻断旧协议支持的恢复，真正变化仍沿用既有拦截。

若全部旧记录已完成迁移，可另行移除兼容读取；本期保留明确过渡期。

### D4：更新、删除与无主对象

发布顺序：验证包→PUT 不可变对象→独立读回校验→数据库事务发布引用。任何对象失败不发布元数据；数据库失败留下未引用对象，后续维护清理，禁止写入者删除它以免误删并发成功发布的相同内容。

更新采用 repository 的受租户保护条件更新，比较读取时的 `content_hash/object_path`；并发发布冲突明确失败，不能用脱离数据库的旧 ORM 实例覆盖已删除或已重建的记录。更新范围仅限内容元数据，不覆盖并发更改的启停状态。

删除先执行原有授权，再删除元数据；新读取及成员校验立即不可用。对象不在请求路径按名称前缀全删，缓存也不能绕过元数据；历史对象待停写维护清理。原因：按前缀删除可能误删同名重建或并发发布的对象，已有任务还可能持有旧文件。需要即时物理擦除时应另立数据保留契约，不在此承诺。

### D5：失败必须可见

现有 get_detail 将缺失包降级为空正文；skill_provisioning 对加载异常日志后跳过。改为：显式选择但缺失/损坏的 Skill 中断该次加载并抛领域错误，不挂载半份 Skill、不使任务宣称已使用它。未选 Skill 依然零读取，不影响普通任务。选中已停用/删除资源沿用配置拒绝，不扩大权限。

既有错误码优先复用；基础设施故障保留异常链交给现有异常处理，不能改成“找不到”掩盖连接故障。此行为对应 spec AC-08，不扩展到无关工具的失败策略。

## 4. 当前链路与实施落点

### 4.1 当前真实状态

`skill endpoints → SkillService → LinsightSkillDao + SkillStore(磁盘)`；管理方法直接同步读写磁盘，详情缺失会返回空内容。

`agent_factory/configured_subagents → materialize_session_skills → SkillStore → WorkspaceBackend.aupload_files`。复制到任务工作区是白名单门，主/成员目录不同。旧 TenantSkillsMiddleware 已 dormant，不作为新版运行入口恢复。

`AgentConfigService.resolve/revalidate → AgentConfigRepository → skill_digest`，成员 Skill 恢复时按实际文件计算摘要。

### 4.2 目标数据流

导入/更新：端点既有权限 → Service 校验 → `to_thread(SkillStore.write_bundle)` → repository 发布 → 既有详情格式。新建继续调用 PermissionService.authorize；数据库已发布但 owner tuple 写入失败仍沿用既有补偿流程，不删除已发布对象。

读取：repository 取得授权租户元数据 → 校验引用 → `to_thread(SkillStore.load_bundle)` → 验证缓存/MinIO → 文件映射 → 详情/导出或任务工作区上传。一次查询可取得所有选中 Skill 的版本，任务内按名称去重复用文件映射和摘要；不缓存跨步骤权限判断。

### 4.3 数据与模块契约

| 项目 | 目标约定 | 消费方 |
|---|---|---|
| `linsight_skill.content_hash` | 可空 64 位小写十六进制；非空表示对象版本，空表示未迁移 | Skill 管理、迁移、任务加载 |
| `object_path` | 新记录为推导对象键，旧记录仍为旧相对目录；不得来自请求参数 | repository/SkillStore |
| `BundleRef` | `size/content_hash/object_key`，size 为解压总字节数 | Service 发布 |
| `SkillStore.write_bundle(tid,name,files)` | 不可变 PUT+核验，返回 BundleRef，不改数据库 | 管理/运维 |
| `SkillStore.load_bundle(tid,name,hash)` | 返回经过核验的路径→bytes；hash 空只读旧推导目录 | 详情/导出/加载/摘要 |
| `skills_root` | 旧目录兼容读取与迁移来源，新增包不写入 | 迁移/过渡运行 |
| `skills_cache_dir` | 本地可重建目录，不应是共享卷 | 各 API/Worker |
| 管理 HTTP | 沿用 `/api/v1/linsight/skill` 的既有请求/响应，不暴露存储字段 | 现有两个前端 |

已新增 `domain/repositories/skill_repository.py` 封装现有元数据读写、条件发布、迁移和分批读取；Service 不新增直接 ORM 查询，不向 DAO 添加新入口。需要版本字段的旧批量访问器已返回完整模型，可复用；保留仍在使用的老访问器。

模块职责：

| 文件 | 负责 | 不负责 |
|---|---|---|
| skill_store.py（必要时拆 skill_bundle_cache.py） | 哈希、打包、对象/缓存读写与路径保护 | 授权/数据库 |
| skill_repository.py | 租户内元数据与条件发布 | 文件 IO/HTTP |
| skill_service.py | 管理编排和领域错误转换 | 裸 SQL/同步阻塞请求循环 |
| skill_provisioning.py | 按选择及启停筛选、批量加载后复制工作区，失败拒绝 | 静默跳过缺失包 |
| agent_config_service.py/repository | 批量版本读取、旧摘要校验、已有权限检查 | 将存储哈希替换恢复摘要 |
| configured_subagents.py/agent_factory.py | 继续使用原有装载入口和主/成员隔离 | 自动装配未选择 Skill |
| migration revision | 添加 content_hash，已有列守卫、保持单 head | 文件迁移/数据 UPDATE |
| migrate_skill_bundles.py、运维文档 | 预览/显式迁移、核验/恢复；清理由手册规定独立停写操作 | 启动自动迁移或后台 GC |
| migrate_sop_to_skill.py / seed_overflow_skill.py | 适配 BundleRef 和新版存储调用 | 重写已有 SOP 迁移语义 |

旧 skill_middleware 保持 dormant，不作为对象存储入口；其旧目录测试继续覆盖兼容读取。内置技能来源不顺带换代。模型说明及 F035 design §7 已引用当前契约，避免将历史共享卷布局用于新版部署。

## 5. 运行陷阱

| 事实 | 忽略后的后果 | 处理位置 |
|---|---|---|
| Redis 私有队列不隔离 MySQL/MinIO | 新发布使旧远端 Worker 找不到文件 | 运维升级窗口 |
| 对象版本哈希与 F074 原摘要算法不同 | 同内容迁移后历史续跑被误拦 | agent_config_service.skill_digest |
| WorkspaceBackend 的文件列表不提供目录树发现 | 直接把 Skill 源换成 MinIO 会发现不到技能 | skill_provisioning 保留复制步骤 |
| 元数据有而文件不存在不是空 Skill | 页面看似成功、任务未用技能 | Service 与 provisioning 明确失败 |
| MinIO 支持部分共享资源 Root 回退 | 租户 Skill 不可错误使用该回退 | 推导 `linsight/skills/{numeric_tid}/...`，验证引用；用多租户回归锁定 |
| 以客户端本地路径证明文件存在不够 | 完成后清理工作区导致误判产物丢失 | 真实 MinIO 读回验收 |

## 6. 迁移、契约与上线

### 6.1 数据结构与迁移脚本

Alembic 在真实当前单 head 后增加可空 String(64) 列，使用现有 online guards；不更改已发布 revision，不在 revision 读写业务数据。Fresh metadata 和升级旧表都要通过，兼容 MySQL/DM8；DM8 实机验证在中央环境执行，未执行前明确标注。

脚本计划命令（实现后可执行，均从 src/backend 目录）：

```powershell
.venv/Scripts/python.exe scripts/migrate_skill_bundles.py --tenant-id 1 --legacy-root <旧目录> --report <受保护报告路径>
.venv/Scripts/python.exe scripts/migrate_skill_bundles.py --tenant-id 1 --legacy-root <旧目录> --report <受保护报告路径> --apply
```

默认 dry-run；必须指定租户，不默认扫描所有租户。以 ID 游标每批最多 100 行，当前租户上下文 + strict filter。报告项为待迁移/已完成/源缺失/冲突/失败、记录 ID、名称、版本引用及错误类别，不写正文或密钥。适用异常的日志只含安全标识，完整底层 URL/授权头不输出。报告权限限运维人员。

apply：读取旧文件并验证→上传→绕开写入节点缓存从 MinIO 读回、核验全部内容→带旧引用和空 hash 的条件更新。失败保留旧文件、旧引用；源缺失不写。条件不匹配视为并发冲突，不覆盖新版本。已迁移行验证对象后跳过；对象缺失报失败而非静默“已完成”。每项事务、失败不中断其他记录，存在失败则退出非零。重试不依赖上次进程内存。

### 6.2 上线顺序与回退

1. 维护窗口暂停 Skill 写入及新任务提交，等待现有任务结束或受控停在可恢复状态；保存 Skill 元数据、旧文件与现有部署配置的备份。不能凭本机进程控制声称其他远端实例已经停写。
2. 发布协调版本的 API 与全部 Worker；执行 DDL-only 升级，启动后核验 schema。旧文件在迁移前仍可从具有原目录的节点只读加载。
3. 显式执行迁移预览与 apply；处理缺失项，从原部署找回文件或通过更新包恢复；进行跨缓存与真实任务验证后开放写入/新任务。迁移脚本退出前显式关闭懒注册的数据库连接，避免独立 CLI 在 Windows 事件循环结束后才回收 aiomysql 连接。
4. 当前开发环境只对标记测试 Skill 验证，不自动迁移缺失的五条真实业务 Skill，也不擅自操作其他远端部署进程。

回退前先停写/停止相关任务，使用受保护的迁移前清单和旧文件恢复原引用；升级后新增/编辑的包从 MinIO 导出到旧推导目录并核验，不能只恢复旧清单丢弃新内容。提供脚本 `--restore-legacy <输出根目录>` 默认预览，显式 apply 时先物化核验、再条件恢复旧引用并清空 hash，拒绝覆盖冲突源文件，保留云端对象。恢复后才能回滚 API/Worker。加法列可留存，禁止为回滚顺手删除数据列。

### 6.3 删除与容量维护

缓存不在每请求执行全目录扫描。运维在停相关节点且无活跃读写时，可删除指定缓存根下已验证的条目/根目录，重启后重建；临时残留也在同一窗口清理。每个包有硬上限，运维应监控节点磁盘余量；不宣称自动总容量淘汰已实现。

历史与未引用对象：独立维护模式只预览对象清单，按各租户数据库全部引用排除已引用对象；对象至少保留 7 天，清理前确认全局 Skill 停写、无相关执行/恢复任务且备份已验证。apply 前重新查询引用，仍可能受外部未协调写入影响，因此不能提供无维护窗口的“安全在线 GC”承诺。不会在本次验证清理生产对象。

### 6.4 失败语义与依赖

沿用 11051（格式/路径/一致性校验失败；并发更新冲突附受控原因，提示重新加载）、11052/11059（容量）、11053（文件包/文件不存在）、11055（新建重名），成员配置失败继续映射为 11071。S3 NoSuchKey 区分为缺失，连接/权限等存储错误保留异常链到既有服务异常处理，日志只记录受控错误类别。必要时复核既有 code 的文案是否足够；如需新码或用户文案，再同步三语言 SSOT，不手改生成文件。

依赖：MinIO manager 的同步字节读写/流式下载接口（在 to_thread 使用）、已有桶策略（若实际允许匿名访问 Skill 对象，必须先解决私有前缀访问边界才能验收租户隔离）、strict tenant filter、PermissionService、已有 WorkspaceBackend、现有登录用户。代码中 bucket 虽名为 public_bucket，默认匿名策略只开放 knowledge/images 和 tmp/images，不能仅凭名称断言整个桶公开，也不能据默认代码假定现有部署策略完全一致。实施前核对真实策略，并以匿名访问测试锁定 Skill 对象不可读；不能依靠对象键难猜替代访问控制，不改变桶共享资源的全局策略来修本特性。

## 7. 性能、测试与观测

I/O 与压缩/哈希放入 to_thread；单包上限控制内存，单进程包加载并发最多 4，避免多个 100 MiB 包及字节拷贝同时撑满事件循环侧资源。只在缺缓存时 GET 对象；完整首次加载先 stat 限制传输大小，流式读取累计长度受限，异常及时关闭连接。暖缓存路径零远端 stat/GET，仍有本地内容核验。授权元数据每次行为重新查询，任务装载中一次批量获取版本，不按文件查询数据库。

单测：用共享内存对象存储和两套独立缓存模拟多节点，验证 CRUD、中文/二进制、并发版本/缓存填充、缓存损坏与重建、边界和故障；repository 覆盖租户/CAS发布，测试旧摘要稳定。迁移测试覆盖预览无副作用、读回失败不更新、重跑/并发变更/恢复。对 MinIO 的调用计数证明暖缓存无远端 IO。

回归：`test/linsight`、相关迁移单 head 测试、ruff、arch-guard；全量结果与现有环境基线区分，不以 mock 代替真实集成结论。DM8 未具备条件则保留明确待验证项。

真机：创建带 REMOTE-SKILL 标记且仅包含合成文本/小附件的测试包；走授权 API 和浏览器导入、详情、导出；隔离缓存 B 冷启动读取，清理 B 缓存再读并比对内容；主 Agent 和指定成员实际 read_file 得到唯一标记并交付云端产物；校验恢复摘要不受迁移影响，内容变化会阻断。测试日志/截图进入忽略目录，不提交任何凭据。

观测：记录租户、Skill 名、内容版本、命中/修复/失败类别、字节数及耗时；不包含正文与凭据。迁移报告为逐记录运维证据；发布/迁移失败保留受控异常链，不写带密钥的 URL。状态记录见 tasks.md，不在本文声称已通过实测。
