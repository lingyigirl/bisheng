## 1. 用户故事

作为工作空间用户，我希望为任务配置不同职责和能力的协作成员，让主智能体自主委派、综合结果，并能看到各成员的执行情况。

作为长时任务用户，我希望断网后能继续查看任务，回答澄清问题后可以接着执行，无需重新提交任务。

## 2. 验收标准

### 2.1 配置与自主执行

- **AC-01** — WHEN 用户在任务模式配置协作成员，THE SYSTEM SHALL 允许分别设置名称、职责、提示词、模型、Skills、工具和已有连接器动作，并在再次打开该任务时展示实际执行配置。
- **AC-02** — WHEN 用户提交配置了成员的任务，THE SYSTEM SHALL 允许主智能体按目标自主规划、选择成员、调用工具、调整执行步骤并汇总最终结果；选中成员不代表必须调用。
- **AC-03** — WHEN 成员使用独立模型、Skills、工具或连接器，THE SYSTEM SHALL 使用该成员的有效配置执行；未选择的可选工具和技能不得因默认继承自动装配给该成员。
- **AC-04** — IF 用户选择不可访问、已删除、已禁用或不适用的资源，THEN THE SYSTEM SHALL 明确拒绝该配置，不得静默替换资源或扩大权限。
- **AC-05** — WHILE 任务正在执行或等待用户输入，THE SYSTEM SHALL 将本轮成员配置展示为只读；继续同一任务时沿用本轮配置。
- **AC-06** — WHEN 新任务未配置协作成员，THE SYSTEM SHALL 仍启用 Harness 执行、持久化补播与安全恢复协议，并保留内置研究子智能体；历史任务保持原协议，不自动升级。

### 2.2 执行过程与结果

- **AC-07** — WHEN 主智能体发起一次委派，THE SYSTEM SHALL 为该次调用显示成员名称、受派目标、运行状态、耗时、可展开的工具活动及返回结果。
- **AC-08** — WHEN 同一成员被多次调用或多个成员并行执行，THE SYSTEM SHALL 将各自活动与正确的调用关联，不得因事件到达顺序变化而串线。
- **AC-09** — WHEN 成员执行失败，THE SYSTEM SHALL 显示真实失败状态或降级结果，并允许主智能体根据已取得的信息决定下一步；不得把失败伪装为成功。
- **AC-10** — WHEN 用户终止任务，THE SYSTEM SHALL 停止继续调度成员并结束运行态展示；成员需要用户澄清时，由主智能体统一呈现问题。

### 2.3 长时任务与恢复

- **AC-11** — WHEN 浏览器暂时断网或关闭连接，THE SYSTEM SHALL 保持后端任务继续运行；重新连接后恢复显示最新任务状态和可用执行过程。
- **AC-12** — WHEN 客户端重连且过程记录仍在保留期内，THE SYSTEM SHALL 补齐遗漏事件，且重复接收事件不得导致重复内容或重复执行任务。
- **AC-13** — IF 客户端保存的过程位置已失效，THEN THE SYSTEM SHALL 明确重置展示，并从持久化历史和最新状态恢复；不得无限重连或声称已找回不存在的逐条事件。
- **AC-14** — WHEN 任务等待用户输入后收到回答，THE SYSTEM SHALL 在可用 Worker 上沿用原任务上下文和成员配置继续执行，包括原 Worker 已退出的情况。
- **AC-15** — IF 执行进程异常退出，THEN THE SYSTEM SHALL 显示异常或可恢复状态，禁止未经安全验证的自动工具重放；任何开放的受控恢复入口必须证明不会重复外部写入。

### 2.4 复用能力与依赖

- **AC-16** — WHEN 任务调用代码执行能力，THE SYSTEM SHALL 在配置的云端沙箱内执行并提供正确的文件产物；隔离按任务级代码执行验收。
- **AC-17** — WHEN 用户继续同一会话，THE SYSTEM SHALL 保留既有会话上下文，并使历史任务仍可查看。
- **AC-18** — WHERE 统一记忆服务已接入，THE SYSTEM SHALL 在可信用户、租户和应用范围内读取相关记忆，并向该服务提交候选经验；服务尚未接入时明确记为依赖未完成，不得声称长期记忆已交付。
- **AC-19** — THE SYSTEM SHALL 拒绝跨租户和越权访问任务配置、执行事件和结果；共享查看者不得取得连接器凭据或因此获得执行权限。

## 3. 边界情况

- 成员标识重复、名称或职责为空、配置超过数量/文本长度限制：提交失败并指出问题。
- 显式空成员列表表示不启用自定义成员，但新任务仍启用 Harness；省略配置的同会话新一轮沿用上一轮成员并重新校验。具体恢复规则见 recovery-policy.md（2026-10-18 用户直接授权调整）。
- 已选成员未被主智能体调用：不能显示为执行失败或永远排队。
- 工具、模型或技能在任务中途被撤销访问：后续执行不得绕过撤销，恢复时不得替换成其他资源。
- 多端同时查看同一任务：各连接均能读取过程，不应相互消耗事件。
- 任务完成后的刷新、等待输入时的重连、终止后的迟到事件：显示最终一致的状态。
- 不兼容的软件版本或过期恢复点：明确说明无法恢复，不能重新执行整项任务冒充续跑。
- 长期记忆服务未提供：核心任务仍可执行，联调结论标为待依赖。

## 4. 本期不包含

- Hermes 运行时整体替换、递归多层子 Agent、逐成员独立容器。
- WBS 8.2/8.3 的长期记忆存储、画像提取与治理页面。
- 未验证的任意崩溃自动续跑和任意外部工具的恰好一次执行承诺。
- F073 工作流型多智能体应用配置与执行树的写入行为变更。

## 2026-10-18 性能修复补充（用户授权“全部处理一下”）

保持现有 Harness 和恢复安全策略，优化长历史回放、快照读取、运行期恢复扫描、成员即时资源校验四条路径。客户端回放不得逐 token 提交全局状态；思考合并必须保留全部文本及原始起止时间。快照按固定末尾游标分页读取，不吞掉分页期间的新事件；裁剪或丢失必须报告不完整。恢复扫描有界分页，不加载大字段，并批量检查租约。成员校验按选定资源和工具组聚合，仍在每次模型/工具调用前重验，撤权和资源禁用必须立即阻断。记忆继续排除。
