# 云端产物预览/下载诊断（2026-10-14）

## 根因与修改

工作空间 Client 的 Vite 文件代理继承 VITE_DEV_MINIO_TARGET=http://127.0.0.1:9000，但本次 Docker MinIO 映射为 127.0.0.1:9100。后端签名路径由 Client 拼接 /workspace 前缀，再经同源代理访问存储；错误代理端口导致所有格式的预览/下载共同返回 502。

已在忽略的 src/frontend/client/.env.local 固定本地 API 7860、MinIO 9100、平台 3001 配置。无需改沙箱执行方式或浏览器直接访问 E2B。现有进程中的同名环境变量优先级更高，必须更新启动环境并重启 Client 才能生效。

## 实证

- 截图对应任务 2499aab2fee243b79ea3a38ec66bc684 的 Markdown 和 PNG 均已落入 MinIO。经已有鉴权 file_download 接口获取签名路径后直接读取，均为 200；字节数分别为 5619 与 345749。
- 对已知测试产物，通过 127.0.0.1:9100 读取为 200；通过 localhost:4001/workspace 同源路径为 502，响应为 MinIO proxy error: connect ECONNREFUSED 127.0.0.1:9000。
- 因而此次故障位于前端开发代理，不是 E2B 文件丢失，也不是 Markdown 格式不支持。
- 写入本地配置后，旧进程仍继承 9000。用户明确授权重启；后台启动被自动审批拒绝，随后改用受管终端执行 pnpm dev，成功在 4001 启动。启动日志确认 MinIO proxy 指向 http://127.0.0.1:9100。
- 修正后 Markdown 与 PNG 的工作空间同源地址均返回 200，内容 SHA-256 与 MinIO 原件逐项一致。
- 浏览器实际打开 Markdown，正文表格和内嵌图表正常；独立 PNG 预览加载完成，尺寸 2220×1638。
- 实际点击“另存为 → Markdown”和图片“下载”，浏览器下载到用户 Downloads；两个文件的 SHA-256 与存储原件相同，字节数分别为 5619 和 345749。
- 验收截图：忽略目录 .venv/f074-artifact-preview-fixed.png。此次仅修正本地部署配置，无业务代码改动、无远端推送。

## 推荐交付路径

保持 E2B output 文件同步到平台持久对象存储，并保存产物清单；浏览器通过平台鉴权和同源网关访问。这样沙箱关闭后仍可预览/下载，也避免暴露沙箱地址、密钥和短期执行环境。

生产环境按部署配置转发 /workspace/<bucket>/... 到对象存储，去除 /workspace 前缀并保留路径与签名查询参数。上游 Host 必须与后端签名所用 sharepoint 完全一致（含端口，localhost 与 127.0.0.1 不能混用），HTTPS 页面也应通过 HTTPS 同源入口访问。9100 是本机映射，不应硬编码成通用生产默认值。

以前“MinIO 直读成功”的证据只覆盖存储链路，不代表浏览器同源访问成功。后续产物验收应同时验证实际同源地址、Markdown 内图片、独立图片预览以及浏览器下载的字节内容。
