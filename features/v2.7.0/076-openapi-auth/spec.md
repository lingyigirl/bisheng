# Feature: 开放 API 鉴权（076-openapi-auth）

> **本文档定位 — 纯 What（需求口径，不随代码漂移）**
>
> spec 只回答 **做什么 / 验收标准 / 不做什么**。
> **所有 How（决策、数据流、字段、API、Service、前端、文件清单、性能指标）一律不写在这里。**
> How 的唯一真相在 [design.md](./design.md)（接手必读）与 [tasks.md](./tasks.md)（执行流水）。
>
> 为什么这么切：How 写进 spec，实现一变 spec 就过时，而 spec 通常没人回头改 → 接手人被旧方案误导。
> spec 只承载需求口径，才能长期稳定、可被反复引用。
>
> **前置步骤**：本文档编写前必须已完成 Spec Discovery（架构师提问），PRD 中的不确定性已与用户对齐。

**关联 PRD**: 北京农商银行《智能体平台建设项目供应商征集公告》（2026-09-24）**（四）对接外部知识、数据和系统 → 第 3 条**：「支持外部系统对接：支持行内各系统经API调用智能体应用和工具；提供 API Key 与调用方鉴权」。需求调研与 8 项决策见 [discovery.md](./discovery.md)；条款对照与实施方案背景见分支 `local/beijing-ns-notes` 的 `docs/openapi-auth-vs-bjrcb-requirement.md` 与 `docs/openapi-auth-implementation-plan.md`。
**优先级**: P0（客户征集公告显式条款）
**所属版本**: v2.7.0
**依赖**: 无前置 Feature。只读复用既有能力：`/api/v2` 全部既有端点、`PermissionService`（ReBAC 授权）、默认操作员的身份装载链路、`audit_log` 审计表、错误码与三语 i18n 生成链。**开发基线**：本特性所在的项目交付集成基线（特性间为线性叠加，非各自独立分支）。

> **范围边界**
> - **本次纳入**：
>   - **服务账号**：每个对接系统一个账号（名称/描述/启用状态），并为其维护一个平台内的专用资源所有者身份
>   - **API 密钥**：签发（明文可由管理员经审计查看）/权限位勾选/有效期（可空）/编辑/吊销（单把与全量）/多把并存/每 Key 智能体白名单
>   - **调用方鉴权**：`/api/v2` 每次调用校验密钥，密钥决定执行身份与可见范围；失败返回真实 HTTP 状态与错误码
>   - **强制开关**：部署级 + 租户级两层，默认关闭；关闭时保持升级前行为不变
>   - **平台免登录面收编**：平台自身免登录页依赖的 8 个端点纳入同一开关（默认关闭即要求密钥）
>   - **工具参数**：助手/工作流的调用请求可指定本轮启用的平台工具（限该应用已绑定且启用的工具），并可在应用详情中查询可用清单
>   - **密钥自检端点**：对接方联调自检
>   - **调用审计与管理动作审计**：逐调用可追溯到密钥与服务账号；不出密钥明文
>   - **管理界面**：管理端「系统」内的服务账号页（三语）
> - **本次明确排除**（延后 / 另立变更）：
>   - **"工具直调"端点**（把工具做成可寻址资源、独立请求/响应契约与权限位）——本期按"调用时可指定启用工具"实现（决策 D2）
>   - **代表用户调用**（`X-On-Behalf-Of`）与**外部终端用户标识**（`X-End-User`）——本期身份固定为服务账号自身，延后
>   - **任务模式 / 日常模式开放 API**（含异步提交、进度查询、产物下载）——我方 `/api/v2` 无该面
>   - **个人密钥（`bs-pat-`）与 AI 助手接入**——本期只签发服务账号密钥
>   - **`/api/v3` 免登录公开接口改造**——本期以 `enable_guest_access` 开关承接免登录面
>   - **服务账号成为一等授权主体**（进入授权模型）——本期以"专用最小权限用户 + 代管其既有资源授权"实现
>   - **限流 / 配额 / IP 白名单 / 幂等 / OpenAPI 规范导出**——对齐上游的范围裁定，本期不做、不预埋
>   - **国密化（SM2/SM3/SM4）**——公告（十）5 属平台级合规条款，本期不单独实现（传输由行内 TLS/网关承载）
>   - **存量调用方改造的组织与实施**——本特性交付能力与迁移指引，不在本特性内代其改造

## 1. 用户故事

**A. 行内系统开发/集成方**
作为 **行内某系统的对接开发**，
我希望 **用一个归属明确、权限范围清晰的密钥调用平台的智能体应用（并可按需指定启用哪些工具）**，
以便 **在不依赖行内网络隔离假设的前提下完成系统集成，且出问题时能自我诊断**。

**B. 平台管理员（超管/租户管理员）**
作为 **平台管理员**，
我希望 **为每个对接系统建立独立账号、单独授予其可访问的应用与知识库、随时签发/吊销密钥并看到谁在何时调用了什么**，
以便 **在人员或系统变动时能收敛权限、在审计场景能给出证据**。

**C. 行方安全/审计**
作为 **行方的安全与审计角色**，
我希望 **开放 API 的每次调用都能追溯到密钥与账号，且密钥明文仅管理员可经审计查看、不会出现在日志与审计中**，
以便 **满足对接入方的可管、可查、可追责要求**。

## 2. 验收标准

> 错误码号在本表中作为**可观测的对外行为**引用；定义与编码规则见 design.md 与 `common/errcode/`。

### 2.1 服务账号与专用身份

- **AC-01** — THE SYSTEM SHALL 为每个对接系统维护一个服务账号：含名称、描述、启用状态，且名称在同一租户内唯一。
- **AC-02** — WHEN 创建服务账号, THE SYSTEM SHALL 自动创建一个专用身份作为该账号的资源所有者：不可交互登录、不授予任何角色与资源权限；创建失败时服务账号不得残留。
- **AC-03** — IF 服务账号的所有者在创建或变更时已是系统管理员 / 租户管理员 / 部门管理员, THEN THE SYSTEM SHALL 拒绝该操作（400 / 11810）。
- **AC-04** — IF 服务账号所有者事后被授予管理员角色, THEN THE SYSTEM SHALL 在该账号后续调用时一律拒绝（403 / 11816），不得静默放行。
- **AC-05** — WHEN 服务账号被停用, THE SYSTEM SHALL 使其名下所有密钥在 ≤5 秒内失效（调用返回 401 / 11805）。
- **AC-06** — WHEN 服务账号被删除, THE SYSTEM SHALL 撤销其全部密钥与资源授权、停用其专用身份，并保留审计记录（不物理删除历史归属）。
- **AC-06a** — WHEN 管理员为服务账号授予或撤销资源（应用、知识库等）授权, THE SYSTEM SHALL 以该管理员对目标资源的管理权限为前提（无权管理的资源不可授予）；授权写入平台的统一权限判定体系，且服务账号调用时的资源可见范围即该授权范围（不得超出、不因授权动作获得管理员特权）。
- **AC-07** — WHERE 多租户开启, THE SYSTEM SHALL 把服务账号与密钥的管理接口限定在当前租户；跨租户访问该租户外对象返回 404。

### 2.2 API 密钥生命周期

- **AC-08** — WHEN 管理员签发密钥, THE SYSTEM SHALL 在签发响应中返回明文；此后列表与调用接口只返回掩码（前缀 + 末四位），管理员可通过**显式查看动作**获取明文（AC-44），其余任何接口与界面不得回显明文。
- **AC-09** — THE SYSTEM SHALL 以**不可逆摘要**校验密钥，并以**独立加密密文**支持管理员查看：明文不落日志、不落审计、不出现在异常信息、列表响应与缓存中；密文只在该密钥的查看动作中被解密。
- **AC-10** — THE SYSTEM SHALL 允许同一服务账号并存多把密钥（用于轮换），每把密钥独立设置有效期（允许为空 = 不过期）与权限位集合。
- **AC-11** — WHEN 密钥被吊销（单把或全量）, THE SYSTEM SHALL 在 ≤5 秒内使其失效（401 / 11804），且**保留**该密钥记录（吊销 ≠ 删除，保留审计归属）。
- **AC-12** — WHEN 密钥已超过有效期, THE SYSTEM SHALL 拒绝其调用（401 / 11803）；有效性判定为"未撤销且未过期"，不引入第三种状态。
- **AC-13** — WHEN 管理员修改密钥名称 / 权限位 / 有效期, THE SYSTEM SHALL 使变更在 ≤5 秒内生效，无需重新签发。
- **AC-14** — THE SYSTEM SHALL 记录每把密钥的最后使用时间，供运维对账与轮换判断（允许分钟级延迟）。
- **AC-15** — THE SYSTEM SHALL 为密钥的签发 / 变更 / 吊销生成审计记录，且审计内容不含明文。

### 2.3 调用鉴权（`/api/v2`）

- **AC-16** — WHERE 强制鉴权开启, THE SYSTEM SHALL 要求 `/api/v2` 的每次调用携带有效服务账号密钥，除 AC-20 的免登录面外**无任何回落路径**（登录态 JWT、cookie、默认操作员一律不得替代密钥）。
- **AC-17** — IF 调用未携带密钥或密钥格式非法, THEN THE SYSTEM SHALL 返回 401 / 11801。
- **AC-18** — IF 密钥无效、已吊销、已过期或所属服务账号已停用, THEN THE SYSTEM SHALL 分别返回 401 / 11802、11804、11803、11805（四类可区分）。
- **AC-19** — WHEN 密钥校验通过, THE SYSTEM SHALL 以该服务账号的专用用户为执行身份（含正确的租户上下文），资源可见范围按其既有授权判定；服务账号**永不继承**任何管理员特权。
- **AC-20** — WHERE 免登录开关关闭, THE SYSTEM SHALL 对平台免登录页依赖的 8 个端点与其他 `/api/v2` 端点**同样要求密钥**；该开关开启时，这 8 个端点允许匿名调用（清单见 design.md，须被守卫测试冻结）。
- **AC-21** — WHERE 强制鉴权关闭, THE SYSTEM SHALL 保持与升级前完全一致的 `/api/v2` 行为，**包括忽略请求携带的任何密钥**（即使密钥无效/已过期也不拦截、不改变身份）。
- **AC-22** — WHEN 密钥缺少端点所需的权限位, THE SYSTEM SHALL 返回 403 / 11807，并在响应中指明缺失的权限位。
- **AC-23** — WHEN 调用的目标资源不存在、或不在该服务账号的授权范围内, THE SYSTEM SHALL 返回 404 / 11809（防枚举：两种情况不可区分）。
- **AC-24** — IF 鉴权所依赖的服务（缓存 / 数据库 / 授权服务）不可用, THEN THE SYSTEM SHALL 返回 503（11812 / 11814），**绝不**降级放行。
- **AC-25** — WHEN 调用在强制开启时携带调用方指定的用户身份参数（裸 `user_id`）, THE SYSTEM SHALL 返回 400 / 11817；不得静默忽略、不得按其指定身份执行。
- **AC-26** — THE SYSTEM SHALL 使上述鉴权/权限失败以**真实 HTTP 状态码**（401/403/404/503/400）返回，响应体为统一错误信封；流式场景中，响应头发出前的失败用 HTTP 状态，发出后的失败走流内终态并记录业务码。
- **AC-27** — THE SYSTEM SHALL 保证 `/api/v2` 不存在"未被授权要求"的端点：任何端点缺少权限位归属时，其调用一律被拒绝（500 / 11811），不得默认放行。

### 2.4 智能体应用与工具调用

- **AC-28** — WHEN 携带有效密钥调用助手 / 工作流的开放端点, THE SYSTEM SHALL 正常执行并返回结果（含流式响应）。
- **AC-29** — WHERE 请求携带工具参数, THE SYSTEM SHALL 仅在该应用**已绑定且启用**的工具范围内启用本轮工具；未携带时按应用默认配置执行（与升级前一致）。
- **AC-30** — IF 工具参数含未绑定、未启用或不可识别的工具, THEN THE SYSTEM SHALL 返回 403 / 11815 并指明工具标识；不得静默忽略或降级。
- **AC-31** — THE SYSTEM SHALL 在应用详情查询中返回该应用当前可用（已绑定且已启用）的工具清单，供对接方构造调用参数。
- **AC-32** — WHEN 通过 WebSocket 建立对话连接, THE SYSTEM SHALL 在握手阶段校验密钥：校验失败拒绝握手；**已建立的会话不因密钥事后吊销而中断**（后续新调用按新状态判定）。

### 2.5 自检、开关与迁移

- **AC-33** — THE SYSTEM SHALL 提供密钥自检端点：校验密钥并要求不高于最小的权限，回显该密钥所属账号、权限位、有效期与掩码。
- **AC-34** — WHEN 管理员调整本租户的强制鉴权开关, THE SYSTEM SHALL 使变更在 ≤5 秒内生效；部署级与租户级**同时开启**时才强制（任一关闭即不强制）。
- **AC-35** — THE SYSTEM SHALL 随交付提供存量调用方的切换步骤与回退步骤：开关关闭即恢复旧行为；并提供"盘点调用方 → 改造 → 预发验证 → 生产切换 → 观察缺失密钥命中"的操作清单。
- **AC-35a** — THE SYSTEM SHALL 使对外接口文档与实际鉴权行为保持一致：文档不再表述"由网络层负责访问控制"，并补充密钥用法、工具参数与存量迁移指引。

### 2.6 审计

- **AC-36** — WHEN 任一被鉴权的调用完成, THE SYSTEM SHALL 记录一条调用审计：密钥标识（掩码）、服务账号、权限位、HTTP 状态、业务码、耗时、来源 IP；审计写入失败**不得阻塞或改变**调用结果。
- **AC-37** — THE SYSTEM SHALL 对全部管理动作记录审计（服务账号创建/启停/删除、密钥签发/变更/吊销、资源授权变更、租户开关变更），含操作者与关键前后取值。

### 2.7 管理界面

- **AC-38** — THE SYSTEM SHALL 在管理端「系统」内提供服务账号页：账号列表（含状态/密钥数/最后使用）、创建、启停、删除、密钥管理（签发/编辑/吊销/全量吊销）、资源授权管理。
- **AC-39** — WHEN 密钥签发成功, THE SYSTEM SHALL 以弹窗展示明文：提供复制、提示"请妥善保存，管理员可经审计再次查看"、要求确认已保存后才允许关闭；密钥列表另提供「查看」动作（AC-44）。
- **AC-40** — THE SYSTEM SHALL 使新界面同时具备中文 / 英文 / 日文文案（三语齐发，沿用平台 i18n 与错误码文案生成链）。
- **AC-41** — IF 操作者不是系统管理员或当前租户管理员, THEN THE SYSTEM SHALL 不在界面展示该页并拒绝其管理接口调用。

### 2.8 密钥查看与按智能体授权（2026-10-22 增量）

- **AC-42** — THE SYSTEM SHALL 支持为每把 API 密钥设置**智能体白名单**：白名单未设置（NULL）表示不限制、沿用服务账号资源授权；显式空列表表示不调用任何智能体；非空列表表示只能调用列表内的助手 / 工作流 / 纳管智能体。白名单只收窄、不扩权。
- **AC-43** — WHEN 管理员签发或编辑密钥, THE SYSTEM SHALL 接受并回显 `allowed_apps`；条目必须属于该服务账号可见的资源，否则拒绝（400 / 11822）。白名单可在签发后随时编辑，≤5 秒生效，且不影响同账号其他密钥。
- **AC-44** — WHEN 管理员对某把密钥执行查看动作, THE SYSTEM SHALL 返回明文并记录一条审计（操作者、账号、密钥掩码/id、时间、IP），响应禁止缓存；密钥无密文（存量密钥）或密文损坏时返回 400 / 11823，不返回明文。查看权限与密钥管理接口一致（系统管理员或当前租户管理员）。
- **AC-45** — THE SYSTEM SHALL 在 `whoami` 中回显 `allowed_apps`；`GET /api/v2/assistant/list` 在密钥设置白名单时只返回白名单内的助手，`total` 与过滤后结果一致；白名单仅含工作流或为空时返回空列表。
- **AC-46** — THE SYSTEM SHALL 对所有智能体寻址端点执行同一白名单判定：助手对话/信息/列表/WS、工作流调用/停止/WS、流程详情、会话面、纳管智能体调用，以及 `schedule/trigger` 的间接调用；未命中一律 404 / 11809（与资源不可见不可区分）。该路由矩阵由静态守卫测试冻结，新增端点不得默认放行。

## 3. 边界情况

- 当**服务账号尚未授予任何资源授权**时，其密钥可完成鉴权但访问具体资源一律 404 / 11809（可见范围为空是合法状态）。
- 当**密钥的权限位集合为空**时，签发成功但调用任何端点均 403 / 11807。
- 当**应用被下线/删除**后仍被调用，返回业务侧既有错误（不因鉴权而改变），且必须发生在鉴权通过之后。
- 当**同一请求同时携带密钥与登录态 cookie** 时，强制开启的 `/api/v2` 一律以密钥身份执行，登录态不生效。
- 当**未鉴权的大文件上传**到达 multipart 端点时，请求体可能已被完整接收后才返回 401——本期记为已知限制（不改变对外语义），设计侧须避免在中间件读取请求体。
- **升级后的行为变化提示**：既有对接若依赖"默认操作员是超级管理员"的短路才能访问资源，切换后将按其服务账号（专用用户）的授权判定；迁移指引须单列该排查条目。
- 状态变更的收敛延迟：吊销 / 停用 / 过期 / 密钥变更的最坏生效时间为 5 秒，AC 中的时延均以此为准。
- `delegate` 权限位本期可签发但不产生任何生效行为（界面标注"预留"）。
- **存量密钥查看**：本次增量上线前签发的密钥只有 SHA-256 摘要、没有查看密文，查看一律 400/11823；需要明文只能重新签发。存量密钥的 `allowed_apps` 为 NULL，行为与升级前一致（不限制）。
- **白名单与档位**：白名单只保证"资源对该账号可见"；若账号对某工作流/纳管智能体只有 viewer 档，白名单可以保存，但实际调用仍按既有权限判定返回 404/11809，不会因白名单而提升档位。
- **纳管智能体条目**：`managed_agent` 白名单条目对应纳管注册表 id，不是 `native_app_id`；工作流内部的 agent 节点、助手绑定的技能不单独授权。
- 本特性会扩展既有的**用户对象**（自动创建专用身份、限制其角色/密码被人工修改、账号删除时停用）与**审计记录**（新增两类动作）——两者均为"扩展既有对象、不拥有对象本身"，须按表 1 的登记写法在 release-contract 中登记（见相关文档）。
