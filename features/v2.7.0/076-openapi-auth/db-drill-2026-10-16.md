## 2. MySQL 真库演练（已执行）

环境：本机 dev 库（`bisheng` schema，MySQL）。三张表**无 Alembic revision**，由 SQLModel `create_all` 建（`common/init_data.py:22-28` → `connection.py:276`）。演练脚本：三张表逐字段核对 + 回滚 SQL 影子演练（`CREATE TABLE <t>__drill LIKE <t>` → `DROP TABLE IF EXISTS <t>__drill`，**不动现网表**）。

### 2.1 DDL 逐字段核对（模型声明 vs `information_schema`）

| 表 | 列数（模型/现网） | 唯一约束 | 索引 | 关键默认值实测 |
|---|---|---|---|---|
| `service_account` | 10 / 10 ✅ | `uk_service_account_tenant_name(tenant_id,name)` ✅ | 3/5（另 2 个来自 `index=True` 单列）✅ | `create_time`/`update_time` = `CURRENT_TIMESTAMP`（update 带 `ON UPDATE`）✅ |
| `api_credential` | 15 / 15 ✅ | `uq_api_credential_token_hash(token_hash)` ✅ | 3/5 ✅ | 同上；`key_prefix` 默认 `'bs-sak-'` ✅；`scopes` 实为 `json NOT NULL` ✅ |
| `open_api_tenant_setting` | 3 / 3 ✅ | 无（`tenant_id` 即主键，每租户一行）✅ | 0/1（主键）✅ | `enforce_keys` 默认 `'0'`、NOT NULL ✅ |

**判定：PASS**（列集合完全一致，无缺失/多余；唯一约束与索引为子集关系且实际存在；注释与默认值逐条核对）。

### 2.2 回滚 SQL 演练

```
-- 与三个模型文件头注释一致（本特性不写 Alembic revision，整表由 create_all 建）
DROP TABLE IF EXISTS service_account;
DROP TABLE IF EXISTS api_credential;
DROP TABLE IF EXISTS open_api_tenant_setting;
```

影子演练：三张 `*__drill` 表由现网 DDL 复制创建成功 → 执行上述 DROP 后**零残留**、现网三表完好 ✅。

**完整卸载回滚（除 DROP 外还须做的一步）**：从租户过滤登记表中摘除这三张表的模型路径（`bisheng/core/database/tenant_filter.py` 的 `_TENANT_AWARE_MODEL_MODULES` 登记 `open_api.domain.models.*`），否则启动期的模型发现会因表不存在而告警。DM8 上还有一条：`create_all` 会为带 `update_time` 的表建 `trg_<表>_update_time` 触发器（`connection.py:311-354`），回滚时随表一并删除（DM 触发器随表 DROP）。
