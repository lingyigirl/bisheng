## A. 需要独立 feature 承接

### A-1 检索期可见性重校验（AC-23 / AC-24）— **唯一一条有安全含义的**

**现状**：linsight 的检索白名单从**会话里存的 id** 构建，`SearchKnowledgeBase` 只校验
「id 在不在白名单里」，**检索时不重算可见性**。会话 id 是客户端提交后原样落库的。

**后果**：一个会话可以继续搜索一个**已经对它不可见**的知识库——用户选了库 → 该库因
机构域变更（翻转载记、移动节点）而移出可见范围 → 检索仍放行。

**为什么没在 F062 修**：
- **早于 F062 存在**。F057 时就是这个行为，根因是**会话模型**「你选了什么就搜什么」的固有语义。
- 修它需要**每轮检索前重做可见性校验**（或在读会话时校验），落点在 linsight，不在可见性规则。
- 它有自己的验收口径（哪些入口、会话何时失效、用户已选但失权的库如何提示）。

**影响面**：INV-21 声称「标记对所有知识库读取入口无条件生效，含 linsight 任务内核」——
**这里是它目前不成立的地方**。invariant 要么被满足，要么被改写，不应长期悬空。

**建议**：下一个版本起 feature，AC 至少覆盖：① 检索前重校验；② 用户失权后的会话行为
（静默忽略 / 提示）；③ 与工作台对话入口的一致性。

### A-2 批量影响面的精确计算

选择集内部有交互——祖先与后代同选时，同时翻转的真实影响 ≠ 各自影响之和。
当前是**逐节点预览后求和**，会**低估**（正是「弹窗说少了比没有弹窗更糟」的方向）。

**建议**：改为对「选择集同时翻转」的假想树做一次计算。若做，先确认选择集的语义
（是否允许祖先后代同选，还是前端就应禁止）。

## C. 明确不做（已定决策，勿重复提议）

| 项 | 理由 |
|---|---|
| **deny / 排除名单**（INV-20） | 需要「减集」语义，而整条链路是并集模型；会与缓存、失效、审计同时纠缠。要隔离请改树结构 |
| **可见集合物化列**（决策 7） | 读时求值是正确的默认；该规模下不需要 |
| **知识空间穿透**（决策 9） | 知识空间有独立的成员制授权，叠加会制造两套并行语义 |
| **标记继承** | 透明是宽松态，继承会让「在哪点创建」意外放宽可见性 |
| **根节点类型约束** | AC-14 已证对规则无影响，约束它没有收益 |

### D-1 组织树标注 —— **本特性不会自动生效**

`is_department` 的存量默认值是 `0-机构`，这是**刻意的安全缺省**：全部为机构时新规则
**恒等于** F057 的既有行为，所以升级本身零风险。代价是**需求 2 不会自动生效**——
必须由实施把组织树标注完成，客户才会观察到需求所述的效果。

**这一条要写进交付清单与验收前置条件**，否则上线当天会被判「功能没生效」。

引导条（AC-08）与批量标注（AC-08 的多选）已实现，用于降低这个动作的成本，
但**不代替**它。
