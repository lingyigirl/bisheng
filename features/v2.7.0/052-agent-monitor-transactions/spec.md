# Feature: 智能体监控页签（按交易监控 + 节点出入参可视化）

> **本文档定位 — 纯 What（需求口径，不随代码漂移）**
>
> spec 只回答 **做什么 / 验收标准 / 不做什么**。
> **所有 How（决策、数据流、字段、API、Service、前端、文件清单、性能指标）一律不写在这里。**
> How 的唯一真相在 [design.md](./design.md)（接手必读）与 [tasks.md](./tasks.md)（执行流水）。

**关联 PRD**: 用户需求（2026-09-05）：日志页（/log）监控能力不足——需要「智能体监控」页签，能够按交易监控（知道是哪笔业务调用），并且智能体中每个节点的执行出入参能够可视化展示。
**优先级**: P0
**所属版本**: v2.7.0
**依赖**: F046-agent-monitoring（只读复用其运行级遥测事件与调用日志查询范式）

> **范围边界**
> - **本次纳入**：
>   - `/log` 页新增「智能体监控」页签（复用 log 菜单权限，不新增菜单/权限）
>   - 按交易监控：一次智能体运行 = 一条交易记录，展示**交易标识（运行输入快照）**、智能体名称、应用类型、调用用户、状态、耗时、发生时间，支持筛选与分页
>   - 交易详情：该次运行的**节点执行视图**（每个节点的状态、开始/结束时间、耗时、失败原因）与**节点出入参可视化**（结构化展示每个节点的输入数据与输出数据）
>   - 交易详情：该次运行内的**模型调用明细**（模型名、状态、耗时、token）
>   - 运行输入快照与节点执行记录的数据采集（自上线起，不回填历史）
> - **本次明确排除**：
>   - 灵思智能体的节点/步骤级详情（执行体系与工作流不同，交易列表中可见其运行记录；详情另起 feature）
>   - 历史运行（上线前）的节点明细回填——探查确认运行结束后节点事件即被清理，无数据可回填
>   - 结构化业务字段抽取（如统一社会信用代码等指定字段的配置与结构化筛选）——本期交易标识 = 输入快照；结构化字段另起 feature
>   - 阈值告警 / 通知推送、监控数据导出（F046 已排除，本期同样不做）
>   - 自动实时轮询；交易列表仅展示已结束的运行（支持手动刷新）

## 1. 用户故事

作为 **平台管理员 / 应用负责人**，
我希望 **在日志页的智能体监控页签中按交易查看每次智能体调用的业务标识（输入快照）、状态与耗时**，
以便 **知道是哪笔业务在什么时间调用了哪个智能体、结果如何，快速定位问题交易**。

作为 **平台管理员 / 应用负责人**，
我希望 **点击一条交易进入详情，看到该次运行中每个节点的执行状态、输入与输出参数**，
以便 **定位失败节点、理解数据在各节点间的流转，排查智能体输出异常**。

作为 **平台管理员**，
我希望 **在交易详情中看到该次运行内的模型调用明细（模型、状态、耗时、token）**，
以便 **排查模型调用失败与性能/成本问题**。

## 2. 验收标准

> 口径说明：「一次交易」= 智能体的一次运行（一轮用户交互）。同一会话多轮交互产生多条交易，每条交易的标识为该轮的输入快照。

### 2.1 数据采集

- **AC-01** — WHEN 一次工作流型智能体（工作流 / 助手 / 工作站）运行结束, THE SYSTEM SHALL 在该运行的遥测记录中持久化**输入快照**（该轮用户问题文本或表单提交值的文本化摘要；截断至 200 字符）。
- **AC-02** — WHEN 智能体运行中某个节点开始执行, THE SYSTEM SHALL 持久化一条节点执行记录（交易标识、节点 ID、节点名称、开始时间）。
- **AC-03** — WHEN 智能体运行中某个节点结束执行, THE SYSTEM SHALL 持久化其结束记录（状态：成功/失败、结束时间、失败原因（如失败）、输入数据、输出数据）。
- **AC-04** — IF 节点执行记录持久化失败, THEN THE SYSTEM SHALL 仅记录日志并继续执行智能体，不影响该次运行的结果与既有的聊天链路。
- **AC-05** — 节点执行记录 THE SYSTEM SHALL 独立存储；既有聊天历史接口的返回内容保持不变（不出现节点执行记录）。
- **AC-06** — IF 节点输入/输出数据中含有大对象（如文件二进制/Base64 内容）, THEN THE SYSTEM SHALL 只记录摘要或引用（文件名/路径/类型），不记录完整二进制；单节点输入/输出记录各不超过 64KB（超限截断）。

### 2.2 交易列表（按交易监控）

- **AC-07** — WHEN 管理员打开智能体监控页签, THE SYSTEM SHALL 按时间倒序分页展示交易记录，每条包含：交易标识（输入快照）、智能体名称、应用类型、调用用户、状态（成功/失败）、耗时、发生时间；默认时间范围近 7 天。
- **AC-08** — WHEN 管理员按智能体 / 应用类型 / 状态 / 时间范围 / 交易关键词筛选, THE SYSTEM SHALL 返回符合条件的交易记录。
- **AC-09** — WHEN 一次运行包含多次模型调用, THE SYSTEM SHALL 在交易列表中只展示一条交易记录（不按内部模型调用重复计数）。
- **AC-10** — IF 智能体已被删除, THEN THE SYSTEM SHALL 仍可查询其历史交易记录（显示记录中的名称快照）。
- **AC-11** — WHEN 管理员点击刷新, THE SYSTEM SHALL 重新拉取交易列表；列表仅展示已结束的运行（成功/失败），最新完成的运行出现在列表顶部（运行中的运行在结束后进入列表）。

### 2.3 交易详情（节点执行视图与出入参）

- **AC-12** — WHEN 管理员点击一条交易, THE SYSTEM SHALL 展示该次运行的节点执行视图：每个节点的名称、状态（运行中/成功/失败）、开始时间、结束时间、执行耗时、失败原因（如失败）。
- **AC-13** — WHEN 管理员点击某个节点, THE SYSTEM SHALL 以结构化方式可视化展示该节点的输入数据与输出数据。
- **AC-14** — WHEN 一次运行包含模型调用, THE SYSTEM SHALL 在交易详情中展示模型调用明细（模型名、状态、耗时、token 消耗）。
- **AC-15** — IF 交易只有运行级数据（无节点记录，如上线前的历史运行）, THEN 交易详情 SHALL 展示运行级信息与模型调用明细，并提示「该运行无节点明细（早于采集上线时间）」。
- **AC-16** — IF 智能体在运行后被修改/删除, THEN 该历史交易的节点视图 SHALL 仍按已持久化的节点记录展示，不因智能体当前版本变化而丢失或错位。

### 2.4 权限与租户隔离

- **AC-17** — WHERE 多租户开启, THE SYSTEM SHALL 仅返回当前租户的交易记录与节点明细（与 F046 调用日志口径一致）。
- **AC-18** — IF 用户无日志菜单权限（log）, THEN THE SYSTEM SHALL 不展示智能体监控页签，且相关接口返回无权限。

## 3. 边界情况

- 输入快照超长（>200 字符）时截断展示，详情中可查看完整输入（如数据存在）。
- 同一会话多轮交互：每轮一条交易，交易标识为该轮输入快照。
- 节点开始后进程中断（无结束记录）：该节点在视图中显示为「运行中」并标注记录不完整，不影响其他节点展示。
- 单次运行节点数量大（如数百节点）：交易详情按记录渲染，不设节点数上限（以真实数据为准）。
- 交易时间范围上限 90 天（与 F046 调用日志一致），超过返回参数错误。
- 灵思智能体交易：列表中可见（运行级），详情仅展示运行级信息与模型调用明细，节点视图提示暂不支持。
