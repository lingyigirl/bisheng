# Feature: 知识库部门归属（057-knowledge-department-ownership）

> **本文档定位 — 纯 What（需求口径，不随代码漂移）**
>
> spec 只回答 **做什么 / 验收标准 / 不做什么**。
> **所有 How（决策、数据流、字段、API、Service、前端、文件清单、性能指标）一律不写在这里。**
> How 的唯一真相在 [design.md](./design.md)（接手必读）与 [tasks.md](./tasks.md)（执行流水）。

**关联 PRD**: 用户需求（2026-09-15）：组织知识库（文档库 / 问答库）需要归属到平台已有的部门树上，使「技术中心的库，技术中心及其下级部门的人都能用」。当前组织知识库的可见性只来自 ReBAC 授权与创建者本人，部门维度只能靠逐个部门展开成大量授权元组来模拟；元组在部门调整后不会重算，既会滞留越权访问，也会漏掉新建的部门。
**优先级**: P0
**所属版本**: v2.7.0
**依赖**: 无（基于既有知识库模块、部门树与权限体系扩展；不新增错误码）

> **范围边界**
> - **本次纳入**：
>   - **部门归属**：为组织知识库指定唯一归属部门，并支持取消归属
>   - **归属可见性**：归属部门的成员、以及其**各级下级部门**的成员，可读取该知识库
>   - **归属可视性调整**：修改归属后立即生效，无需重新同步任何授权元组
>   - **部门筛选视图**：知识库管理页左侧部门树可按部门筛选知识库，含子部门；并提供各节点知识库数量
>   - **归属维护入口**：通过接口设置/取消知识库归属，受管理权限约束
>   - **部门删除联动**：部门被删除/归档时，其名下知识库回到「未分类」
> - **本次明确排除**：
>   - 知识库归属到**多个**部门（本期一库一部门；多归属另起 feature）
>   - 知识库管理页的**归属编辑 UI**（本期只提供筛选视图；设置归属走接口，UI 后续补齐）
>   - 按部门控制**写**权限（本期归属只影响读取可见性，不影响编辑/删除/管理等权限）
>   - 复制知识库时的归属**编辑**（副本沿用源库归属，但不在复制流程里提供改归属的入口）
>   - 部门维度的**报表 / 统计页面**（本期只在树节点上给数量徽标）
>   - 对已有存量部门授权元组的自动清理（由运维脚本人工审核后执行，属迁移前置作业）

---

## 1. 用户故事

作为 **部门成员**，
我希望 **本部门及其下级部门的知识库出现在我的知识库列表里**，
以便 **不用等管理员逐个授权就能用到部门共享的知识资产**。

作为 **部门负责人 / 知识库管理员**，
我希望 **把某个知识库指派给一个部门后，该部门及其下级的成员立刻就能看到它，换部门时旧的部门立刻失去可见性**，
以便 **组织调整（部门合并、拆分、改名）时知识库的可见范围跟着走，不用手工维护一堆授权**。

作为 **平台运营人员**，
我希望 **在知识库管理页按部门树浏览，并能看到每个部门下有多少个知识库**，
以便 **快速盘点「哪个部门有多少知识资产」「哪些库还没有归类」**。

## 2. 验收标准

### 2.1 归属可见性

- **AC-01** — WHEN 知识库被指派给部门 D, THE SYSTEM SHALL 部门 D 的成员可读取该知识库。
- **AC-02** — WHEN 知识库被指派给部门 D, THE SYSTEM SHALL 部门 D 的**各级下级部门**成员可读取该知识库（归属向下传递）。
- **AC-03** — IF 用户所属部门是 D 的**上级**部门, THEN THE SYSTEM SHALL 不授予该知识库的读取权限（方向守卫：只向下，不向上）。
  > **v2.7.0 F062 回写（2026-09-21）**：本条原同时禁止**同级兄弟**部门的横向可见性。F062 引入「机构域」概念后，**同一机构域内**的横向部门之间可见（见下 AC-03a），本条相应收窄为只约束**向上**方向。嵌套机构构成边界，该边界由 F062 AC-12 保证。
- **AC-03a**（**v2.7.0 F062 引入**，随 F062 AC-25 回写）— IF 用户所属部门与 D 同级、或为 D 的叔伯部门，且二者处于**同一机构域**内（该机构域的定义与判定以 **F062 spec §2.2 的规则口径**为准，本条不另立解释）, THEN THE SYSTEM SHALL 授予该知识库的读取权限。
- **AC-03b**（**v2.7.0 F062 引入**，随 F062 AC-25 回写）— IF D **是**用户所属部门所在机构域之下的嵌套机构，或**位于**该嵌套机构之内及之下, THEN THE SYSTEM SHALL 不授予该知识库的读取权限。
- **AC-04** — IF 知识库未指派部门, THEN THE SYSTEM SHALL 其可见性维持现状（由既有 ReBAC 授权与创建者本人决定），既不被放大也不被收窄。
- **AC-05** — THE SYSTEM SHALL 不把归属规则应用于知识空间（`knowledge_space`）与个人知识库；二者沿用各自既有的可见性口径。
- **AC-06** — WHEN 管理员修改知识库归属, THE SYSTEM SHALL 新归属立即生效、旧归属立即失效，无需重新同步任何授权元组。
- **AC-07** — WHEN 用户加入或离开某部门, THE SYSTEM SHALL 该用户对部门归属知识库的可见性随之立即变化。
- **AC-08** — WHERE 多租户开启, THE SYSTEM SHALL 归属与可见性判定限定在当前租户内，不跨租户生效。

### 2.2 部门筛选视图

- **AC-09** — WHEN 用户在知识库管理页选择一个部门节点, THE SYSTEM SHALL 列表只展示归属该部门及其各级下级部门的知识库。
- **AC-10** — WHEN 用户选定某部门节点, THE SYSTEM SHALL 页面明确显示当前生效的筛选范围（由树中该行的高亮呈现），并提供回到「全部」的入口。
- **AC-11** — WHEN 用户选择「全部」, THE SYSTEM SHALL 列表恢复为不按部门筛选的完整结果。
- **AC-12** — THE SYSTEM SHALL 在部门树的每个节点上展示该部门（含下级部门）的知识库数量；数量为 0 时不显示。
- **AC-13** — THE SYSTEM SHALL 只统计当前用户**有权限看到**的知识库，用户无权访问的知识库不得从数量上被推断出来。
- **AC-14** — WHEN 用户打开知识库管理页, THE SYSTEM SHALL 默认选中该用户的主部门；用户没有主部门时保持不筛选。
- **AC-15** — IF 选定的部门已不存在或已被归档, THEN THE SYSTEM SHALL 返回空结果，**不得**降级为「不筛选」而把整租户的知识库都展示出来。
- **AC-16** — THE SYSTEM SHALL 对平台管理员同样应用部门筛选（管理员选中部门节点时列表同样收窄）。

### 2.3 归属维护

- **AC-17** — IF 操作者不是管理员且不具备该知识库的管理权限, THEN THE SYSTEM SHALL 拒绝设置或取消归属。
- **AC-18** — IF 操作者不是管理员, THEN THE SYSTEM SHALL 只允许把知识库指派给自己所属部门**子树内**的部门。
- **AC-19** — WHEN 操作者取消知识库归属, THE SYSTEM SHALL 该知识库回到未分类状态，可见性退回既有 ReBAC 授权口径。
- **AC-20** — IF 指定的目标部门不存在, THEN THE SYSTEM SHALL 拒绝该次指派。
- **AC-21** — THE SYSTEM SHALL 只允许对文档库与问答库设置归属；知识空间与个人知识库不可指派。

### 2.4 部门删除联动

- **AC-22** — WHEN 部门被删除, THE SYSTEM SHALL 其名下知识库回到未分类状态，不再显示任何部门归属。
- **AC-23** — WHEN 部门被归档, THE SYSTEM SHALL 其名下知识库回到未分类状态，且其成员不再因该部门获得这些知识库的可见性（归档即失效，与成员、部门角色随归档一并清理的既有口径一致）。
- **AC-24** — IF 知识库的归属部门已不存在, THEN THE SYSTEM SHALL 该知识库不产生任何部门派生可见性，且列表与筛选视图不报错。

### 2.5 复制行为

- **AC-25** — WHEN 用户复制一个已归属部门的知识库, THE SYSTEM SHALL 副本沿用源库的归属部门。

---

## 3. 边界情况

- 部门树为空 / 用户不属于任何部门 → 不产生任何部门派生可见性，全部退回既有 ReBAC 口径。
- 知识库归属部门已被删除（悬空归属）→ 行为上与「未分类」一致；不报错、不授权。
- 部门 ID 形如 `/1/2/` 与 `/1/20/` → 前缀比较不得把前者误判为后者的祖先。
- 用户同属多个部门 → 任一部门命中归属链即可见。
- 选定的部门下没有任何知识库 → 返回空列表（不是报错，也不是全量）。
- 知识库列表分页与部门筛选叠加 → 分页游标必须与筛选条件一致，不得出现「翻页后筛选失效」。
- 归属变更与列表读取并发 → 不要求强一致快照，但不得出现「归属已改、旧部门长期仍可见」。

**已知缺口（本期不做，记录待另行处理）**

- 部门树上**没有**显式的「未分类」节点，无法直接盘点无归属的知识库，只能靠清除筛选间接看到。是否补充为产品决定，见 design.md §5。
- 知识库管理页**没有归属编辑 UI**：设置/取消归属目前只有接口（AC-17~AC-21），页面只提供筛选视图。UI 补齐另起任务。
