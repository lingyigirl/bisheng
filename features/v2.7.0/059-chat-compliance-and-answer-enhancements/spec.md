# Feature: 对话合规与回答区增强（平台强制词库 · 评价留痕 · 关联问题 · 友情提醒）

> **本文档定位 — 纯 What（需求口径，不随代码漂移）**
>
> spec 只回答 **做什么 / 验收标准 / 不做什么**。
> **所有 How（决策、数据流、字段、API、Service、前端、文件清单、性能指标）一律不写在这里。**
> How 的唯一真相在 [design.md](./design.md)（接手必读）与 [tasks.md](./tasks.md)（执行流水）。

**关联 PRD**: 用户需求（2026-09-17）：广西信贷系统对接的四项对话能力需求——
①（原文 #3）敏感词监测：用户每次提问语句都需匹配信贷系统维护的敏感词库，命中则 AI 自动回复固定话术；
②（原文 #4）问答评价：每条 AI 回答下方嵌入点赞/差评按钮，并留痕每次评价记录；
③（原文 #5）场景热词/关联问题提示：每次 AI 回答下方自动展示相关场景热词列表与关联问题列表（两类内容，经确认分列展示）；
④（原文 #6）友情提醒：每次 AI 回答下方增加「本回答由AI生成，内容仅供参考，请仔细甄别」。

**现状评估**（2026-09-17 全链路盘点）：需求 ①② 的**检测链路**已由 v2.7.0 F056-llm-guardrail 实现（AC 自动机、对话输入拦截、流式输出截断/打码、命中日志、双入口覆盖），需求 ①②的**缺口**在于：词库无管理能力（现仅为策略表单里的一个自定义词表文本框）、检测为租户级可关、评价只存「当前状态」而非「每次操作」；需求 ③④ **全库无任何实现**（既有 `recommend_question` 是知识库 QA 扩写用途且前端零调用）。
**优先级**: P0
**所属版本**: v2.7.0
**依赖**: F056-llm-guardrail（对话围栏链路：`ChatGuardService` / 命中日志表 / 平台安全围栏页）、F055-risk-compliance-knowledge（检索构建入口 `retrieve_knowledge_documents` 与标签体系）

> **范围边界**
> - **本次纳入**：
>   - **平台级强制敏感词库**：超管维护的全局词库（单库），支持词条级管理（分页列表 / 搜索 / 单条增删）与批量导入（覆盖 / 追加两种模式）
>   - **强制生效**：平台级策略独立于租户策略，对所有租户、所有对话入口、输入与输出双向无条件生效；租户管理员不可关闭或修改
>   - **命中来源可辨**：命中日志区分来源（租户策略 / 平台强制），平台来源的命中词不向租户暴露内容
>   - **问答评价留痕**：追加式评价事件记录（谁、何时、对哪条回答、什么评价，含取消与改评），供租户与超管分别查询
>   - **场景热词**：从当轮用户提问与 AI 回答中提取关键词 / 实体，异步展示于该条回答下方（不依赖知识库绑定）
>   - **关联问题**：基于本轮问答从应用绑定的知识库检索并凝练为追问列表，异步展示于该条回答下方
>   - **友情提醒**：每条 AI 回答下方的固定免责提示（三语文案）
> - **本次明确排除**：
>   - **语义级内容安全检测**（谐音、上下文语义、变形绕过）——F056 已排除，本期同样不做；关键词实时检测为第一道
>   - **信贷系统直连同步**（词库推送接口 / 定时拉取）——本期词库内容由人工在平台导入，不提供对外同步 API
>   - **词条的属性化管理**（生效期、优先级、分类、启用位）——本期为单库单套配置，词条只承载词本身
>   - **场景热词与关联问题的落库与历史回看**——两者均仅当轮会话内展示，刷新或重载历史不重现
>   - **热词 / 关联问题的用户反馈闭环**（如「这些问题有用吗」）——本期只展示与点击，不采集效果数据
>   - **场景热词的运营预配**——本期热词由当轮问答实时提取，不提供平台侧「场景 → 热词清单」的配置能力
>   - **场景热词的独立知识库来源**——热词不检索知识库（区别于关联问题）；以知识库标签充当场景热词的方案本期不采用
>   - **评价数据的导出报表**——本期提供查询页，不提供 Excel 导出；导出另起 feature
>   - **多模态内容检测**（图片、语音文本化、文件）——一期仅检测对话文本
>   - **友情提醒的文案配置与关闭开关**——固定三语文案，服务端无配置项
>   - **租户侧对平台词库内容的任何可见性**——不提供「查看被拦截的是哪个词」的能力
>   - 知识库文件解析与订阅文章两个既有敏感词场景（F036）的行为改造

## 1. 用户故事

作为 **平台管理员（超管）**，
我希望 **在平台维护一份全局敏感词库并批量导入信贷系统下发的词表，配置命中后的动作与统一话术**，
以便 **在任意租户、任意对话入口上强制落实信贷内容合规要求，而不依赖各租户自行配置**。

作为 **租户管理员**，
我希望 **在本租户的命中日志中看到「某用户某时刻被拦截」这一事实（含来源标注），但看不到具体命中了哪个词**，
以便 **在被用户问起时能确认拦截确实发生、不是系统故障，同时不泄露平台词库内容**。

作为 **最终用户**，
我希望 **输入违规内容时得到明确一致的提示，并且能对每条回答点赞/点踩，还能在回答下方看到本轮涉及的场景热词与可继续追问的关联问题**，
以便 **理解平台边界、反馈回答质量、快速抓住回答要点并顺着思路继续提问**。

作为 **业务负责人 / 审计方**，
我希望 **每一次评价操作（含取消与改评）都留痕、可查询**，
以便 **复盘回答质量与用户满意度，且能还原用户的真实操作轨迹而非仅最终状态**。

## 2. 验收标准

> **相对需求原文的口径扩展（2026-09-17 经用户确认）**：需求原文 #3 仅要求检测「用户每次提问语句」（输入方向）；
> 本 spec 扩展为**输入 + 输出双向**强制（输出动作可配截断 / 打码），理由是同一份信贷词库对模型输出同样具有合规约束力。
>
> 需求原文 #5 的「场景热词」与「关联问题」为**两类独立内容**，本期分别实现（§2.5 场景热词 / §2.6 关联问题）：
> 热词 = 从当轮问答中提取的关键词/实体（不依赖知识库）；关联问题 = 从应用绑定知识库检索并凝练出的追问句。
> 二者在回答下方**同区展示、顺序固定**（热词在上、关联问题在下），点击行为一致（填入输入框，不自动发送）。

### 2.1 平台级词库管理

- **AC-01** — WHEN 平台管理员在平台维护全局词库, THE SYSTEM SHALL 提供词条级管理能力：分页列表、关键词搜索、单条新增、单条删除。
- **AC-02** — WHEN 平台管理员批量导入词表文件, THE SYSTEM SHALL 支持选择「覆盖」或「追加」两种模式：覆盖 = 导入后词库内容等于文件内容；追加 = 仅新增文件中有而库中没有的词条，不删除既有词条。
- **AC-03** — WHERE 导入模式为覆盖, THE SYSTEM SHALL 在落库前展示差异预览（新增 N 条 / 删除 M 条 / 去重 K 条），仅在管理员确认后才执行。
- **AC-04** — WHEN 导入词表文件, THE SYSTEM SHALL 容错解析：支持 txt / csv / xlsx；词条分隔符为换行、逗号、分号、竖线（中英文标点均可）；忽略空行与重复词条；文件含表头行时忽略表头。
- **AC-05** — IF 导入文件为空、无法解析、或解析后无有效词条, THEN THE SYSTEM SHALL 拒绝该次导入并返回错误码 11301，词库保持导入前状态（不产生部分写入）。
- **AC-06** — IF 非平台管理员的用户访问全局词库的管理能力, THEN THE SYSTEM SHALL 拒绝访问（管理入口不展示，直接调用接口返回拒绝，不授予任何词库读写）。
- **AC-07** — WHEN 平台管理员新增/删除词条或完成一次导入, THE SYSTEM SHALL 修改立即生效于后续检测，无需重启服务。

### 2.2 强制生效与检测

- **AC-08** — WHERE 平台级词库策略处于启用状态, THE SYSTEM SHALL 对全部租户的对话入口生效；租户管理员**无法**关闭该策略、无法修改其词表、命中动作与话术。
- **AC-09** — WHEN 用户输入命中平台级词库, THE SYSTEM SHALL 不执行该轮对话（不调用模型），并立即以平台配置的命中话术作为该轮回复返回给用户。

> **初始话术口径**（需求原文指定，作为平台侧配置的**初始值**，平台管理员可修改；租户侧不可改）：
> 「很抱歉，你的提问包含敏感词，系统无法做出判断。如果您有其他问题或需要帮助，欢迎随时告诉我，我会尽力为您提供支持」
- **AC-10** — WHERE 平台级策略的输出动作配置为截断, IF 模型流式输出命中平台级词库, THEN THE SYSTEM SHALL 在命中词开始处停止后续输出，并以平台话术收尾该轮回复。
- **AC-11** — WHERE 平台级策略的输出动作配置为打码, IF 模型流式输出命中平台级词库, THEN THE SYSTEM SHALL 将命中词替换为等长 `*` 后继续输出，不中断生成。
- **AC-12** — WHEN 同一段文本同时命中平台级词库与租户侧词表, THE SYSTEM SHALL 以平台级词库的判定与话术为准，不再套用租户策略的话术。输入方向命中即短路（不执行该轮）；输出方向在同一检测决策点内平台优先，且以双方命中位置中**最早者**作为截断点（不得因平台优先而把租户策略本应拦下的内容原样输出）。
- **AC-13** — IF OpenAI 兼容接口（`POST /api/v2/chat/completions`）的输入命中平台级词库, THEN THE SYSTEM SHALL 返回 HTTP 400 与错误码 11201，响应体携带平台话术。
- **AC-14** — IF 平台级词库为空或平台级策略未启用, THEN THE SYSTEM SHALL 该层不做任何检测，租户策略与全部对话入口的行为与未发布本特性时完全一致。
- **AC-15** — WHEN 平台管理员在对话进行中修改词库, THE SYSTEM SHALL 后续轮次使用新词库检测；已开始的流式输出沿用变更前的判定，不中断、不中途改写。
- **AC-16** — WHERE 多租户开启, THE SYSTEM SHALL 全部租户使用同一份平台词表与同一套动作、话术，检测口径一致。

### 2.3 命中日志

- **AC-17** — WHEN 命中由平台级词库产生, THE SYSTEM SHALL 在命中日志中记录该次命中的来源为「平台」，与租户策略命中可区分。
- **AC-18** — WHEN 租户管理员查看本租户命中日志, THE SYSTEM SHALL 展示平台来源的命中记录（时间、方向、应用、动作、命中次数），但**不返回命中词条内容**（租户侧界面据此可自证拦截已发生，但无法据此还原词库）。
- **AC-19** — WHEN 租户管理员查看本租户命中日志, THE SYSTEM SHALL 对租户策略来源的命中记录沿用既有展示口径（含命中词与次数）。
- **AC-20** — WHEN 平台管理员查看命中日志, THE SYSTEM SHALL 可查询全部租户的命中记录，并可按来源（平台 / 租户）筛选。

### 2.4 问答评价留痕

- **AC-21** — 每条 AI 回答下方 THE SYSTEM SHALL 提供点赞与差评两个操作入口（沿用既有按钮形态与位置），且入口覆盖全部 AI 回答展示界面。
- **AC-22** — WHEN 用户对某条 AI 回答提交评价、取消评价、或由一种评价改为另一种, THE SYSTEM SHALL 追加一条评价事件，记录：操作人、租户、消息 ID、所属应用、评价类型、变更前值、变更后值、时间。
- **AC-23** — WHEN 用户在点踩流程中提交了原因文本, THE SYSTEM SHALL 将该原因回填至本次点踩对应的那条评价事件。
- **AC-24** — IF 评价事件写入失败, THEN THE SYSTEM SHALL 不影响评价主流程（点赞/点踩的既有生效与按钮状态照常，仅告警）。
- **AC-25** — WHEN 租户管理员查询评价明细, THE SYSTEM SHALL 返回本租户的评价事件，并支持按时间、应用、评价类型筛选。
- **AC-26** — WHEN 平台管理员查询评价明细, THE SYSTEM SHALL 返回全部租户的评价事件。
- **AC-27** — IF 用户提交的评价与其当前状态相同（无实际变更）, THEN THE SYSTEM SHALL 不追加评价事件。
- **AC-28** — 评价的既有交互 THE SYSTEM SHALL 保持不变：点赞即时生效、点踩先弹出原因框且提交后才落库、取消不弹框、按钮高亮随历史加载回填；评价事件为增量记录，不改变上述任一行为。

### 2.5 场景热词

- **AC-29** — WHEN 一条 AI 回答生成完成, THE SYSTEM SHALL 从该轮的用户提问与 AI 回答中提取关键词 / 实体，作为场景热词异步展示于该条回答下方。
- **AC-30** — 场景热词的提取与推送 THE SYSTEM SHALL 不阻塞、不延迟该轮回答的流式输出。
- **AC-31** — WHEN 用户点击一个场景热词, THE SYSTEM SHALL 将其文本填入输入框，**不自动发送**；用户可修改后再发送。
- **AC-32** — IF 场景热词提取失败、超时或结果为空, THEN THE SYSTEM SHALL 不展示该区域，且不向用户展示任何错误或提示。
- **AC-33** — IF 未配置场景热词生成所使用的模型, THEN THE SYSTEM SHALL 不展示场景热词区域。
- **AC-34** — 场景热词 THE SYSTEM SHALL 不依赖知识库绑定；未绑定知识库的对话同样展示（区别于关联问题）。
- **AC-35** — 场景热词 THE SYSTEM SHALL 仅在当轮会话内展示；刷新页面或重新加载历史会话时不再重现。
- **AC-36** — 场景热词 THE SYSTEM SHALL 不进入对话历史、不随会话存档（同 AC-35）。
- **AC-37** — 场景热词 THE SYSTEM SHALL 不包含命中平台级词库的词条内容（被拦截轮次不输出热词）。

### 2.6 关联问题

- **AC-38** — WHEN 一条 AI 回答生成完成, THE SYSTEM SHALL 基于该轮问答内容，从该对话所属应用绑定的知识库中检索并凝练出一组关联问题，异步追加展示于该条回答下方。
- **AC-39** — 关联问题的生成与推送 THE SYSTEM SHALL 不阻塞、不延迟该轮回答的流式输出。
- **AC-40** — WHEN 用户点击一条关联问题, THE SYSTEM SHALL 将其文本填入输入框，**不自动发送**；用户可修改后再发送。
- **AC-41** — IF 关联问题生成失败、超时或结果为空, THEN THE SYSTEM SHALL 不展示该区域，且不向用户展示任何错误或提示。
- **AC-42** — IF 该应用未绑定知识库，或未配置关联问题所使用的模型, THEN THE SYSTEM SHALL 不展示关联问题区域。
- **AC-43** — 关联问题 THE SYSTEM SHALL 仅在当轮会话内展示；刷新页面或重新加载历史会话时不再重现。
- **AC-44** — WHERE 知识库存在权限或标签范围限制, THE SYSTEM SHALL 仅使用当前对话用户可见范围内的内容生成关联问题。
- **AC-45** — 关联问题 THE SYSTEM SHALL 不进入对话历史、不随会话存档（同 AC-43）。

### 2.7 友情提醒

- **AC-46** — 每条 AI 回答下方 THE SYSTEM SHALL 固定展示友情提醒文案「本回答由AI生成，内容仅供参考，请仔细甄别」。
- **AC-47** — WHEN 界面语言切换为中/英/日, THE SYSTEM SHALL 友情提醒以对应语言的文案展示。
- **AC-48** — 友情提醒 THE SYSTEM SHALL 不可由租户管理员或平台管理员配置、修改或关闭。
- **AC-49** — WHEN 场景热词、关联问题与友情提醒展示于同一条回答下方, THE SYSTEM SHALL 按「场景热词 → 关联问题 → 友情提醒」的固定顺序排列；友情提醒的位置不因前两者的异步到达而改变。

### 2.8 覆盖面与兼容性

- **AC-50** — 评价入口、场景热词、关联问题与友情提醒 THE SYSTEM SHALL 覆盖全部 AI 回答展示界面（首页对话、知源、订阅、应用对话、灵思）。
- **AC-51** — IF 处于分享（只读）视图, THEN THE SYSTEM SHALL 沿用既有口径不展示评价按钮、场景热词与关联问题，但**仍然展示友情提醒**（分享视图为对外可及的回答内容，缺失免责提示的合规风险更高）。
- **AC-52** — 本特性 THE SYSTEM SHALL 不改变知识库文件解析与订阅文章两个既有敏感词场景（F036）的行为。
- **AC-53** — IF 平台级策略未启用且租户未配置任何对话策略, THEN THE SYSTEM SHALL 全部对话入口的行为与发布前完全一致。

## 3. 边界情况

- 导入文件与词库完全一致 → 差异预览显示新增 0 / 删除 0，不产生写入，视为成功。
- 导入过程中词库被另一端修改 → 以确认时刻的实际状态执行，预览数据仅作参考（一致性口径指向 design.md）。
- 同一输入同时命中平台词库的多个词 → 全部记录进命中日志；动作按平台策略统一执行。
- 流式输出命中的词横跨两个分片 → 沿用 F056 的跨分片增量检测口径，仍能命中。
- 平台词库在流式生成中途被修改 → 该轮流式沿用变更前判定；下一轮起用新词库（AC-15）。
- 平台强制拦截与租户策略同时可能命中 → 平台优先，租户策略不参与该决策点的判定（AC-12）。
- **流式输出下跨分片的优先级边界**：租户策略输出动作为「截断」且租户词先于平台词出现时，已输出的分片不可回退，该轮以租户话术收尾（平台词尚未到达即已终止）。此为流式的固有约束——要让平台词跨分片也绝对优先，只能改为缓冲整段输出再检测，代价是首字延迟不可接受。**双方动作均为打码时不触发此边界**（打码不中断流，后续平台命中照常生效）。
- 平台词库在某个分片内与租户词同时命中且动作为截断 → 截断点取两者中更早的位置，话术用平台的（保证既不泄露、也不放过租户策略本应拦下的内容）。
- 输出被平台词库截断后用户再提问 → 新一轮独立判定，不受上一轮截断影响。
- 场景热词提取超时或为空 → 静默丢弃，不重试、不占位、不提示（AC-32）；关联问题同理（AC-41）。
- 热词 / 关联问题所用模型返回非法 JSON 或多余解释文本 → 视为生成失败，静默丢弃。
- 用户在热词 / 关联问题到达前已发出下一轮提问 → 仍挂在其所属的那条回答下方，不与后一轮错位。
- 热词与关联问题先后到达（两次异步推送） → 各自插入自己的位置，顺序恒定不变（AC-49）。
- 热词提取出的词与关联问题文本重复 → 两者独立展示，不做去重（分属不同控件与语义）。
- 本轮回答被平台级词库拦截（输入命中，无模型输出） → 不产生热词与关联问题（无可提取内容，且 AC-37 禁止泄露命中词条）。
- 应用绑定了知识库但本轮检索无命中 → 关联问题为空则静默不展示，不影响热词展示。
- 会话被删除或消息被删除后再查询评价明细 → 事件行仍保留（事件表只存消息 ID，不级联删除）。
- 用户短时间内连续切换评价（赞→取消→踩） → 三条事件均保留，顺序按时间可还原。
- 点踩原因提交时找不到对应的点踩事件（如网络重试、跨端操作） → 原因不丢失：作为独立记录补写或忽略，以不报错为准（口径指向 design.md）。
- 平台词库为空但策略为启用态 → 该层不检测（AC-14），不报错。
- 超管查询命中日志时的跨租户范围 → 沿用既有超管跨租户查询口径，不做逐租户拆表。
