## 1. 用户故事

作为 **银行信贷人员**，
我希望 **上传客户的征信报告 PDF 后自动生成五段式征信分析报告**，
以便 **快速掌握客户信用全貌并识别风险点，支撑授信审查**。

## 2. 验收标准

| ID | 操作 | 预期结果 |
|----|------|---------|
| AC-01 | 客户端打开「征信分析智能体」并上传 1 个文本版征信报告 PDF | 正常生成五段式报告（信息概要 / 信贷记录明细 / 对外担保分析 / 公共信息分析 / 综合信用评价与风险预警） |
| AC-02 | 上传扫描版（图片型）征信报告 PDF | 自动走 MinerU OCR 回退并同样生成五段式报告 |
| AC-03 | 上传多个 PDF 文件 | 多个文件内容合并分析，生成一份报告 |
| AC-04 | 不传文件直接提交 | 返回明确提示（未收到文件）而非报错崩溃 |
| AC-05 | 报告中的关键数字（机构数/金额/笔数/逾期天数/查询次数等） | 与原文一致；原文未体现的字段标注「报告未体现」，不编造 |
| AC-06 | 综合信用评价章节 | 给出评级（五级：低风险/较低风险/中等风险/较高风险/高风险）+ 风险预警条目 + 可执行的风控措施；含「内部参考、不构成授信决策依据」提示 |
| AC-07 | 超长报告（>2.8 万字符） | 截断至上限并在报告注明截断情况，不静默丢尾 |
| AC-08 | MinerU OCR 服务不可用且 PDF 无文本层 | 返回「解析失败，请更换清晰的文本版报告」类明确错误，不输出编造内容 |

## 3. 边界情况

- 报告为 Word/图片等非 PDF 格式：表单 file_type=all 允许上传；code 节点仅处理 PDF，非 PDF 尝试文本直读，失败按 AC-08 报错
- 同一客户多份报告：合并分析，重复内容由 LLM 归纳
- LLM1 提取输出超长：截断提示在 LLM2 侧以「部分数据未纳入」注明

## 4. 设计与实现（指针）

- 工作流结构：start → input(表单：征信报告文件) → code「报告文本提取」→ llm「结构化数据提取」(output_user=false) → llm「征信分析报告生成」(output_user=true) → end
- 模型：deepseek-v4-flash-无思考（llm_model id=17，规避推理模型思考风暴，同会议纪要口径）
- 创建方式：以「智能审查智能体」(flow 4202a401d08345be92e4eba2fae01eed) 为 JSON 模板改造后 `POST /api/v1/workflow/create`（201）→ `PATCH /api/v1/workflow/update/{id} {status:2}` 上线
- e2e：合成征信报告 PDF（reportlab 生成）走全流程验证五段输出与数字忠实性
