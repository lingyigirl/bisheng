# Feature: 流水分析智能体（F050）

> 小功能 track：配置级新增工作流智能体实例（与 F048 征信分析 / F049 财务分析智能体同模式）。无跨 Feature 契约变更、无新增领域对象。

**关联 PRD**: 会话需求（2026-09-01）：新增流水分析智能体——上传企业银行流水（图片/PDF/Excel），自动识别提取流水关键信息，完成流水概览、收支结构分析、大额及异常交易筛查、偿债能力测算，并给出结论与授信建议。
**优先级**: P0
**所属版本**: v2.7.0
**依赖**: 无（复用工作流引擎；文本提取/OCR 回退代码与 F048/F049 共用同一实现，新增 Excel/图片解析分支）

> **范围边界**
> - **本次纳入**：
>   - 新建工作流应用「流水分析智能体」并上线
>   - 表单上传银行流水文件（图片/PDF/Excel/CSV，可多文件；可选填贷款本金/年利率/期限/企业主营业务）
>   - 文本 PDF 直读 + 扫描件/图片 MinerU OCR 回退 + Excel（openpyxl/xlrd）读取
>   - 两段式：LLM 提取流水明细 JSON（逐笔交易：本方/对手方户名账号、交易日期时间、金额方向、交易摘要等）→ **code 节点自动计算**流水概览指标、收支结构、异常交易筛查（机械规则）、偿债能力测算 → LLM 生成六段式报告
>   - 六段式输出：流水信息提取概览 / 流水概览 / 收支结构分析 / 大额及异常交易筛查 / 偿债能力测算 / 结论与授信建议
> - **本次明确排除**：
>   - 流水数据入库 / 知识库留存（临时文件分析后即弃，同 F048 口径）
>   - 银行流水格式的字段级标准化输出（本期输出为报告文本，仅供人工阅读）
>   - 异常交易认定的监管口径（规则筛查为提示性线索，最终判断以行内制度为准——报告模板中明示）
>   - 多期（跨年）长序列建模（本期支持流水覆盖期内分析，通常 3-12 个月）

## 1. 用户故事

作为 **银行信贷人员**，
我希望 **上传企业银行流水后自动完成信息提取、指标计算、异常筛查与偿债测算**，
以便 **快速判断企业经营状况与流水真实性，支撑授信决策，无需手工逐笔筛查**。

## 2. 验收标准

| ID | 操作 | 预期结果 |
|----|------|---------|
| AC-01 | 上传银行流水文件（PDF 文本版 / Excel / 图片，任一格式） | 自动识别提取流水信息（本方户名账号、对手方户名账号、交易日期、交易金额、交易摘要等）并生成六段式报告 |
| AC-02 | 上传扫描版/图片型流水 | 自动走 MinerU OCR 回退并同样生成六段式报告 |
| AC-03 | 流水概览章节 | 指标由 code 节点计算而非 LLM 心算：总收入、总支出、净流入、期末余额、日均余额、总笔数、日均笔数；**计算口径与数值可核对** |
| AC-04 | 收支结构分析章节 | 收入/支出结构拆解（按摘要关键词机械归类+LLM 语义修正）、经营收入占比、月净收入、净现金流入（流入/流出比），按流水覆盖期给出月度序列 |
| AC-05 | 大额及异常交易筛查章节 | 机械规则筛查快进快出（同对手方相近金额 N 日内进出）、整数交易、深夜交易（23:00-5:59）、分拆规避（同日同对手方多笔小额拼大额）、大额交易；与主业无关交易由 LLM 结合主营业务语义判断；逐项给出笔数/金额/明细 |
| AC-06 | 偿债能力测算章节 | 可支配现金流估算（经营净流入月均值）与贷款本息月供对比，给出覆盖倍数；未填贷款参数时给出按假设条件的测算口径提示，不编造 |
| AC-07 | 结论与授信建议章节 | 覆盖流水造假等风险点（快进快出、整进整出、余额突变、对手方集中、摘要与主业不符、夜间异常等）识别与预警，给出具体风控措施 + 流水综合评价 + 授信建议（含「内部参考、不构成授信决策依据」提示） |
| AC-08 | 不传文件直接提交 | 返回明确提示（未收到文件）而非报错崩溃 |
| AC-09 | 超长流水 | 截断至上限并注明，不静默丢尾 |
| AC-10 | OCR 不可用且文件无文本层 | 返回明确解析失败提示，不编造内容 |

## 3. 边界情况

- 多文件混合格式（PDF+Excel+图片）：合并分析，重复账户流水由 LLM 归集
- Excel 多 sheet / 表头不规范（手工流水表）：LLM 提取阶段做字段名归一（金额列方向按「收入/支出」「贷/借」等口径判断）
- 流水行含「合计」「小计」「承前页」等非交易行：LLM 提取阶段剔除，code 复核（无日期/无对手方行不计入）
- LLM 提取 JSON 不合法：code 容错解析（截取首尾大括号），仍失败则报告注明「数据提取失败，无法计算指标」，不静默
- 余额列缺失：期末余额取最后一笔可得余额，日均余额用可得余额均值，报告注明口径
- 交易时间缺失（仅日期）：深夜交易筛查仅对含时间的记录生效，报告注明覆盖范围

## 4. 设计与实现（指针）

- 工作流结构：start → input(表单：流水文件 + 可选贷款参数) → code「流水文件解析」→ llm「流水数据提取」(output_user=false, 严格 JSON) → code「流水指标计算」→ llm「流水分析报告生成」(output_user=true) → end
- 模型：deepseek-v4-flash-无思考（llm_model id=17，同 F048/F049 口径）
- 创建方式：F049 同款模板改造（**创建 JSON 内直接写对表单**，Flow.data 是客户端渲染与运行时的唯一数据源，创建后无法通过 API 更新 data 字段——F048/F049 表单缺陷已由 2026-09-02 DB 直改修复）→ `POST /api/v1/workflow/create`（201）→ `PATCH /api/v1/workflow/update/{id} {status:2}` 上线
- e2e：合成银行流水（openpyxl 生成 Excel 流水 + 图片变体）走全流程，核对 code 计算数值与六段式输出、异常筛查命中、偿债测算
