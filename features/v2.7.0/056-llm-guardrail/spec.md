# Feature: 大模型安全围栏（056-llm-guardrail）

> **本文档定位 — 纯 What（需求口径，不随代码漂移）**
>
> spec 只回答 **做什么 / 验收标准 / 不做什么**。
> **所有 How（决策、数据流、字段、API、Service、前端、文件清单、性能指标）一律不写在这里。**
> How 的唯一真相在 [design.md](./design.md)（接手必读）与 [tasks.md](./tasks.md)（执行流水）。

**关联 PRD**: 用户需求（2026-09-07）：平台内置敏感词策略与内容监测过滤机制，实现大模型对话**输入输出数据的实时监测与过滤**。现状评估结论：平台已有完整敏感词策略基础设施（v2.6.0 F036，AC 自动机 + 策略表 + 内置词表），但仅接入「知识库文件解析」「订阅文章」两个场景，**LLM 对话输入/输出围栏为空白**，本 feature 补齐该缺口。
**优先级**: P0
**所属版本**: v2.7.0
**依赖**: 无（扩展 v2.6.0 F036 既有 `sensitive_word` 模块与对话链路；不依赖本版本其他 feature）

> **范围边界**
> - **本次纳入**：
>   - **对话输入敏感词策略**：租户级策略（开关 / 内置词表 / 自定义词表 / 命中话术），与输出策略独立配置
>   - **输入实时检测与拦截**：用户在任一对话入口发送的消息命中敏感词时，本轮对话不执行、不调模型，立即返回配置话术
>   - **对话输出敏感词策略**：租户级策略，支持「截断 + 话术收尾」（block）与「敏感词打码继续输出」（mask）两种动作
>   - **流式输出实时检测**：模型生成按流式分片增量检测，命中即截断/打码，跨分片截断的词也能命中
>   - **命中监测日志**：输入/输出命中均落日志（方向、应用、命中词与次数、动作、时间），平台侧可查询
>   - **平台设置页**：租户管理员可视化配置输入/输出策略与查看命中日志
> - **本次明确排除**：
>   - **语义级内容安全检测**（谐音、上下文语义、变形绕过）——关键词实时检测为第一道；语义检测设计为可插拔 provider，二期另立
>   - **应用（flow）级独立策略**——一期仅租户级（沿用 F036 既有作用域）；flow 级作用域二期
>   - **仅审计不拦截（action=audit）**——一期动作只有 block / mask；audit 二期
>   - **历史会话回扫、存量数据检测**——只对检测点之后的对话生效
>   - **多模态内容检测**（图片、文件、语音文本化）——一期仅检测对话文本；知识库文件解析场景沿用 F036 既有能力，不在本 feature 范围
>   - 知识库文件解析与订阅文章两个既有场景的行为改造（F036 能力不动，仅共享同一策略基础设施）

## 1. 用户故事

作为 **平台管理员**，
我希望 **在平台配置租户级的对话输入/输出敏感词策略（词表、动作、话术），并查看命中监测日志**，
以便 **满足内容安全合规要求，且配置可自主调整、不依赖开发**。

作为 **最终用户**，
我希望 **输入违规内容时得到即时、明确的话术提示，而不是静默失败或看到违规输出**，
以便 **理解平台边界并修正输入，对话体验不被破坏**。

作为 **智能体构建者 / 业务负责人**，
我希望 **所有对话入口（助手、工作流、OpenAI 兼容接口）都受同一套敏感词围栏保护，模型输出不含违规内容**，
以便 **降低合规风险，无需在每个应用中自行实现过滤**。

## 2. 验收标准

> **范围限定（2026-09-17 由 F059 引入 INV-10 后回写）**：以下 AC-02 / AC-04 / AC-17 描述的是**租户策略层**的行为。
> 当平台侧配置了**平台级强制词库**（F059）且其处于启用态时，该层**独立于本 spec 的租户策略无条件生效**，
> 且优先级高于租户策略（同一输入双方皆命中时以平台层为准）。即：这三条 AC 的「完全一致 / 不做任何检测 / 相互隔离」
> 均以「平台级强制词库未启用」为前提。详见 [release-contract INV-10](../release-contract.md) 与 [F059 spec](../059-chat-compliance-and-answer-enhancements/spec.md)。

### 2.1 策略配置与管理

- **AC-01** — WHEN 租户管理员在平台「大模型安全围栏」设置页配置对话输入/输出敏感词策略（启用开关、词表类型、自定义词表、命中话术、输出动作）, THE SYSTEM SHALL 保存为租户级策略，输入与输出方向各自独立配置。
- **AC-02** — IF 某方向策略未启用或生效词表为空, THEN THE SYSTEM SHALL 该方向不做任何检测与改写，对话行为与未发布本特性时完全一致（**除平台级强制词库外**，见上文范围限定）。
- **AC-03** — WHEN 管理员修改策略（词表 / 动作 / 话术）, THE SYSTEM SHALL 修改立即生效于后续对话，无需重启服务。
- **AC-04** — WHERE 多租户开启, THE SYSTEM SHALL 各租户策略相互隔离，检测仅使用本租户词表（**除平台级强制词库外**，其词表为全部租户共享，见上文范围限定）。

### 2.2 输入检测与拦截

- **AC-05** — WHEN 用户在任一对话入口（助手 / 工作流 WebSocket 聊天、OpenAI 兼容接口 `POST /api/v2/assistant/chat/completions`）发送的消息命中输入策略敏感词, THE SYSTEM SHALL 不执行该轮对话（不调用模型），并立即以配置话术作为该轮回复返回给用户。
- **AC-06** — IF 输入未命中, THEN THE SYSTEM SHALL 正常执行该轮对话并返回模型结果，回复内容与未开启策略时一致。
- **AC-07** — IF 输入命中, THEN THE SYSTEM SHALL 写入一条输入方向命中日志（时间、租户、应用、用户、命中词与次数、动作）。
- **AC-08** — IF OpenAI 兼容接口的输入命中, THEN THE SYSTEM SHALL 返回 HTTP 400 与错误码 11201，响应体携带配置话术。

### 2.3 输出检测（流式实时）

- **AC-09** — WHERE 输出策略开启, THE SYSTEM SHALL 对模型生成文本按流式分片实时检测，检测使用输出方向独立配置的词表与动作。
- **AC-10** — WHEN 流式输出中检测到敏感词（含被分片边界截断的词）, THE SYSTEM SHALL 在命中词所在分片处停止后续输出，并以配置话术收尾该轮回复。
- **AC-11** — WHERE 输出动作配置为打码（mask）, THE SYSTEM SHALL 将命中词替换为等长 `*` 后继续输出，不中断生成。
- **AC-12** — IF 输出未命中, THEN THE SYSTEM SHALL 输出文本与未开启策略时逐字一致（检测过程对用户不可见、无改写）。
- **AC-13** — IF 输出命中, THEN THE SYSTEM SHALL 写入一条输出方向命中日志（时间、租户、应用、命中词与次数、动作）。
- **AC-14** — WHERE OpenAI 兼容接口以流式方式（`stream=true`）返回生成结果, THE SYSTEM SHALL 输出分片按输出策略实时检测，命中后的截断 / 打码行为与 WebSocket 流式对话一致（同 AC-10 / AC-11 口径）。

### 2.4 命中监测日志

- **AC-15** — WHEN 管理员在平台安全围栏页面查看命中日志, THE SYSTEM SHALL 可按时间 / 方向 / 应用筛选查看命中记录（展示命中词、次数、动作等摘要信息，不展示完整对话内容）。
- **AC-16** — IF 命中日志写入失败, THEN THE SYSTEM SHALL 不影响对话主流程（检测与拦截行为照常，仅告警）。

### 2.5 兼容性

- **AC-17** — IF 租户未配置任何对话围栏策略, THEN THE SYSTEM SHALL 所有对话入口（WebSocket / OpenAI 兼容接口）行为与发布前完全一致（**除平台级强制词库外**，见 §2 开头的范围限定）。
- **AC-18** — 知识库文件解析与订阅文章两个既有敏感词场景（F036）THE SYSTEM SHALL 行为不变，与对话围栏共享策略基础设施但互不影响。

## 3. 边界情况

- 敏感词恰好横跨两个流式分片 → 增量检测状态跨分片保持，仍能命中（实现口径指向 design.md 决策 3）。
- 一条消息 / 一段输出命中多个敏感词 → 全部记录进命中日志；动作按策略统一执行（mask 动作下所有命中词均打码）。
- 输出命中截断发生在词中间 → 整词替换/截断，不输出半个敏感词。
- 用户在输出截断前主动停止（stop）→ 停止后的剩余流不再检测。
- 词表为空、策略未启用 → 检测跳过，零开销（AC-02 的兜底口径）。
- 检测依赖的运行时异常（策略读取失败、日志写入失败）→ 对话主流程不中断：输入检测异常按放行处理、输出检测异常按原样输出、日志失败仅告警（可观测口径指向 design.md §7）。
- 同一轮对话中的非文本消息（如中间步骤、状态帧）→ 仅对文本内容分片与最终回复检测。
