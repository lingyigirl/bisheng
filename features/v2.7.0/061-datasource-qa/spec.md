# Feature: 数据库知识问答（数据源接入 · NL2SQL · 对话侧混合来源）

> **本文档定位 — 纯 What（需求口径，不随代码漂移）**
>
> spec 只回答 **做什么 / 验收标准 / 不做什么**。
> **所有 How（决策、数据流、字段、API、Service、前端、文件清单、性能指标）一律不写在这里。**
> How 的唯一真相在 [design.md](./design.md)（接手必读）与 [tasks.md](./tasks.md)（执行流水）。

**关联 PRD**: 用户需求（2026-09-17）：「想添加从数据库中获取知识库进行问答」。
经 Spec Discovery（2026-09-17 全链路盘点 + 逐项确认）收敛为——数据源以**配置方式**接入（库与表均由管理员配置），
经 **NL2SQL 实时查询**回答，并作为**对话侧可用的知识来源**与既有文档知识库并列。

**现状评估**（2026-09-17 全链路盘点）：
平台**已存在一个 NL2SQL 能力**，但位置与形态均不满足本需求——
`bisheng_langchain/gpts/tools/sql_agent/tool.py` 的 `SqlAgentTool`（ReAct 套 LangChain `SQLDatabaseToolkit`，
系统提示硬编码「只读 SELECT、≤50 行」），配置入口是**工作流 Agent 节点内的一个内联勾选项**
（`SqlConfigItem.tsx` → `agent.py:146 SqlAgentParams`），DB 密码**明文存于流程配置**；
其 `arun` 直接委托同步 `run`（`tool.py:75-76`），会阻塞事件循环。
连带的既有资产：预制应用「⭐️SQLAgent」「⭐️ 查询数据库并画图」；未被任何调用方使用的
`bisheng_langchain/sql/base.py:15 SQLDatabaseChain`（text-to-SQL 链）。
**缺口**：无数据源领域对象（全仓无连接实体、无 Alembic 迁移）、`KnowledgeTypeEnum` 只有
`NORMAL/QA/PRIVATE/SPACE` **四值且无数据库类型**、知识库模块**无任何 DB 连接器**、
工作流**无独立 SQL 节点**、客户端（`/workspace`）**完全没有数据库问答入口**。

**优先级**: P0
**所属版本**: v2.7.0
**依赖**: 开发基线 = 本特性所在的**项目交付集成基线**（该基线上已叠加 F045 / F056 / F058 / F059 等特性，特性间为线性叠加而非各自独立分支）。
被本特性实际读用的上游能力：
- **F056-llm-guardrail** — 对话链路的输入/输出缝合点（数据库回答文本同样应受既有关卡约束）
- **F059-chat-compliance-and-answer-enhancements** — 回答区的引用/附属信息展示位（引用锚点需与之共存不冲突）
- **F004-rebac-core**（**跨版本，v2.5.0**）— 平台授权模型与统一权限入口；本特性在其授权模型中**新增一类数据源资源类型**，并按 v2.5.0 INV-15 完成权限接入（创建登记归属、变更前校验）。这是本特性唯一跨越版本边界的对象写入
- **F005-role-menu-quota**（**跨版本，v2.5.0**）— 菜单权限机制，承载数据源的独立管理权限点
- **既有 LLM 槽位机制**（`tenant_system_model_config`，含 Root 租户回退）— 承载本特性新增的 SQL 生成模型槽位
- **既有知识库检索工具的形态** — 仅作为「数据源以同层工具形态呈现」的**参照**，本特性**不修改**知识库任何对象、检索链路与授权形状

> **范围边界**
> - **本次纳入**：
>   - **数据源领域对象**：管理员以配置方式接入外部数据库（连接信息 + 暴露的表清单），凭据加密存储，多租户隔离
>   - **表结构元数据治理**：建源时采集表/字段快照，管理员补业务描述，支持手动重新采集
>   - **NL2SQL 实时查询**：提问时由模型基于表结构生成 SQL，实时执行并基于结果作答
>   - **查询安全护栏**：单条 SELECT 白名单、行数与超时限制、只读会话、执行留痕
>   - **对话侧接入**：数据源可作为助手 / 工作台 / 客户端的知识来源被选用，与文档知识库**同一轮内共存**
>   - **混合来源回答与引用**：一条回答内可同时呈现文档与数据库两类来源，引用可定位到表与 SQL
>   - **查询可复核**：SQL 与结果表随回答持久化，用户可展开查看
>   - **失败治理闭环**：生成失败自动重试，失败提问留档供管理员反哺表描述
>   - **工作流侧收敛**：Agent 节点由「内联填写连接信息」改为「选择已建数据源」，兼容既有流程
>   - **独立权限点**：数据源作为新的受控资源类型纳入统一授权
> - **本次明确排除**：
>   - **把数据库数据抽取灌入向量库**（快照式 RAG）——本特性为**实时查询**，数据库数据不切块、不向量化、不落 Milvus/ES
>   - **扩展知识库类型枚举**（`KnowledgeTypeEnum` 新增数据库类型）——数据源为独立领域对象，不进知识库体系
>   - **平台强制的行级数据过滤**——本期数据可见范围 = 所配置数据库账号的权限范围，平台不注入行级条件、不做 AST 绕过校验；**此项为显式安全风险，见 §3**
>   - **公有的数据源**（全员可见）——数据源无 PUBLIC 语义；授权为显式授予用户/用户组
>   - **表级授权与逻辑分组**——授权粒度只到数据源，不到表
>   - **跨租户共享与部门归属**——不参与 root 共享，不引入部门归属语义
>   - **手写 SQL 作为虚拟表**——不允许管理员保存一段 SQL 当作可查询对象
>   - **裸连接串输入**——不提供 JDBC URL / DSN 粘贴入口
>   - **表结构定时自动重采集**——改为手动触发 + 漂移时提示
>   - **表内真实数据采样**（把样例值喂给模型）——本期不做，避免真实业务数据进入提示词
>   - **独立的数据源检索工作流节点**——工作流侧只经 Agent 节点使用
>   - **SQLite 支持**
>   - **SQL 执行前的人工确认**——不做用户侧 SQL 审阅确认
>   - **多表联合的预设语义层 / 指标口径配置**——本期只到「表 + 字段」的业务描述，不建指标/维度/度量语义层
>   - **查询结果的图表化展示与导出**——本期为可折叠的表格式结果
>   - **对既有预制应用（「⭐️SQLAgent」等）的功能改造**——是否随本特性更新留待后续

## 1. 用户故事

作为 **平台/租户管理员**，
我希望 **以配置方式接入一个外部业务数据库、勾选要开放的表，并为表与字段补上业务描述**，
以便 **让不具备 SQL 能力的业务人员能够直接用自然语言问到库里的数据，而不必每次找数据部门取数**。

作为 **业务人员（终端用户）**，
我希望 **在与 AI 的同一个对话框里，既能问文档里的规定、也能问数据库里的数字，并看清答案分别来自哪里**，
以便 **一次提问就把「制度是怎么规定的」和「实际数据是多少」对上，不必在两个系统之间来回切换**。

作为 **业务人员（终端用户）**，
我希望 **回答里能展开看到本次实际执行了什么查询、取回了哪些数据**，
以便 **在把数字报给他人之前能够自行核对，而不是只能选择相信**。

作为 **数据治理 / 运维负责人**，
我希望 **每一次查询都可追溯（谁、何时、查了哪个数据源的哪张表、执行了什么语句），且被拒绝或失败的提问能被收集起来**，
以便 **在出现数据误用时能定位到人，并能据此发现哪些表的结构描述还需要补充**。

作为 **安全 / 合规负责人**，
我希望 **平台接入生产库时只持有只读能力、不提供全员可见的数据源、且凭据不以明文存储或回显**，
以便 **在开放数据查询能力的同时，把最坏情况限制在「查到不该查的行」而不是「改坏数据」**。

## 2. 验收标准

> **相对需求原文的口径扩展（2026-09-17 经用户逐项确认）**：
> 需求原文仅为「从数据库中获取知识库进行问答」。本期将其收敛为**实时 NL2SQL**（而非把数据抽取灌入向量库），
> 并明确其为**独立领域对象**（而非知识库的新类型）；对话侧要求**与文档知识库在同一轮内共存**（混合来源为硬性需求，非副作用）。
> 连接信息与暴露的表**均由管理员配置**接入，凭据按平台既有加密口径存储。

### 2.1 数据源管理与连接配置

- **AC-01** — WHEN 管理员创建数据源, THE SYSTEM SHALL 采集：名称、数据库引擎、连接信息（主机、端口、库名、账号、密码），并提供**测试连接**能力。
- **AC-02** — THE SYSTEM SHALL 支持以下数据库引擎：MySQL、PostgreSQL、GaussDB、Oracle、DB2、达梦（DM8）。
- **AC-03** — WHEN 管理员发起测试连接, THE SYSTEM SHALL 返回可判定的结果（成功 / 失败及失败原因），**失败不产生任何落库写入**。
- **AC-04** — 数据源的连接凭据 THE SYSTEM SHALL 加密存储；**任何读取响应 SHALL NOT 返回密码明文**，任何列表/详情/日志 SHALL NOT 回显密码。
- **AC-05** — IF 所配置的数据库账号具备写权限, THEN THE SYSTEM SHALL 在保存时给出明确警告，但**允许管理员继续保存**（不阻断）。
- **AC-06** — IF 数据源配置为 SQLite, THEN THE SYSTEM SHALL 拒绝创建（该引擎不在支持范围内，且其文件路径会成为隐式权限边界）。
- **AC-07** — THE SYSTEM SHALL NOT 提供「保存一段 SQL 作为可查询对象」的能力，THE SYSTEM SHALL NOT 提供裸连接串（JDBC URL / DSN）输入入口。
- **AC-08** — WHEN 管理员修改数据源的连接信息或表清单, THE SYSTEM SHALL 立即对后续查询生效，无需重启服务。

### 2.2 表结构元数据治理

- **AC-09** — WHEN 数据源连接成功后, THE SYSTEM SHALL 列出该库中当前账号可访问的表，供管理员**勾选**纳入暴露范围。
- **AC-10** — WHEN 管理员确认表选择, THE SYSTEM SHALL 采集并持久化所选表的表名、字段名、字段类型与**库内注释**的快照。
- **AC-11** — 管理员 SHALL 能为数据源中的每一张已暴露的表维护**业务描述**（供模型理解该表承载什么业务含义）。
- **AC-12** — WHEN 管理员触发**重新采集**, THE SYSTEM SHALL 重新读取表结构并更新快照；管理员已填写的业务描述 SHALL NOT 被重采集覆盖。
- **AC-13** — 表结构采集 THE SYSTEM SHALL NOT 读取表内真实数据行（不采样样例值）。
- **AC-14** — IF 某数据库引擎的库内注释无法被自动采集, THEN THE SYSTEM SHALL 仍然建源成功，对应的字段描述留空并由人工补充；**该限制 SHALL 在界面上向管理员明示**，不得静默留空。
- **AC-15** — THE SYSTEM SHALL NOT 对已建数据源的表结构做定时轮询（无自动重采集）。

### 2.3 查询执行与安全护栏

- **AC-16** — WHEN 系统执行模型生成的语句, THE SYSTEM SHALL **仅放行单条 SELECT 语句**；多语句、非查询语句一律拒绝。
- **AC-17** — IF 语句包含数据修改、结构变更、授权变更或**加锁读取**（如 `FOR UPDATE`）, THEN THE SYSTEM SHALL 拒绝执行。
- **AC-18** — 每一次查询 THE SYSTEM SHALL 受**返回行数上限**与**执行超时**约束；超出上限时截断结果并**在结果上标注已截断**。
- **AC-19** — 查询 THE SYSTEM SHALL 在只读会话下执行；**IF 目标数据库不支持只读会话, THEN THE SYSTEM SHALL 降级执行并记录该次降级**。
- **AC-20** — IF 语句无法被平台的解析器识别该方言, THEN THE SYSTEM SHALL 退化为关键字级的窄校验（**不得**因「解析失败」而拒绝执行），并记录该次降级。
- **AC-21** — 查询执行 THE SYSTEM SHALL NOT 阻塞对话主链路；单次查询的耗时 SHALL NOT 使同一进程内的其他对话请求排队等待。
- **AC-22** — WHEN 系统执行一次查询, THE SYSTEM SHALL 留存执行记录：操作人、租户、数据源、涉及的表、执行的语句、执行结果状态与时间。
- **AC-23** — 上述执行记录 THE SYSTEM SHALL NOT 包含查询返回的数据内容（只记语句与状态，不记结果集；见 AC-65）。

### 2.4 对话侧接入与模型选路

- **AC-24** — 管理员 SHALL 能将数据源配置为助手 / 工作台的可用知识来源。
- **AC-25** — WHEN 用户在一个已选择数据源的会话中提问, THE SYSTEM SHALL 由模型**自主判断**是否需要查询该数据源；系统 SHALL NOT 在对话链路上做强制的前置路由判定。
- **AC-26** — 数据源 THE SYSTEM SHALL 以**可被模型调用的工具**形态呈现，与文档知识库检索处于**同一调用层**（同一轮内模型可自由选择其一或两者）。
- **AC-27** — 生成查询语句所用的模型 THE SYSTEM SHALL 来自一个**独立的模型槽位**；该槽位的取值 SHALL 满足 INV-8（本租户内可见，且其模型类型与该槽位匹配）。IF 该槽位未配置, THEN THE SYSTEM SHALL 回退使用该轮对话的模型，且**不报错**。
- **AC-28** — WHERE 数据源暴露的表描述总量在上限内, THE SYSTEM SHALL 将该数据源的完整表结构提供给模型；IF 超出上限, THEN THE SYSTEM SHALL 退化为按当前问题检索相关表的描述。**两种形态 SHALL 可被区分观测**（可判定本次注入走的是全量还是检索），以便该上限被验证与调优。上限的具体取值属实现参数，不在本 spec 约定。
- **AC-29** — WHEN 模型决定查询数据源, THE SYSTEM SHALL 在回答中**明示数据来源**（来自哪个数据源 / 哪些表），不得把数据库结果与文档内容混为一谈而不加区分。

### 2.5 混合来源与引用

- **AC-30** — WHEN 一次提问同时命中文档知识库与数据源, THE SYSTEM SHALL 在**一条回答内**同时呈现两类来源的内容，并在回答中区分标注各自的出处。
- **AC-31** — 数据库来源的引用锚点 THE SYSTEM SHALL 包含**表名与本次执行的语句**。
- **AC-32** — WHEN 用户展开一条数据库相关回答, THE SYSTEM SHALL 展示本次执行的语句与结果表；默认状态为**收起**。
- **AC-33** — 结果表 THE SYSTEM SHALL 支持下载。
- **AC-34** — WHEN 用户重新加载会话历史或换端查看, THE SYSTEM SHALL 仍能展开该条历史回答的语句与结果表（即二者随回答持久化）。
- **AC-35** — 结果表落库 THE SYSTEM SHALL 复用执行期的行数上限，**不引入第二套裁剪规则**。
- **AC-36** — IF 该轮回答未查询任何数据源, THEN THE SYSTEM SHALL NOT 展示数据库相关的引用、语句与结果表区域（不占位、不展示空态）。

### 2.6 失败处理与治理闭环

- **AC-37** — IF 查询执行失败（含语句语法错误、字段不存在、权限不足、超时）, THEN THE SYSTEM SHALL 将数据库返回的错误信息回喂给模型并允许其修正后重试。
- **AC-38** — 上述自动重试 THE SYSTEM SHALL 有次数上限（**不超过 3 轮**），达到上限即停止。
- **AC-39** — IF 重试后仍然失败, THEN THE SYSTEM SHALL 向用户返回可理解的失败说明；返回内容 SHALL NOT 暴露数据库内部结构、连接信息、账号或原始错误堆栈。
- **AC-40** — 上述失败 SHALL NOT 中断该轮对话的其他能力：若同一轮内文档知识库有命中，THE SYSTEM SHALL 仍以文档内容正常作答。
- **AC-41** — WHEN 一次查询在重试后仍然失败, THE SYSTEM SHALL 为管理员留存该次失败的**语句与错误类别摘要**（**不存结果集数据、不存用户提问原文**——遵守 INV-11 / INV-19 的留痕存储边界）。
- **AC-42** — 管理员 SHALL 能查看失败提问清单，并据此补全对应表的业务描述。

### 2.7 权限与授权

- **AC-43** — 数据源 THE SYSTEM SHALL 作为一种**新的受控资源类型**纳入平台统一的资源授权体系，**与知识库同级**（相等地位，非其子类型）。
- **AC-44** — 数据源 SHALL 有**独立的权限点**用于控制「谁能创建 / 管理数据源」，与知识库的管理权限相互独立。
- **AC-45** — 数据源默认 SHALL 仅创建者可见；SHALL 支持显式授权给指定用户与用户组。
- **AC-46** — 数据源 SHALL NOT 提供「全员可见 / 公有」选项。
- **AC-47** — 数据源 SHALL NOT 参与跨租户共享，SHALL NOT 引入部门归属语义。
- **AC-48** — 授权粒度 THE SYSTEM SHALL 到**数据源级**；THE SYSTEM SHALL NOT 提供表级授权。
- **AC-49** — IF 用户未被授权某数据源, THEN 该数据源 SHALL NOT 出现在该用户可选的来源列表中；直接调用相关接口 SHALL 被拒绝。
- **AC-50** — 数据源 THE SYSTEM SHALL 按租户隔离：跨租户不可见、不可用、不可授权。
- **AC-51** — 平台 THE SYSTEM SHALL NOT 对查询结果施加行级过滤；用户可见的数据行范围**等于所配置数据库账号在该库中的权限范围**（此为经确认显式接受的风险，见 §3）。
- **AC-52** — WHEN 用户可访问的数据源集合发生变化（授权或取消授权）, THE SYSTEM SHALL 在此后的对话轮次中按新集合生效。

### 2.8 工作流侧

- **AC-53** — 工作流 Agent 节点 THE SYSTEM SHALL 由「内联填写数据库连接信息」改为「**选择一个已建数据源**」。
- **AC-54** — WHEN 一个既有流程中仍配置着旧的**内联**数据库连接信息, THE SYSTEM SHALL 使其**继续正常运行**（兼容读取），不因本特性而中断。
- **AC-55** — 本特性 THE SYSTEM SHALL NOT 新增独立的数据源检索工作流节点。
- **AC-56** — THE SYSTEM SHALL NOT 允许通过内联配置**新建**数据库连接（内联入口只保留对既有流程的兼容读取）。

### 2.9 前端覆盖面

- **AC-57** — 平台侧（管理端）THE SYSTEM SHALL 提供：数据源的创建与编辑、测试连接、表勾选、表描述维护、重新采集、授权管理、失败提问清单。
- **AC-58** — 客户端（终端用户对话界面）THE SYSTEM SHALL 提供：数据源的选择、回答中的来源标注、引用锚点、语句与结果表的展开与下载。
- **AC-59** — 平台侧与客户端 THE SYSTEM SHALL 提供**等价**的数据库问答能力（客户端不得因分属不同应用而缺失引用与展开能力）。

### 2.10 兼容性与不变量

- **AC-60** — IF 租户未创建任何数据源, THEN 全部既有对话、工作流、知识库行为 SHALL 与发布前完全一致。
- **AC-61** — 数据源 THE SYSTEM SHALL NOT 进入知识库的类型枚举，SHALL NOT 产生向量、SHALL NOT 创建向量库集合或检索索引。
- **AC-62** — WHEN 数据源被删除, THE SYSTEM SHALL 使其对后续对话立即不可用；已产生的历史回答、引用锚点与执行记录 SHALL 保持可读（不级联删除）。
- **AC-63** — 数据库问答的回答文本 THE SYSTEM SHALL 与既有对话回答遵守同一套对话合规约束（敏感词关卡、留痕口径等不受本特性影响）。
- **AC-64** — 本特性 THE SYSTEM SHALL NOT 修改知识库对象、知识库类型枚举、知识库检索链路与知识库授权形状的任何既有行为。
- **AC-65** — 数据源查询产生的执行记录与失败留档 THE SYSTEM SHALL 只存语句与状态摘要，SHALL NOT 存结果集数据、SHALL NOT 存用户提问原文（遵守 INV-11 的留痕存储边界，本特性不新增例外）。
- **AC-66** — 数据源作为一类受控资源，其创建与变更 THE SYSTEM SHALL 统一经由平台权限入口（创建时登记归属、变更前校验），SHALL NOT 绕过该入口直接判定权限。

## 3. 边界情况

- 管理员勾选的表在后续被数据库侧删除或改名 → 查询报错并进入失败路径（AC-37）；管理员可在表清单上看到该表已不可达。
- 管理员重新采集后表结构已变化（字段增删改），但业务描述仍在 → 描述保留，字段以新结构为准（AC-12）。
- 模型生成的语句在语法上正确但**引用了未暴露的表** → 视为查询失败并进入重试路径；重试仍失败则不执行、不越权访问。
- 同一轮内模型既查询数据源、又检索文档知识库 → 两类来源在一条回答内并存并分别标注（AC-30）。
- 同一轮内模型连续查询同一个数据源多次（如先探结构再取样） → 每次查询各自留痕（AC-22）；回答只展示最终采用的语句与结果。
- 结果集为空 → 正常作答并说明「未查询到数据」，不算失败、不进入重试。
- 查询超时或达到行数上限 → 以已取回的部分作答，并在结果上标注已截断（AC-18）；不进入重试路径。
- 数据源为达梦（DM8） → 库内注释可能无法自动采集，字段描述由人工补充（AC-14），界面须明示该限制。
- 数据源为达梦（DM8）且语句含方言特有语法 → 解析器可能无法识别，退化为窄校验而非拒绝（AC-20）。
- 所配置的数据库账号本身具备写权限 → 建源时警告但允许保存（AC-05）；平台的拒绝能力为兜底，只读边界以账号权限为首要防线。
- 同一轮问答中数据源被管理员删除或取消授权 → 该轮按失败路径处理（AC-37/AC-39），此后该数据源不再可选（AC-52）。
- 业务描述为空的数据源被提问 → 系统仍尝试生成查询；若失败则进入失败清单，形成「补充描述」的驱动信号（AC-41/AC-42）。
- 表描述总量超出注入阈值 → 退化为按问题检索相关表（AC-28）；检索未命中任何表时不发起查询，直接以其他来源作答。
- 用户在回答的展开区内看到语句后，后续数据已变化 → 展开区展示的是**查询当时**的语句与结果（快照），不随数据变化刷新（AC-34/AC-35）。
- 旧流程中的内联连接信息所连的库已不可达 → 行为与发布前一致（原有报错照旧），不因本特性额外拦截（AC-54）。
- **安全边界的显式声险**：本特性**不提供平台强制的行级过滤**。数据可见范围完全取决于「所配置的数据库账号在库中的权限」与「数据源被授权给了谁」两个外部因素。若管理员配置了一个高权限账号并将该数据源授权给了本不应看到全量数据的用户，**平台侧不存在任何拦截机制**。该风险在本期被显式接受，其缓解手段为授权治理（AC-45/AC-48/AC-49），而非技术强制。
