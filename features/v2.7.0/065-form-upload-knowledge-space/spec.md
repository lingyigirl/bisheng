# Feature: 表单上传组件的知识空间选择与本地文件归集（065-form-upload-knowledge-space）

> **本文档定位 — 纯 What（需求口径，不随代码漂移）**
>
> spec 只回答 **做什么 / 验收标准 / 不做什么**。
> **所有 How（决策、数据流、字段、API、Service、前端、文件清单、性能指标）一律不写在这里。**
> How 的唯一真相在 [design.md](./design.md)（接手必读）与 [tasks.md](./tasks.md)（执行流水）。
>
> 为什么这么切：How 写进 spec，实现一变 spec 就过时，而 spec 通常没人回头改 → 接手人被旧方案误导。
> spec 只承载需求口径，才能长期稳定、可被反复引用。
>
> **前置步骤**：本文档编写前必须已完成 Spec Discovery（架构师提问），PRD 中的不确定性已与用户对齐。

**关联 PRD**: 用户需求（2026-09-24）。三条需求的澄清共 9 项决策已与需求方逐条对齐（见 §2 各 AC 的分布与 §3 末条）：目标空间「应用文件」、空间不存在时自动创建、空间以**私有**可见性创建（**每人各自己的空间**）、文件夹名取「客户名称」字段否则回退应用名称、空值同样回退、去重接受整个空间的内容口径、重复静默跳过且不提示、文件夹在提交时统一创建、生效范围仅限表单上传组件。
**优先级**: P1
**所属版本**: v2.7.0
**依赖**: 无前置 Feature。只读复用知识空间既有能力（空间查询/创建、文件夹创建、子项列表、文件登记、文件下载地址）与应用对话既有的表单提交链路；不修改任何既有 Feature 的 AC。
**本特性不新增错误码。**

> **范围边界**（写清「明确不做什么」比写「做什么」更能防 scope 膨胀）
> - **本次纳入**：
>   - **知识空间选择入口**：表单上传组件新增「从知识空间选择文件」入口，弹层内按「知识空间 → 文件夹 → 文件」浏览并选择
>   - **单选/多选跟随字段配置**：选择器的可选数量跟随该表单字段的 `multiple` 配置——多选可多选、单选只能单选
>   - **统一产出**：知识空间选中的文件与本地选择的文件产出同一种语义的值，进入同一条既有提交通道，后端按既有逻辑处理
>   - **合并语义**：多选时重复添加为**合并追加**；单选时为**后选覆盖**
>   - **输入框去重**：多选时按**文件名**去重，输入框展示名与字段值一一对应且无重名
>   - **类型门槛与批量选择**：选择器内只允许选中该字段类型列表内的文件（AC-29）；多选时提供「全选 / 取消全选当前文件夹」与「清空全部已选」（AC-30 / AC-31），单选不提供（AC-32）
>   - **本地文件归集**：表单提交时，把本地上传的文件写入名为「应用文件」的知识空间下的目标文件夹；文件夹名取表单中「客户名称」字段值，缺字段或值为空时取应用名称
>   - **空间与文件夹的幂等**：用户可见范围内无「应用文件」空间则自动创建（**私有**），已存在则复用；目标文件夹已存在则复用不重建；内容重复的文件静默跳过（判定范围为**目标文件夹**，见 AC-20）
> - **本次明确排除**：
>   - **主对话输入区（聊天附件）的上传归集**：需求方明确生效范围仅限表单上传组件，聊天附件（`InputFiles`）的上传链路本次不动，其文件不归集（见 AC-24）
>   - **技能表单（会话报告生成表单）的改造**：它与目标表单**复用同一个文件控件**，故必须显式关闭新能力——不提供知识空间选择入口、不做文件归集、文件字段的既有行为不变（见 AC-28）
>   - **知识空间选中文件的复制归集**：只按引用使用，**不**在「应用文件」中另存一份，避免同一内容在空间内落两份
>   - **后端处理逻辑的改动**：输入节点对表单文件值的解析、下载、入库行为（含解析策略选择）保持原样。本特性对后端的唯一改动是给判重**新增一个可选作用域参数**（默认值与既有行为完全一致，见 AC-20 与 design 决策 11）——不改变任何既有调用方的判重口径
>   - **知识空间去重口径的改动**：接受后端既有的「按内容 md5、范围是整个知识空间」的判定，不改为「按文件夹」去重
>   - **重复文件的覆盖交互**：命中重复一律静默跳过，不提供「覆盖已有文件」的选择入口
>   - **跨用户共享与检索**：空间为私有、每人各自己的一份，本特性**不**提供跨用户共享归集文件的能力，也**不**保证他人上传的同内容文件对自己可见（见 AC-27 与 §3）
>   - **新增错误码**：拒绝与失败路径复用既有错误信封，不新增错误码模块
>   - **「应用文件」空间的可见性、成员与权限模型**：沿用知识空间既有模型（私有），本特性不定义新的授权口径，也不提供成员邀请
>   - **文件夹名的用户可见配置**：命名规则（客户名称 / 应用名称）为固定口径，不提供让用户自定义文件夹名的设置项
>   - **任务模式（灵思）的输入区**：其表单与上传链路为独立实现，本次不动

## 1. 用户故事

作为 **使用带表单上传的应用的用户**，
我希望 **直接复用知识空间里已经沉淀的文件，而不必每次从本机重新上传一份**，
以便 **省掉「下载到本地再上传」的往返，也避免同一份材料在系统里出现多个版本**。

作为 **需要一次提供多份材料、且可能分几次补齐的用户**，
我希望 **多次添加的文件是叠加保留的，并且重名的不会被塞进来两遍**，
以便 **能从容地分次挑选，而不会因为一次误操作把之前选好的都清掉**。

作为 **需要按客户/项目归档材料、并且只让自己看到这些材料的业务人员**，
我希望 **上传的附件自动按客户名称归到（我自己的）知识空间里对应的文件夹下**，
以便 **不用手工建目录、不用记文件传到了哪里；我自己后续按客户就能检索回来，同时材料不对外暴露**。

## 2. 验收标准

### 2.1 知识空间选择

- **AC-01** — WHEN 用户触发表单上传组件的「从知识空间选择」入口, THE SYSTEM SHALL 打开知识空间文件选择器，并允许按「知识空间 → 文件夹 → 文件」逐层浏览。
- **AC-02** — WHERE 该表单字段配置为多选, THE SYSTEM SHALL 允许在选择器中同时选中多个文件。
- **AC-03** — WHERE 该表单字段配置为单选, THE SYSTEM SHALL 在选择器中只允许选中一个文件。
- **AC-04** — WHEN 用户在选择器中确认选择, THE SYSTEM SHALL 把选中的每个文件写入该字段的值；该值与本地文件的取值语义一致，因而进入同一条既有提交通道、由既有的后端逻辑消费。
- **AC-05** — IF 用户未选中任何文件即关闭选择器, THEN THE SYSTEM SHALL 保持该字段已选内容不变。
- **AC-06** — THE SYSTEM SHALL 在选择器中只展示当前用户有权限访问的知识空间与文件；文件夹类型条目不可被选中。
- **AC-07** — IF 某个选中文件无法被解析为该字段可用的取值, THEN THE SYSTEM SHALL 不把该文件写入字段值，并提示该文件失败；其余已选文件照常写入。
- **AC-08** — WHERE 该表单字段配置为单选, THE SYSTEM SHALL 使知识空间选择器与本地文件选择两者都只能产生一个文件。
- **AC-29** — THE SYSTEM SHALL 在选择器中只允许选中**该字段自身声明的文件类型**内的文件；类型不符的文件条目不可被选中，并标明原因。字段未声明类型时不做此限制。（2026-09-24 需求方补充）
- **AC-30** — WHERE 该表单字段配置为多选, THE SYSTEM SHALL 在选择器中提供「全选当前文件夹」：把当前文件夹内**可被该字段接受**的文件全部加入已选；已选内容的其余部分（其他文件夹、其他空间）保持不变。该动作的作用范围是**当前已加载的条目**，不额外拉取未加载的分页。
- **AC-31** — WHERE 该表单字段配置为多选, THE SYSTEM SHALL 提供「取消全选当前文件夹」与「清空全部已选」两个入口：前者只移除当前文件夹内的已选文件，后者移除全部已选文件（含其他文件夹与空间）。
- **AC-32** — WHERE 该表单字段配置为单选, THE SYSTEM SHALL 不提供「全选」与「清空全部」入口（单选下全选无意义，取消已有「再次点击已选文件」的既有手势）。

### 2.2 合并与去重

- **AC-09** — WHERE 该表单字段配置为多选, WHEN 用户再次从知识空间选择或从本地上传文件, THE SYSTEM SHALL 把新文件**追加**到既有已选列表，而不是替换既有列表。
- **AC-10** — WHERE 该表单字段配置为多选, THE SYSTEM SHALL 按**文件名**对已选列表去重：与已选文件同名的文件不再重复加入，无论其来源是本地还是知识空间。
- **AC-11** — WHERE 该表单字段配置为单选, WHEN 用户再次从知识空间选择或从本地上传文件, THE SYSTEM SHALL 以最后一次选择为准，字段值只保留该文件。
- **AC-12** — WHEN 某个文件因重名被去重跳过, THE SYSTEM SHALL 保持该字段已选列表不变，且不阻断用户继续添加。
- **AC-13** — THE SYSTEM SHALL 在输入框中展示已选文件的名字（多选时以分隔符连接），展示名与字段值一一对应且不含重复名。

### 2.3 本地文件的归集

- **AC-14** — WHEN 用户提交表单且该表单包含本地上传的文件, THE SYSTEM SHALL 把每个文件字段的**本地上传**文件写入该用户自己的「应用文件」知识空间下的目标文件夹。
- **AC-15** — WHEN 该表单中存在显示名称为「客户名称」的字段，且其值去除首尾空白后非空, THEN THE SYSTEM SHALL 以该值作为目标文件夹名。
- **AC-16** — IF 该表单中不存在显示名称为「客户名称」的字段，或该字段值去除首尾空白后为空, THEN THE SYSTEM SHALL 以当前应用的名称作为目标文件夹名。
- **AC-17** — WHEN 目标文件夹已存在于「应用文件」空间的根目录下, THE SYSTEM SHALL 复用该文件夹，不重复创建。
- **AC-18** — WHEN 目标文件夹不存在于「应用文件」空间的根目录下, THE SYSTEM SHALL 创建该文件夹。
- **AC-19** — IF 当前用户可见范围内不存在名为「应用文件」的知识空间, THEN THE SYSTEM SHALL 先按 AC-27 创建该空间，再执行归集。
- **AC-20** — WHEN 待写入文件的内容在该用户的「应用文件」空间的**目标文件夹内**已存在, THEN THE SYSTEM SHALL 静默跳过该文件（保留该文件夹内的既有文件），且不向用户提示、不阻断提交。判定范围为**目标文件夹**：同一份内容存在于该空间的其他文件夹时，不构成重复、不影响本文件夹的写入（见 §3）。
- **AC-21** — THE SYSTEM SHALL 只归集本地上传的文件；从知识空间选中的文件不写入「应用文件」空间。
- **AC-22** — IF 归集过程中任一步失败（空间创建失败、文件夹创建失败或文件写入失败）, THEN THE SYSTEM SHALL 不阻断表单提交，并保留用户已填写的表单内容。
- **AC-23** — THE SYSTEM SHALL 不改变表单提交的通道与字段值语义：文件字段的值仍与本地文件同形，可被既有后端逻辑消费；单选时字段值只含该文件。
- **AC-24** — THE SYSTEM SHALL 不对主对话输入区（聊天附件）的本地上传文件做归集。
- **AC-25** — WHEN 同一表单中存在多个文件字段, THE SYSTEM SHALL 让它们各自独立归集，并共用同一个目标文件夹（文件夹名只由客户名称或应用名称决定，与字段无关）。
- **AC-26** — WHEN 当前用户可见范围内已存在名为「应用文件」的知识空间（含由用户自行创建的），THEN THE SYSTEM SHALL 复用该空间，不重复创建。
- **AC-27** — WHERE 「应用文件」知识空间由本特性自动创建, THE SYSTEM SHALL 以**私有**可见性创建它，使该空间及其文件仅对创建者（即当前用户）可读。
- **AC-28** — WHERE 该文件控件被**技能表单**（会话报告生成表单）复用, THE SYSTEM SHALL 不向其提供知识空间选择入口、不对其文件做归集，其文件字段的既有行为（含取值与提交通道）保持不变。

## 3. 边界情况

- 当「客户名称」字段存在但值为全空白时，按 AC-16 回退用应用名称；**不**用空白名建文件夹。
- AC-15 的「客户名称」匹配为**显示名称去首尾空白后的精确匹配**；不做大小写或别名的模糊匹配。
- 当应用名称本身也为空（异常数据）时，系统不做归集，且不阻断表单提交。
- 当文件夹名包含路径分隔符或文件系统保留字符时，系统不做静默改写；创建失败按 AC-22 处理（不阻断提交）。
- **AC-20 的判定范围是目标文件夹**（后端按内容 md5 或文件名判定，范围限定在该文件夹内）。因此同一份文件可同时存在于多个客户文件夹，**各存一份副本、各占一份存储与配额**——这是需求方 2026-09-24 明确选定并接受的代价（design 决策 11）。
- 该口径在 2026-09-24 经历了**一次收窄**：初版为「判定范围是整个『应用文件』空间」，需求方实测发现「同一份材料已在另一个客户文件夹时，本次目标文件夹会被判重跳过而变空」，遂改为按目标文件夹判定。
- **AC-20 与 AC-07 的「提示」口径分属两条不同路径**：AC-07 是「取用知识空间文件本身失败」时的即时反馈（在输入区，用户需要知道选不上），AC-20 是「归集写入时命中重复」的静默跳过（在提交之后，属于后台归档动作，不打扰用户）。二者不矛盾。
- **两处去重的口径不同，属预期行为**：输入框按文件名去重（同名即视为重复，不再加入），而空间内按内容判定（同名不同内容不会被跳过）。因此「同名不同内容的两个文件」在输入框侧进不来、在空间侧也不会被当成重复——二者的差异不构成缺陷。
- **空间为私有 ⇒ 每人各自一份**：当前用户可见的「应用文件」空间只有自己创建的那一个（除非他人主动共享）。因此①跨用户共享检索不成立（他人上传的文件对自己不可见）；②AC-20 的去重只在**各自的**空间内生效，同一内容由不同用户上传会各存一份。此为需求方 2026-09-24 明确接受的行为，**不是**缺陷。
- 当用户已有一个同名但用途不同的自有空间时，按 AC-26 复用该空间并写入其根目录下的目标文件夹；系统不因此新建空间，也不迁移既有内容。
- 知识空间中的条目为文件夹时不可被选中（AC-06）；用户在浏览到文件夹时可进入其内部继续选择。
- 当用户对某个知识空间文件没有读取/下载权限时，按 AC-07 处理。
- 知识空间文件的可用取值具有时效性；用户在打开选择器后长时间停留再提交，可能因取值过期导致后端消费失败。此为已知边界，其取舍与影响记录在 design.md（不在 spec 展开）。
- 用户重复点击提交不产生重复的文件夹或文件（依赖 AC-17 的复用与 AC-20 的跳过去重）。
- 同一表单中多个文件字段归集到同一文件夹时，字段间的重名/同内容文件同样按 AC-20 跳过。
