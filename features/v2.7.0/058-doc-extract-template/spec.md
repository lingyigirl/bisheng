# Feature: 文档抽取模板（058-doc-extract-template）

> **本文档定位 — 纯 What（需求口径，不随代码漂移）**
>
> spec 只回答 **做什么 / 验收标准 / 不做什么**。
> **所有 How（决策、数据流、字段、API、Service、前端、文件清单、性能指标）一律不写在这里。**
> How 的唯一真相在 [design.md](./design.md)（接手必读）与 [tasks.md](./tasks.md)（执行流水）。

**关联 PRD**: 用户需求（2026-09-17，无正式 PRD 文件，需求在对话中对齐）：针对特定文档类型（身份证、营业执照等）做结构化抽取。平台当前无此能力——文档类型判定仅有一个绑定特定文档体系的既有实现、不可由管理员配置；文档解析产出的只是供检索的文本，没有「结构化字段」的概念。本特性把「文档类型 → 字段定义 + 呈现形式」抽成**管理员可配置的数据**，并产出可被程序消费的结构化结果与人类可读文本。
**优先级**: P0
**所属版本**: v2.8.0
**依赖**: 无（基于既有知识库解析链路、LLM 管理与多租户体系扩展；本版本首个 Feature，负责创建 v2.8.0 release-contract）

> **范围边界**
> - **本次纳入**：
>   - **抽取模板**：管理员可配置「文档类型 → 字段定义 + 呈现形式」，增删改查 + 启停
>   - **文档类型判定**：上传文档后自动判定属于哪个已配置类型，给出候选与置信度；调用方可显式指定类型跳过判定
>   - **结构化抽取**：按模板字段定义产出结构化结果，含类型与必填校验、失败重试
>   - **可读渲染**：按模板的呈现形式产出人类可读文本
>   - **统一输入**：同时接受含文字层的文档与图片，按文档实际情况自动分流
>   - **抽取记录**：留存每次抽取的追溯信息
>   - **模板管理界面**：平台端配置界面，含列表 / 新建 / 编辑 / 启停 / 删除与试抽取验证（不做模板复制）
> - **本次明确排除**：
>   - **工作流「文档抽取」节点**（画布节点类型 + 配置面板；另起 feature）
>   - **对话 / 助手附件接入**（用户在聊天里上传证照自动出结构化卡片；另起 feature）
>   - **知识库入库时的元数据抽取**（另起 feature）
>   - **模板级模型覆盖**（本期模型槽位为租户级；出现「某些模板要更强模型」再评估）
>   - **异步抽取任务**（本期同步返回，不引入任务队列与轮询）
>   - **多页 / 多证件批量拆分**（一份文件含多张证件时不做拆分，按整份处理）
>   - **字段级置信度与人工纠错回写**（本期只给文档级置信度）
>   - **模板复制**（不支持从既有模板「另存为」新建；本期只做全新的新建与编辑，同类模板请手工重配）
>   - **嵌套结构的字段类型**（本期字段类型仅标量；发票明细行等留待后续）
>   - **对既有知识库数据的任何写入**（本特性对知识库只读）

## 1. 用户故事

作为 **业务配置人员**，
我希望 **为每一类需要识别的文档（身份证、营业执照、发票…）配置「要抽哪些字段」和「结果长什么样」**，
以便 **新增一类证照时不用改代码、不用等发版，自己就能配上**。

作为 **应用 / 流程编排者**，
我希望 **把一份文档丢进去就能拿到结构化的字段结果，而不用自己写提示词、不用自己处理模型返回格式不规范**，
以便 **把精力放在业务逻辑上，而不是反复调试抽取的稳定性**。

作为 **平台运维人员**，
我希望 **每一次抽取都留下可追溯的记录（用了哪个模板、置信度多少、走的哪条解析链路）**，
以便 **业务方反馈「这张证照抽错了」时能定位是类型判错了、解析没出文字、还是字段配得不对**。

## 2. 调用模式（先读这一节）

> 本特性的对外行为由**两个正交的模式**决定。下面的 AC 大量引用模式名，而不是各自重述条件 —— 这是为了避免「同一场景被多条 AC 用不同条件表述、进而互相矛盾」。

### M-1 调用目的（二选一，互斥）

| 模式 | 发起方 | 是否落抽取记录 | 是否受「模板已启用」约束 |
|---|---|---|---|
| **M-1a 业务抽取** | 应用 / 流程编排者等**业务调用方** | 仅「已进入抽取后」的成功与失败落记录（见 AC-03 / AC-31） | 受约束（停用模板不可用） |
| **M-1b 试抽取** | **租户管理员**，经模板管理界面发起 | 不落 | 不受约束（停用模板也可试） |

两类模式共享全部**硬前提**校验 —— 即 §3.1 表序号 **1 / 2 / 3 / 4**（文档可读、未超体量、模型已配置、内容可获得）。M-1b 与**业务前置校验**无关 —— 即序号 **5 / 6 / 7 / 8**（指定的类型是否可用、有无候选模板、判定阶段失败、判定未达阈值）；这四项本就是「该不该用这个模板」的判别，而回答这个问题正是试抽取的目的。

因此 M-1b 实际会命中的是序号 **1 / 2 / 3 / 4 / 9 / 10 / 11**，与 AC-44 列出的失败原因一一对应。

试抽取存在的意义是让管理员在**不确信模板配置是否正确**时先行验证 —— 尤其是新建之后、尚不确定字段定义是否合适的那段时间，以及因故停用、正在调整的模板。因此它与模板的启用状态无关。

### M-2 类型确定方式（二选一，互斥）

| 模式 | 条件 | 类型从哪来 |
|---|---|---|
| **M-2a 显式指定** | 调用方给出文档类型 | 由调用方指定；不经过判定 |
| **M-2b 自动判定** | 调用方未给出文档类型 | 由系统判定；可能判不出 |

**M-1b 试抽取恒为 M-2a**（管理员正在编辑哪个模板，就试哪个模板），因此不存在「试抽取要走自动判定」的情形。

## 3. 验收标准

### 3.1 前置校验与结果口径

> 抽取请求**到达服务端后**，按下表**自上而下**判定，命中即返回对应错误码并停止，不再继续后续检查。优先级固定，避免同一请求命中多条时返回码不确定。
>
> **适用范围**：本表描述的是**服务端**对抽取请求的校验。界面层在发起请求**之前**的输入拦截（AC-42 的不合法定义、AC-46 的非法输入）不占本表序号，它们是请求根本不会被发出的情形。

| 序 | 条件 | 适用模式 | 错误码 | 阶段 |
|---|---|---|---|---|
| 1 | 文档不可读或为空 | 全部 | 11609 | 未进入抽取 |
| 2 | 文档超出体量上限 | 全部 | 11610 | 未进入抽取 |
| 3 | 当前租户未配置本特性所用模型 | 全部 | 11608 | 未进入抽取 |
| 4 | 文档无文字层且环境未配置可用识别服务 → 内容不可获得 | 全部 | 11605 | 未进入抽取 |
| 5 | 指定的文档类型不存在或已停用 | 仅 M-1a + M-2a | 11601 | 未进入抽取 |
| 6 | 当前租户无已启用模板 → 无从判定 | 仅 M-1a + M-2b | 11606 | 未进入抽取 |
| 7 | 判定阶段模型调用失败或超时 | 仅 M-1a + M-2b | 11608 | 未进入抽取 |
| 8 | 判定置信度低于阈值 | 仅 M-1a + M-2b | 11606 | 未进入抽取 |
| 9 | 识别服务调用失败或超时 | 全部 | 11608 | 已进入抽取 |
| 10 | 抽取阶段模型调用失败或超时 | 全部 | 11608 | 已进入抽取 |
| 11 | 模型结果不符字段定义，且重试耗尽 | 全部 | 11607 | 已进入抽取 |

> **排序依据**：先校验「本次请求能不能继续」（序 1–4：文档可读、未超体量、模型已配置、内容可获得），再校验「该不该用某个模板」（序 5–8，仅 M-1a + M-2b 的判定路径），最后才是「拿到内容之后能不能抽出来」（序 9–11）。序 4 必须排在任何需要文档内容才能进行的检查之前 —— 判定（AC-16）同样需要内容，因此不能排在内容可获得性之前。

- **AC-01** — THE SYSTEM SHALL 按 §3.1 表的固定优先级执行前置校验，同一请求命中多个条件时返回序号最靠前者对应的错误码。
- **AC-02** — WHEN 抽取请求被序号 1–8 中任一条拒绝, THE SYSTEM SHALL **不产生抽取记录**（尚未进入抽取，无记录可言）。序号 7 的判定阶段失败同理——此时尚未确定模板，无法按 AC-31 记录「用了哪类模板」。
- **AC-03** — WHEN 抽取请求在序号 9–11 失败, THE SYSTEM SHALL 在 M-1a 下落一条失败记录，在 M-1b 下不落记录。

> **阶段划分的意义**：序号 1–8 为「未进入抽取即被拒」（含序号 7 的「判定阶段失败」——此时模板尚未确定），序号 9–11 为「已进入抽取后失败」，此时模板已确定、可完整留痕。二者的留痕口径不同（AC-02 / AC-03），这是刻意的。

### 3.2 模板配置

- **AC-04** — WHEN 管理员创建抽取模板并指定名称、文档类型标识、适用范围、字段定义与呈现形式, THE SYSTEM SHALL 保存该模板并使其在模板列表中可见。
- **AC-05** — IF 操作者试图读取、修改、启停或删除一个不存在、或不属于当前租户的模板, THEN THE SYSTEM SHALL 拒绝并返回错误码 11611（不区分「不存在」与「无权访问」，避免借此推断其他租户的模板是否存在）。
- **AC-06** — THE SYSTEM SHALL 使新建模板的初始状态为**已启用**（因此新建后即刻参与判定；管理员若需先验证配置，可直接用试抽取，无需依赖「未启用」状态）。
- **AC-07** — IF 同一租户内已存在相同文档类型标识的**未删除**模板, THEN THE SYSTEM SHALL 拒绝创建并返回错误码 11602。
- **AC-08** — WHEN 管理员删除某模板, THE SYSTEM SHALL 使该文档类型标识可被重新用于新建模板，并保持既有抽取记录可读。
- **AC-09** — IF 呈现形式中引用了字段定义中不存在的字段, THEN THE SYSTEM SHALL **在保存时**拒绝并返回错误码 11604（不得延迟到运行期才暴露）。
- **AC-10** — IF 模板定义非法, THEN THE SYSTEM SHALL 在保存时拒绝并返回错误码 11603。非法情形至少包括：名称为空、适用范围为空、字段定义为空（零个字段）、字段缺少标识、字段标识重复、字段类型不在允许集合内。
- **AC-11** — IF 呈现形式为空, THEN THE SYSTEM SHALL 接受保存（无呈现形式只影响可读文本的产出，不影响结构化结果与判定）。
- **AC-12** — WHEN 管理员停用某模板, THE SYSTEM SHALL 立即将该模板从 M-1a 业务抽取中排除（既不参与判定，也不接受显式指定）；M-1b 试抽取不受此限。停用状态下对其编辑可正常保存，但保存不改变其停用状态（AC-13 的「即时生效」不隐含「重新启用」）。
- **AC-13** — WHEN 管理员修改某模板的**任意内容**（字段定义、呈现形式、适用范围、名称）并保存后, THE SYSTEM SHALL 使后续该类型文档的抽取与判定立即使用修改后的内容（含 M-2a 显式指定路径）；既有抽取记录保持其原有内容不变。
- **AC-14** — THE SYSTEM SHALL 区分「字段未抽取到」与「抽取失败」：**非必填**字段未抽取到内容不视为失败；**必填**字段未抽取到内容属 AC-26 的「不符合字段定义」，走重试与失败路径。
- **AC-15** — THE SYSTEM SHALL 把「字段值为空字符串」与「字段缺失」同等视为「未抽取到」，二者不做区分。

> AC-14 只管「未抽到算不算失败」；「未抽到的字段如何渲染」由 AC-29 规定，二者不重叠。

### 3.3 文档类型判定（M-2b）

- **AC-16** — WHEN 调用方以 M-2b 提交文档, THE SYSTEM SHALL 依据当前租户**已启用**模板所声明的适用范围做类型判定，返回候选类型及其置信度。
- **AC-17** — THE SYSTEM SHALL 只把当前租户已启用的模板纳入判定候选集；其他租户的模板、以及已停用或已删除的模板不得影响判定结果。
- **AC-18** — WHEN 判定结果的置信度达到阈值, THE SYSTEM SHALL 采用命中类型对应的模板执行抽取。
- **AC-19** — IF 判定置信度低于阈值, THEN THE SYSTEM SHALL 不执行抽取并返回错误码 11606，由调用方决定后续处理。
- **AC-20** — WHEN 调用方以 M-2a 提交文档, THE SYSTEM SHALL 直接采用该类型对应的模板，**不经过判定**（无判定结果、无置信度）。

### 3.4 抽取执行

- **AC-21** — THE SYSTEM SHALL 接受两类输入：含可用文字层的文档、以及图片（图片不含文字层，恒走识别服务路径）。
- **AC-22** — WHEN 文档含可用文字层, THE SYSTEM SHALL 直接取用其文字内容，**不依赖任何外部识别服务**。
- **AC-23** — WHEN 文档不含可用文字层且环境已配置可用的识别服务, THE SYSTEM SHALL 经由该服务获得文档内容后继续抽取。
- **AC-24** — IF 识别服务已配置但调用失败或超时, THEN THE SYSTEM SHALL 返回错误码 11608（与模型调用失败同码：对外都是「本次没能拿到内容」）。
- **AC-25** — WHEN 执行抽取, THE SYSTEM SHALL 依据模板的字段定义产出结构化结果，其中每个字段的类型与必填性符合该模板的字段定义。
- **AC-26** — IF 模型产出的结果**缺少必填字段、或字段类型不符定义**, THEN THE SYSTEM SHALL 重试；达到重试上限仍不符合时返回错误码 11607，并指明失败的字段。
- **AC-27** — IF 模型返回了字段定义**之外**的字段, THEN THE SYSTEM SHALL 忽略这些额外字段并判定本次结果**通过**（额外字段不属于 AC-26 的「不符合定义」，不触发重试）。
- **AC-28** — WHEN 抽取成功, THE SYSTEM SHALL 依据模板的呈现形式产出可读文本，其内容与结构化结果一致。
- **AC-29** — WHEN 抽取**已成功**（即已通过 AC-26 的必填与类型校验），THE SYSTEM SHALL 把其中未抽到的字段按「该字段无内容」渲染（不报错、不残留占位符、不影响其余字段）。此类字段只可能是非必填字段——必填字段缺失已在 AC-26 处被拦下，走不到渲染。
- **AC-30** — THE SYSTEM SHALL 在执行抽取时不修改源文档、不写入知识库、不产生向量。

### 3.5 留痕

- **AC-31** — WHEN 一次 M-1a 抽取完成（成功或失败）, THE SYSTEM SHALL 留存足以回答「用了哪类模板、判得准不准、走了哪条解析路径、抽出了什么、成功与否」的追溯信息，使业务反馈「这份文件抽错了」时可定位到具体环节。
- **AC-32** — THE SYSTEM SHALL 允许租户管理员与平台超级管理员检索与查阅抽取记录，检索维度至少含模板、时间范围、成功或失败；其他角色不得查阅（记录含抽取出的字段内容，可能含证照类敏感信息）。
- **AC-33** — WHERE 该次抽取为 M-2a（显式指定、无判定）, THE SYSTEM SHALL 在追溯信息中如实标记「未经过判定」，而非留空或填默认值。
- **AC-34** — WHEN 一次 M-1b 试抽取完成, THE SYSTEM SHALL **不落抽取记录**（AC-31 的留存要求对试抽取不适用）。

### 3.6 租户与权限

- **AC-35** — WHERE 多租户开启, THE SYSTEM SHALL 模板的读取、判定候选集构建、抽取执行均限定在当前租户内，不跨租户生效。
- **AC-36** — IF 操作者不是租户管理员与平台超级管理员中的任一类, THEN THE SYSTEM SHALL 拒绝其创建、修改、启停、删除模板，也不向其展示模板管理界面入口。
- **AC-37** — THE SYSTEM SHALL 允许登录用户以 M-1a 发起文档类型判定与抽取。
- **AC-38** — THE SYSTEM SHALL 对模板的创建、修改、启停、删除记录操作者、操作时间与模板名，使「谁在什么时候改了哪个模板」可事后查阅。

### 3.7 模板管理界面

- **AC-39** — THE SYSTEM SHALL 在平台端提供模板管理界面，租户管理员可在此完成模板的列表查看、新建、编辑、启停与删除，无需借助接口或数据库。
- **AC-40** — THE SYSTEM SHALL 在模板管理界面提供逐字段编辑字段定义的能力（增行、删行、改字段标识 / 名称 / 类型 / 必填），并在编辑呈现形式时提示当前可用的字段变量。
- **AC-41** — WHEN 管理员在编辑某模板时发起 M-1b 试抽取并提交一份样件, THE SYSTEM SHALL **对编辑器中当前正在编辑的字段定义与呈现形式**执行抽取（即包含尚未保存的改动），且**恒按 M-2a 直接使用该模板**（试抽取不经过判定）；该模板处于停用状态时同样如此。
- **AC-42** — IF 编辑器中当前的定义未通过 AC-09 / AC-10 的合法性校验, THEN THE SYSTEM SHALL 拒绝该次试抽取并告知原因（不合法定义无从执行），错误码与 AC-46 一致。试抽取**不写回**模板，管理员的未保存改动不因此被保存或丢弃。
- **AC-43** — IF 发起试抽取时该模板已被其他管理员删除, THEN THE SYSTEM SHALL 拒绝并返回错误码 11611（试抽取作用于服务端已存在的模板；编辑器内的未保存改动不足以构成模板）。
- **AC-44** — IF 试抽取未能产出结果, THEN THE SYSTEM SHALL 明确告知失败原因，覆盖 §3.1 表中对 M-1b 适用的全部条目：文档不可读（11609）、超体量（11610）、模型未配置（11608）、无可用识别服务（11605）、识别服务调用失败（11608）、模型调用失败（11608）、字段校验失败（11607），使管理员能区分「模板配置问题」与「样件或环境问题」。
- **AC-45** — IF 试抽取产出了结果, THEN THE SYSTEM SHALL 标识出其中**未能抽到的字段**（按 AC-14 口径：必填字段缺失本应判失败，故到达此处的只可能是非必填字段），使管理员能判断是「样件本身无该信息」还是「该字段的适用范围/命名配得不对」。
- **AC-46** — IF 管理员在模板管理界面做了非法输入, THEN THE SYSTEM SHALL 在保存前给出提示并阻止保存，返回与 AC-07 / AC-09 / AC-10 一致的错误码。非法输入至少包括：名称为空、字段定义非法（零字段 / 缺标识 / 标识重复 / 类型越界）、呈现形式引用不存在的字段、类型标识与既有未删除模板冲突。

## 4. 边界情况

- 文档为空或无法读取 → 按 §3.1 序号 1 返回 11609，**不产生半成品记录**（AC-02）。
- 文档体量超出处理上限 → 按 §3.1 序号 2 返回 11610，**不得静默截断后按完整结果返回**（上限口径见 design.md §2）。
- 租户未配置本特性所用模型 → 按 §3.1 序号 3 在解析前即拒绝，不做无谓的文档解析开销。
- 模型返回的不是合法结构化结果 → 走重试；重试耗尽返回字段级错误（AC-26）。
- 模型返回了字段定义之外的字段 → 忽略额外字段并判为通过，**不重试**（AC-27）。
- 字段值为空字符串与字段缺失 → 统一按「未抽取到」处理（AC-15）。
- 非必填字段未被抽到 → 不算失败（AC-14），渲染时按「该字段无内容」处理（AC-29）。
- 必填字段未被抽到 → 属抽取失败，走重试与 11607（AC-14 / AC-26），不进入渲染。
- 同一份文档并发发起多次抽取 → 各自独立，互不影响。
- 抽取进行中模板被修改 → 本次抽取**按发起时的模板定义**完成（改动自 AC-13 的保存时点起对**后续**请求生效，不影响进行中的请求）。
- 抽取进行中模板被删除 → 已在途的本次抽取仍按已取得的定义完成；其结果照常留存（AC-31），且不因模板已删而不可读（AC-08）。
- 判定为某类型但抽取后必填字段全空 → 属抽取失败而非成功，返回字段级错误（AC-26）。
- 模板列表中同时存在已启用与已停用模板 → 停用者仅影响 M-1a，不影响管理界面的试抽取（AC-12 / AC-41）。
- 文档含多张证件 → 本期按整份处理，不拆分（见范围边界）。

**已知缺口（本期不做，记录待另行处理）**

- 平台端**没有模板导入 / 导出**：跨环境（测试 → 生产）搬运模板只能靠人工重配。是否需要，见 design.md §8。
- **无模板版本历史**：改了模板无法回看「上一版字段定义长什么样」，只能靠抽取记录间接推断当时用的是哪版。AC-38 只保证「谁改的、什么时候改的」可查，不保证「改前是什么」可查。
- 判定阈值**不可按模板配置**，为全局口径。出现「某类证照特别容易误判」再评估是否下放。
- 各前置校验条件的**优先级虽已固定（AC-01），但阈值本身**（置信度阈值、文档体量上限、重试次数）的具体取值属设计参数，见 design.md §2。
- 被拒请求**只返回错误码、不落记录**（AC-02），因此「有多少请求因为文档不可读被拒」无法从事后记录统计，只能靠日志。是否需要补统计，见 design.md §8。
- **试抽取结果不可回看**：AC-34 规定试抽取不落记录，因此管理员调完模板后无法回头对照「上一版试出来是什么样」。这是为「不污染抽取记录」付出的代价（D11），若日后成为痛点再评估是否单列一张试抽取记录表。
- **触发抽取与查阅记录的主体范围不对称**：AC-37 允许任意登录用户发起业务抽取（从而写入含字段内容的记录），而 AC-32 只允许管理员查阅这些记录。这是刻意的——写入是业务动作、查阅涉及敏感信息，但意味着普通用户写入的内容自己看不到。若后续接入对话场景需要「用户看自己的抽取结果」，应另开「仅看本人记录」的路径，而非放宽 AC-32。
