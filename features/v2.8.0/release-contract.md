## 表 1：领域对象归属

每个领域对象只能有一个 Owner Feature，负责定义该对象的写入行为
（创建、更新、删除）。其他 Feature 只能"读取"或"引用"该对象。

| 领域对象 | Owner Feature | 说明 |
|---------|--------------|------|
| 文档解析能力（loader 栈 / `TempFilePipeline` / `settings.get_knowledge()` provider 配置） | knowledge 模块（既有） | **非 Owner**，仅读取 / 调用；不修改既有解析行为，不新增服务配置项 |
| 术语库词条（`term_library_term`） | F060-term-library | 新增独立表（租户 / 标准词 / 别名集 / 释义 / 归属部门）；仅本 Feature 写入。**归属部门只用于管理页筛选，不构成授权边界**（见 INV-17）。库规模上限 500 条、单条释义上限 200 字，超限在写入与导入时拒绝 |
| 对话提示词的术语注入（运行时行为，**不落库**） | F060-term-library | 在对话链路 system prompt 末尾追加本轮命中术语区块；**不拥有** `assistant.prompt`、应用配置、工作流提示词等任何既有对象——注入内容永远不写入它们，用户的提示词字段永远保持其编辑时的原文（见 INV-18）。不新增表 |

**规则**：
- 非 Owner Feature 的 AC 中不得出现其他对象的"创建/修改/删除"行为，只能"读取"或"调用" Owner 的 Service
- 新增领域对象时必须先更新本表

## 表 2：跨 Feature 不变量（INV-N）

全局业务约束，任何 spec 的 AC **不得与之矛盾**。

| ID | 不变量描述 | 涉及领域对象 | 来源 spec |
|----|-----------|------------|---------|
| INV-16 | 术语库按租户隔离：词条的读取、导入、匹配与注入均限定在当前租户内，不跨租户生效；平台侧无全局术语库，租户间术语互不可见 | term_library_term | F060 |
| INV-17 | 术语库的**部门归属不是授权边界**：它只用于管理页的筛选与归类，既不授予也不收窄任何用户对术语的读写权限，**更不限定对话注入的范围**——注入一律使用当前租户的**全库**。任何 Feature 不得把术语的部门归属当作可见性或生效作用域来消费（对应 F057 的相反设定：知识库部门归属**是**可见性边界；二者不可类推） | term_library_term | F060 |
| INV-18 | 术语注入是**运行时只读行为**：注入内容不写入 `assistant.prompt`、应用配置、工作流提示词或任何持久化配置，用户的提示词字段永远保持其编辑时的原文；因此术语库的增删改对后续对话**立即生效**，无需回写或重算任何应用配置 | term_library_term, assistant | F060 |

> **编号续接说明**：INV-N 为**跨版本全局递增**，不按版本重新起算。v2.6.0 占用 INV-1 ~ INV-7，v2.7.0 续接 INV-8 ~ INV-11，F058 占用 INV-12 ~ INV-15（**2026-09-17 起 F058 所属版本由 v2.8.0 调整为 v2.7.0，其 INV-12 ~ INV-15 随之登记于 v2.7.0 契约**），F060 占用 **INV-16 ~ INV-18**，F061 续接 **INV-19**（v2.7.0）。以 INV-N 引用时须结合编号即可定位来源版本，不存在歧义——**编号不因版本归属调整而变化**。

**规则**：
- 新增不变量：先在此表追加，再写 AC
- 修改不变量：必须列出 Impacted Specs 清单，逐一回写并重新评审
- 冲突检测：若 AC 与不变量矛盾，spec 评审不通过
