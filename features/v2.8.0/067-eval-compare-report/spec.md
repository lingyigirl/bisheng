## 1. 用户故事

**A. 银行领导 / 评审**
作为一名**银行领导（评审 / 验收视角）**，
我希望**在一份可视化的对比报告里一眼看清两个版本谁更好、差在哪个指标**，
以便**评估我方智能体评测能力、并作为选型与优化的量化依据（同时是交付证明）**。

**B. 评测操作者**
作为一名**负责评测的操作者**，
我希望**在报告里逐题下钻、按指标切换查看细节，并把报告导出留档**，
以便**定位是哪些题、哪个指标拖了后腿，并沉淀为可归档的证据**。

## 2. 验收标准

> AC-ID 在本特性内唯一。tasks.md 的测试任务须 `覆盖 AC: AC-NN` 追溯到此表。
> 复杂 feature 采用 **EARS 句型**。

**2.1 报告页与信息结构**

- **AC-01** — WHEN 用户在评测列表对一个**对比组**触发「对比」, THE SYSTEM SHALL 打开该组的**可视化报告页**；报告页的成员 SHALL 仅由该**对比组标识**确定（每组恰好两版），**SHALL NOT** 依据列表中的相邻行推断。
- **AC-02** — THE SYSTEM SHALL 在报告头部展示本次对比的两版**各自的全部模型**与**全部提示词节点**，并标注变更项；依变更内容标注为「换模型对比」「换提示词对比」「模型 + 提示词 均变更」之一；后一种 SHALL 标为「多变量 · 不可单独归因」。
- **AC-03** — THE SYSTEM SHALL 给出一句结论文案，形如「`<版本名>` 更优」；结论栏 **SHALL NOT** 出现任何指标名，也 **SHALL NOT** 出现通过 / 不通过（✅ / ❌）判定。
- **AC-09** — THE SYSTEM SHALL 在逐题明细标题展示**题目总数 · 成功率 · 失败数**。
- **AC-10** — WHEN 某题执行失败, THE SYSTEM SHALL 在该题所在行展示**失败原因**，其各指标值记 **N/A** 且**不计入**任何均值 / 聚合。

**2.2 指标与结论**

- **AC-04** — WHEN 两版在优先级链上均有有效值, THE SYSTEM SHALL 按固定优先级 **准确率 → 幻觉率 → 成本(Token) → 延迟** 依次比较，在**某一优先级上差值超容差**者判优；"越低越好"的指标（幻觉率 / 成本 / 延迟）SHALL **先按方向归一再比**；高优先级打平（差值未超容差）SHALL **下探**下一优先级；四项全打平分不出差异，结论 SHALL 为「无超容差差异」。容差 SHALL **按指标类型分别取值**（百分比类与 秒 / 个 类各自单定）。
- **AC-05** — THE SYSTEM SHALL 给出一节「**对比分析**」，说明结论所依据的指标与差值；**当结论由非最高优先级指标决定时，该节 SHALL 写明"下探"情形**；该节内容 SHALL 由**差值与逐题胜负按模板生成**，**SHALL NOT** 包含大模型自由生成的内容。
- **AC-06** — THE SYSTEM SHALL 以**指标卡**展示下列指标的两版值与对比差值：**准确率、F1、召回、幻觉率、延迟、成本(Token)**；指标卡 **SHALL NOT** 出现达标 / 通过判定。
- **AC-07** — THE SYSTEM SHALL 渲染**两张图**：分组柱状图（准确率 / F1 / 召回）与逐题折线图（横轴题号、两条线为两版）；延迟、Token **若**出图 SHALL **各用独立纵轴**。

**2.3 幻觉率**

- **AC-11** — THE SYSTEM SHALL 以**内容级（陈述级）**计算幻觉率：`幻觉率 = Σ"与标准答案矛盾的陈述数" ÷ Σ"总陈述数"`（跨题按总陈述数加权，**非逐题均值**）；该判定 SHALL 与准确率**在同一次裁判调用内**完成、以**标准答案**为唯一参照、**不溯源**检索上下文；「矛盾」与「多答」SHALL NOT 重复计数。
- **AC-12** — WHILE 用户提供了**自定义裁判提示词**, THE SYSTEM SHALL 仍把幻觉判定指令**固定拼接**进最终裁判模板（拼在 `{question}` / `{answer}` / `{ground_truth}` 占位符之外），使用户无法移除该指令，从而保证**幻觉率恒可计算**；用户对提示词其余部分的自定义空间 SHALL 不受影响。

**2.4 逐题明细**

- **AC-08** — WHEN 用户切换逐题明细所用的**指标**, THE SYSTEM SHALL 按**当前所选指标**重新判定每题的「更好 / 更差」：**准确率 / F1 / 召回 越高越好**；**幻觉率 / 延迟 / Token 越低越好**。

**2.5 导出**

- **AC-13** — WHEN 用户导出报告, THE SYSTEM SHALL 导出两版的**完整指标数据**，含**每一个指标**（包括界面上一次只看一个的逐题指标）的**逐题值**；导出内容 **SHALL NOT** 随界面当前所选指标变化。
- **AC-14** — THE SYSTEM SHALL 由**后端基于与报告页同一份数据生成**导出文件（**SHALL NOT** 依赖前端截图 / 打印）；本期导出格式 SHALL 支持 **Excel**。

**2.6 非功能**

- **AC-15** — WHERE 多租户开启, THE SYSTEM SHALL 仅返回**当前租户、当前用户有权访问**的评测与报告数据。
- **AC-16** — WHERE 评测为**单版本**（无对比组）, THE SYSTEM SHALL 保持既有行为不变。

## 3. 边界情况

- 当对比的**一侧**仍在运行或已失败时，系统应**标注该侧状态**，并**仍展示已完成的一侧**（不整页报错）。
- 当某指标在**两版均无有效值**时，该指标卡 / 该指标在图中应显示 **N/A**，且**不参与**结论。
- 当**结果文件不可读**时，报告应**不可生成并返回可辨识的错误**（对外行为，不静默成功）。
- 当**题面文本重复**时，两版配对应依据**唯一标识**而非题面文本（避免取错题）。
- 结果数据中由系统追加的**汇总行**应**不被计为一道题**（不计入题目总数 / 成功率）。
- 当**表单型题目无题面**时，应以**表单摘要**作为其显示题面。
- 当某题的**延迟 / Token 采集缺失**时，该题该项应记为 **N/A** 且**不进聚合**（不因缺一项而失败整次评测）。

> 兜底策略、运行时坑（如百分比 / 数值列的单位解析、方向归一、聚合口径、比对唯一键）的处理细节指向 design.md §5 与需求分析 §14「实现必查清单」。
