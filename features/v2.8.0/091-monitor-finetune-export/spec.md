## 1. 用户故事

**A. 算法 / 运营人员**
作为一名**负责智能体效果优化的算法人员**，
我希望**在智能体监测页把一段时间内跑过的真实问答按反馈筛选后导出为微调 JSON**，
以便**把线上表现好的问答回流到模型微调，形成「评测—反馈—优化」里的数据回流环节**。

**B. 银行管理员**
作为一名**关注数据安全的银行管理员**，
我希望**导出必须持有审计日志菜单权限、只能导出本租户数据，并且在导出前明确提示文件含原始对话**，
以便**控制敏感客户信息的外流风险**。

## 2. 范围边界

### 本次纳入

- **导出入口**：智能体监测（`/log` → 智能体监控）筛选栏新增「导出微调数据」按钮。
- **筛选复用**：导出沿用列表已有筛选——应用、应用类型、运行状态、关键词、时间范围（默认最近 7 天，最长 90 天）。
- **反馈筛选**（导出专属）：`全部反馈` / `仅点赞` / `排除差评`，**默认排除差评**。
- **单轮样本**：每条运行只导出其**当轮**的「问题 → 答案」，格式为
  `[{"instruction": "...", "input": "", "output": "..."}]`。
- **全量导出**：导出当前筛选命中的**全部**运行（不是当前页），设 **5000 条运行**硬上限；超限**报错并提示缩小时间范围**，不静默截断。
- **去重**：问题与答案完全相同的样本只保留一条。
- **权限与隔离**：非管理员需持有审计日志菜单权限（复用 F052 AC-18 口径）；查询显式限定本租户。
- **前端确认**：导出前弹确认框，明确提示文件含原始对话、可能含客户敏感信息。

### 本次明确排除

- **多轮 / history 上下文导出** —— MVP 只导单轮问答；格式虽允许 `history`，本期不生成。
- **勾选行导出** —— 只支持按筛选全量导出。
- **自动 / 定时沉淀（"自动沉淀"）** —— 本期只做人工触发。
- **自动回流提示词 / 自动触发微调任务** —— 只产出数据集，后续由既有微调流程人工上传。
- **敏感数据脱敏** —— 待银行数据安全口径确认后另行开发；本期原样导出 + 确认提示。
- **审计事件落库** —— 需要新增审计 `EventType`（含前后端枚举与三语 i18n），不在本期；本期以服务日志记录操作人与导出条数。
- **失败运行** 不特殊排除，但无完整问答（缺问题或缺答案）的运行自动跳过。

## 3. 验收标准

| ID | 验收标准 |
|----|---------|
| AC-01 | 智能体监测筛选栏出现「导出微调数据」按钮与反馈筛选下拉（全部 / 仅点赞 / 排除差评），默认「排除差评」 |
| AC-02 | 点击导出先弹确认框；取消不发起请求；确认后下载 `agent_finetune_<时间戳>.json` |
| AC-03 | 文件为 UTF-8 的 JSON 数组，元素字段为 `instruction` / `input` / `output`；可直接通过模型微调既有指令集上传校验 |
| AC-04 | 每个元素对应一条运行：`instruction` 为该轮用户问题，`output` 为该轮最终答案，`input` 为空字符串 |
| AC-05 | 反馈筛选生效：`仅点赞` 只导出答案 `liked=1`；`排除差评` 排除 `liked=2`（未评价保留）；`全部反馈` 不过滤 |
| AC-06 | 导出范围是当前**已搜索**的筛选条件命中的全部运行，不受列表分页影响 |
| AC-07 | 命中运行数超过 5000 时返回 400，前端提示"缩小时间范围"，且不下载残缺文件 |
| AC-08 | 时间窗沿用列表语义：默认最近 7 天，最长 90 天，`start_time >= end_time` 报错 |
| AC-09 | 非管理员无审计日志菜单权限时导出返回未授权，不产生文件 |
| AC-10 | 只导出当前租户数据；`chatmessage` 查询显式带 `tenant_id` |
| AC-11 | 缺失问题或缺失答案的运行、空问题/空答案的样本被跳过，不产生空样本 |
| AC-12 | 问题与答案完全相同的样本只出现一次 |
| AC-13 | 前端对 400 错误展示后端 `detail`（如超限提示），而不是只显示 HTTP 状态码 |

## 4. 既有能力与差距

| 能力 | 现状 | 差距 |
|------|------|------|
| 运行列表 | F052 已有，ES `application_process` 事件，按 `trace_id` 折叠 | 无导出 |
| 完整问答 | `chatmessage` 表已持久化问题与各应用类型答案 | 监测事件只有 `input_snapshot`（≤200 字），需按 `chat_id` + 运行时间窗关联 |
| 反馈 | `chatmessage.liked`（0 未评价 / 1 点赞 / 2 差评） | 导出需支持按反馈筛选 |
| 微调数据集 | 既有上传接口接受 `[{"instruction","input","output"}]` | 需生成同结构文件 |

---

## 5. 验收方式

- 后端单测覆盖：文本解包、问答配对、反馈过滤、去重、超限、schema 校验。
- 前端手测：筛选 → 反馈切换 → 确认框 → 下载 → 用微调上传页校验文件格式。
- 真实环境抽 1 个应用、近 7 天数据核对：导出条数与列表命中数一致，抽查 3 条问答与原始会话一致。
