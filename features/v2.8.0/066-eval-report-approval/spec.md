# Feature: 评测报告与上线审批参考

> **本文档定位 — 纯 What（需求口径，不随代码漂移）**
>
> spec 只回答 **做什么 / 验收标准 / 不做什么**。
> **所有 How（决策、数据流、字段、API、Service、前端、文件清单、性能指标）一律不写在这里。**
> How 的唯一真相在 [design.md](./design.md)（接手必读）与 [tasks.md](./tasks.md)（执行流水）。

**关联 PRD**: 用户需求（2026-10-14）：评测模块需要支持「下载评测报告」，报告内容结合现有评测结果与性能指标（请求成功率、端到端耗时、Token 速率等）；智能体点击「上线」走审批时，审批人需要能在「审批中心 → 我的审批 → 待我处理」详情页直接看到评测报告简要信息与下载链接，作为上线准入与验收的**参考依据**。
**优先级**: P1
**所属版本**: v2.8.0
**依赖**: F053（评测对比组 / 结果 CSV 结构）、F054（表单型评测 / 结果行注入）、审批模块 `agent_publish_request` 场景

> **范围边界**
> - **本次纳入**：
>   - 评测执行期**实测采集性能指标**：逐题端到端耗时、执行成功/失败、Token 用量（输入/输出/总量）、首 token 延迟
>   - 评测模块**「下载评测报告」**：按需生成 xlsx（汇总 sheet + 逐题明细 sheet）
>   - 审批详情**注入评测报告简要信息 + 下载链接**（`agent_publish_request` 场景）
> - **本次明确排除**：
>   - **硬门禁**：报告缺失/不合格**不阻止**上线或审批（本期为参考依据，拦截另起 feature）
>   - 自动阈值判定 / 自动放行结论（报告不含 PASS/FAIL 判定）
>   - 历史评测回填性能指标（上线前已有的评测无性能数据 → 显示 N/A）
>   - 多报告对比 / N 版本报告
>   - 性能指标超出 P95 的分位扩展（P99 等）
>   - `agent_publish_request` 以外审批场景的报告注入

---

## 1. 用户故事

作为 **应用负责人**，
我希望 **评测跑完后能下载一份包含效果与性能指标的完整报告**，
以便 **作为版本上线的准入与验收依据，而不只是看一个总分**。

作为 **应用负责人**，
我希望 **创建评测时不必额外做压测，性能数据在评测执行期自动采集**，
以便 **一份数据集既验效果、也验性能，省一轮人工操作**。

作为 **审批人**，
我希望 **在待我处理的审批详情页直接看到评测报告的关键指标与下载入口**，
以便 **不切页面、凭数据做出是否放行的判断**。

## 2. 验收标准

### 2.1 性能指标采集（评测执行期）

- **AC-01** — WHEN 评测任务执行, THE SYSTEM SHALL 逐题记录端到端耗时（题目提交到答案返回的墙钟耗时）与执行成功/失败标记。
- **AC-02** — WHEN 评测任务执行, THE SYSTEM SHALL 采集每题的 Token 用量（输入 / 输出 / 总量）与首 token 延迟。
- **AC-03** — IF Token 采集不可用（遥测不可达、事件缺失）, THEN THE SYSTEM SHALL 将该题 Token 相关值记为「无法判定」(N/A)，且**不阻断**评测执行与结果产出。
- **AC-04** — 评测结果 CSV SHALL 追加性能列（耗时、输入 Token、输出 Token、执行状态）；IF 该题无性能数据, THEN 对应列为 N/A。既有列结构 SHALL NOT 变化（向后兼容，旧结果文件缺列即 N/A）。

### 2.2 评测报告下载

- **AC-05** — WHEN 用户对某条成功评测点击「下载评测报告」, THE SYSTEM SHALL 生成 xlsx 格式报告并返回可下载链接。报告 SHALL 包含两个工作表：**汇总** 与 **逐题明细**。
- **AC-06** — 报告**汇总**页 SHALL 包含：
  - 基础信息：应用名、应用类型、版本名、评测时间、数据集文件名、题目数量、评测人
  - 效果指标：F1、召回、精确（总分）
  - 性能指标：请求成功率、平均端到端耗时、最大端到端耗时、P95 端到端耗时、Token 总量、平均 Token 速率（token/s）、平均首 token 延迟
  - 参考结论：一行文字摘要（仅供审批参考，**不含放行判定**）
- **AC-07** — 报告**逐题明细**页 SHALL 包含：题目、标准答案、答案、命中数、多答数、漏答数、召回、精确、F1、耗时、输入 Token、输出 Token、执行状态（成功 / 失败原因）。
- **AC-08** — IF 某题性能数据为 N/A, THEN 汇总页对应指标 SHALL 为该题不计入聚合（按有效样本统计）；IF 有效样本为 0, THEN 该指标显示 N/A。
- **AC-09** — IF 评测不存在、非当前用户所有、或未成功完成, THEN 「下载评测报告」SHALL 返回明确的错误而非空文件。

### 2.3 审批详情集成

- **AC-10** — WHEN 审批人打开一个场景为智能体发布的待办详情, THE SYSTEM SHALL 展示该应用**该版本最近一次成功评测**的简要信息（评测时间、F1/召回/精确、请求成功率、平均耗时、Token 速率）与报告下载链接。
- **AC-11** — IF 该应用该版本没有成功评测, THEN 详情页 SHALL 显示「暂无评测报告」提示，且**不影响审批操作**。
- **AC-12** — 报告**仅作参考**：THE SYSTEM SHALL NOT 因报告缺失、指标低或未生成而阻止审批人同意、阻止审批流程推进或阻止智能体上线。
- **AC-13** — 助手类应用无版本概念：WHEN 应用类型为助手, THE SYSTEM SHALL 按应用维度匹配最近一次成功评测。

### 2.4 权限与租户隔离

- **AC-14** — 评测模块的报告下载 SHALL 与既有评测接口同权限口径（仅评测所属用户）。
- **AC-15** — 审批详情中的报告链接 SHALL 对**该审批任务的审批人**可用（不要求其为评测属主）。
- **AC-16** — WHERE 多租户开启, THE SYSTEM SHALL 仅匹配与返回当前租户的评测数据。

## 3. 边界情况

- 评测失败（status=failed）或尚无结果文件：不生成报告，返回明确错误。
- 部分题目执行失败：失败题计入「请求成功率」分母、不计入「成功」；其效果与性能指标为 N/A 且从聚合中排除。
- 旧评测（本 feature 上线前产生）：结果 CSV 无性能列 → 汇总页性能区块显示 N/A，效果区块正常。
- 助手评测无版本：审批 payload 的 version_id 为空，按应用 id 匹配。
- 审批期间评测被删除（逻辑删除）：按最近一次**未删除**的成功评测匹配。
- 同一应用同一版本多次评测：取**最近一次成功**（按 `update_time`）。
- 报告重复下载：每次按需生成（内容一致）；不落库、不占用版本表结构。
- 遥测 ES 不可达：Token 指标整体 N/A，报告仍可生成（效果指标正常）。
- 应用在评测后又改动了版本内容：报告反映的是评测执行时的快照，不做版本一致性校验（沿用既有评测语义）。
